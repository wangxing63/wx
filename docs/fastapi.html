1三个核心概念

写代码之前，先用 5 分钟搞明白我们到底在做什么。

什么是"后端"？

把网站想象成一家餐厅：前端 = 装修、菜单、服务员（顾客看得见的部分）；后端 = 厨房（顾客看不见，但菜/数据都在这里做出来）。FastAPI 就是盖厨房的工具。

什么是 API？

🍽️ 类比
API 就是点菜窗口。顾客（前端/App）不能冲进厨房，只能通过窗口递纸条（请求）→ 厨房做好 → 从窗口递出来（响应）。API 就是约定好的纸条格式。

什么是 FastAPI？

  • 一个 Python Web 框架，专门快速搭建后端 API，写起来快、运行也快。
  • 招牌特性：自动生成接口文档、自动数据验证、基于 Python 类型标注。

后端概念餐厅类比后端概念餐厅类比
服务器 / 后端厨房Pydantic 模型标准点菜单模板
API 接口（路由）点菜窗口依赖注入传菜员（各窗口共用）

3第一个程序

类比：先把火点着，端出第一盘菜。去掉注释只有 4 行。

main.py
# 从 fastapi 工具包里，把 FastAPI 这个"厨房建造器"拿进来
from fastapi import FastAPI

# 盖一间厨房，起个名字叫 app（约定俗成）
app = FastAPI()

# @ 开头这行叫"装饰器"：给下面的函数挂一个"点菜窗口"
# "get" = 只处理"查看"类请求；"/" = 窗口地址（首页/正门）
@app.get("/")
def read_root():
    # 返回字典，FastAPI 自动转成 JSON 递给顾客
    # JSON 先理解为：一种大家都看得懂的通用纸条格式
    return {"message": "Hello FastAPI，我的厨房开张了！"}

uvicorn main:app --reload

--reload改代码后自动重启，开发必加

6路径参数

🍽️ 类比：取餐号
"取 5 号餐"——5 嵌在网址里，就是路径参数。

基础用法

# 大括号是占位符：访问 /items/5，5 就被装进 item_id
@app.get("/items/{item_id}")
def read_item(item_id: int):
    # item_id: int 是类型标注：必须是整数
    # 访问 /items/abc 会被 FastAPI 自动拒绝（422 错误）
    return {"item_id": item_id}

多个路径参数

# 类比：/用户/张三/的订单/7号
@app.get("/users/{username}/orders/{order_id}")
def read_order(username: str, order_id: int):
    return {"用户": username, "订单号": order_id}

带文件路径的参数（path 类型）

# :path 表示这个参数可以包含斜杠 /（比如文件路径）
# 访问 /files/reports/2024/a.txt → file_path = "reports/2024/a.txt"
@app.get("/files/{file_path:path}")
def read_file(file_path: str):
    return {"文件路径": file_path}
⚠️ 顺序坑
同时有 /items/me 和 /items/{item_id} 时，具体路径必须写在前面，否则 "me" 会被当成 item_id。

7枚举：参数只能是固定几个值

🍽️ 类比
辣度只能选"不辣 / 微辣 / 特辣"，不许自创"宇宙辣"。用 Python 的 Enum（枚举）把可选值列死。
from enum import Enum  # Python 自带的枚举工具

# 定义"辣度"枚举：继承 str 和 Enum
# 继承 str 是为了让值既是枚举又是字符串，能直接用在 URL 里
class SpicyLevel(str, Enum):
    no = "不辣"       # 成员名 = 值
    mild = "微辣"
    hot = "特辣"

@app.get("/dishes/spicy/{level}")
def get_by_spicy(level: SpicyLevel):
    # level 只会是三种之一，乱填（如 /宇宙辣）自动 422 报错
    # 还能用枚举成员做比较：
    if level is SpicyLevel.hot:
        return {"警告": "小心喷火！", "辣度": level}
    return {"辣度": level}

文档里这个参数会变成下拉选择框，顾客只能三选一。

8查询参数

🍽️ 类比：点单备注
"牛肉面，微辣、不要香菜"——备注写在网址 ? 后，多个用 & 连接：/search?keyword=牛肉&spicy=true
# 函数里有参数、路径里没有 → FastAPI 自动当作查询参数
@app.get("/search")
def search(keyword: str, spicy: bool = False, limit: int = 10):
    # keyword 无默认值 → 必填；spicy/limit 有默认值 → 可选
    return {"搜索词": keyword, "要辣吗": spicy, "条数": limit}

可选参数（可以为空 None）

@app.get("/items")
def list_items(q: str | None = None):
    # str | None 表示：可以是文字，也可以什么都不给
    if q:  # 顾客给了搜索词
        return {"搜索": q}
    return {"提示": "没给搜索词，返回全部"}

接收多个值（列表型查询参数）

from fastapi import Query

# 访问 /tags/?tag=辣&tag=便宜&tag=快 → tag = ["辣","便宜","快"]
@app.get("/tags/")
def read_tags(tag: list[str] = Query(default=[])):
    return {"标签列表": tag}
💡 bool 类型自动识别
查询参数写 true、True、1、yes、on 都会被识别为 True，其余为 False。

9请求体与 Pydantic 模型

🍽️ 类比：标准点菜单
GET 像隔窗口问句话；POST 像递一张写满信息的点菜单。菜单不能乱写，得有标准模板——就是 Pydantic 模型。菜单内容叫请求体（body）。

定义模板 + 接单

from pydantic import BaseModel  # 所有模板的"母模板"

class Dish(BaseModel):           # 定义"菜品"模板
    name: str                    # 菜名：必填，文字
    price: float                  # 价格：必填，数字
    spicy: bool = False          # 可选，默认不辣
    description: str | None = None  # 可选，可为空

@app.post("/dishes")
def create_dish(dish: Dish):
    # dish: Dish = 把请求体按 Dish 模板解析和检查
    # 少填 price、price 写成文字 → FastAPI 自动报 422
    return {"一句话": f"已下单：{dish.name}，售价 {dish.price} 元"}

怎么测试 POST？（地址栏做不到）

方法1（推荐）：打开 /docs → 找到 POST /dishes → Try it out → 填 JSON → Execute：

{"name": "宫保鸡丁", "price": 28.5, "spicy": true}

方法2：用 Python 发请求（先 pip install requests）：

import requests  # 发网络请求的工具包
r = requests.post("http://127.0.0.1:8000/dishes",
                  json={"name": "宫保鸡丁", "price": 28.5})
print(r.json())  # 打印厨房端回来的结果

请求体 + 路径参数 + 查询参数同时用

# FastAPI 的识别规则：
# 1. 参数名出现在路径里 → 路径参数
# 2. 参数是 Pydantic 模型 → 请求体
# 3. 其余（int/str/bool 等单值）→ 查询参数
@app.put("/dishes/{dish_id}")
def update_dish(dish_id: int, dish: Dish, notify: bool = False):
    # dish_id 来自路径，dish 来自请求体，notify 来自查询参数
    return {"改了几号菜": dish_id, "新信息": dish, "要通知吗": notify}

10Query：查询参数验证

🍽️ 类比
备注也不能乱写："加辣程度 1~5 级"、"备注最多 50 字"。用 Query() 给查询参数立规矩。
from fastapi import Query

@app.get("/dishes/search")
def search(
    # 必填，1~50 个字；title/description 会印在说明书上
    keyword: str = Query(min_length=1, max_length=50,
                         title="搜索词", description="要搜索的菜名关键词"),
    # 可选，默认 10，范围 1~100
    limit: int = Query(default=10, ge=1, le=100),
    # 正则约束：必须是 11 位手机号（pattern 用正则表达式）
    phone: str | None = Query(default=None, pattern="^1[0-9]{10}$"),
    # alias：对外用别的名字（顾客填 search-word，代码里用 keyword2）
    keyword2: str | None = Query(default=None, alias="search-word"),
    # deprecated=True：标记"此参数已过时"，文档里会划线提示
    old_param: str | None = Query(default=None, deprecated=True)
):
    return {"搜索词": keyword, "条数": limit}
ℹ️ 通用规则
Query、Path、Field 的验证参数（min_length、gt、pattern 等）几乎一样，学会了 Query 就等于学会了另外两个。

11Path：路径参数验证

取餐号也不能乱报：不能是负数、不能超过 9999。用 Path() 立规矩，写法和 Query 一样。

from fastapi import Path

@app.get("/items/{item_id}")
def read_item(
    # ge=1：大于等于1；le=9999：小于等于9999；title 印在说明书上
    item_id: int = Path(ge=1, le=9999, title="商品编号", description="1~9999 之间的商品ID")
):
    return {"item_id": item_id}
规则意思规则意思
gt大于ge大于等于
lt小于le小于等于
⚠️ 顺序提醒
路径参数用 Path() 赋予默认值后，就不能再写在"无默认值参数"前面了。如果报语法错，把带默认值的参数移到后面，或者都改成关键字传参。

12Field：模型字段验证

🍽️ 类比：服务员审单
点菜单每栏都有填写规范：菜名 2~20 字、价格必须为正。用 Field() 写在模型里，一次定义处处生效。
from pydantic import BaseModel, Field

class Dish(BaseModel):
    # min_length/max_length：字数限制；description：说明书上的栏目说明
    name: str = Field(min_length=2, max_length=20, description="菜名，2~20个字")
    # gt=0：必须大于0；le=9999：不超过9999
    price: float = Field(gt=0, le=9999, description="价格，0~9999元")
    # default：默认值
    spicy: bool = Field(default=False, description="是否加辣")
    # 列表字段：标签可以填多个，也可以一个都不填
    tags: list[str] = Field(default=[])

常用规则速查

规则意思例子
min_length / max_length文字/列表 最短/最长Field(min_length=2)
gt / ge / lt / le大于/大于等于/小于/小于等于Field(gt=0)
pattern正则约束Field(pattern="^1[0-9]{10}$")
default / default_factory默认值 / 默认值工厂（生成列表等）Field(default_factory=list)
alias对外用别的字段名Field(alias="dish_name")

13嵌套模型

🍽️ 类比
点菜单里还有子菜单：一份"套餐"里包含"主食 + 饮料 + 小食"，每样又有自己的栏目。模型里套模型，就是嵌套模型。
from pydantic import BaseModel, Field

# 子菜单：饮料
class Drink(BaseModel):
    name: str
    iced: bool = True   # 是否加冰，默认加

# 子菜单：小食
class Snack(BaseModel):
    name: str
    count: int = Field(ge=1)   # 至少 1 份

# 主菜单：套餐（里面嵌着 Drink 和 Snack 列表）
class Combo(BaseModel):
    main_dish: str                    # 主食名
    drink: Drink                       # 嵌套：一杯饮料
    snacks: list[Snack] = []          # 嵌套：多份小食

@app.post("/combos")
def create_combo(combo: Combo):
    # 可以像剥洋葱一样一层层取数据
    return {
        "主食": combo.main_dish,
        "饮料": combo.drink.name,
        "加冰吗": combo.drink.iced,
        "小食几样": len(combo.snacks)
    }

顾客提交的请求体长这样（FastAPI 会自动逐层校验，哪层错了报哪层）：

{
  "main_dish": "牛肉面",
  "drink": {"name": "可乐", "iced": false},
  "snacks": [{"name": "鸡翅", "count": 2}, {"name": "薯条", "count": 1}]
}

更多嵌套形态

class Order(BaseModel):
    prices: dict[str, float]          # 字典：{"可乐": 3.5, "雪碧": 3.0}
    matrix: list[list[int]]            # 列表套列表：[[1,2],[3,4]]
    backup_drink: Drink | None = None  # 嵌套模型也可以可选

14请求示例数据（example）

类比：菜单上印"填写样例"，顾客照着填不出错。示例会自动显示在 /docs 的输入框里。

方法1：在模型里写示例（推荐）

from pydantic import BaseModel, Field

class Dish(BaseModel):
    # examples：给每个字段单独的示例值
    name: str = Field(examples=["宫保鸡丁"])
    price: float = Field(gt=0, examples=[28.5])

    # model_config：给整个模型一整份示例
    model_config = {
        "json_schema_extra": {
            "examples": [{"name": "鱼香肉丝", "price": 26.0}]
        }
    }

方法2：在接口上用 Body 写多份示例

from fastapi import Body

@app.post("/dishes")
def create_dish(
    dish: Dish = Body(examples=[{
        "正常单": {"summary": "一份正常的点菜",   # 示例标题
                  "value": {"name": "宫保鸡丁", "price": 28.5}},  # 示例内容
        "错误示范": {"summary": "价格写错的样子",
                    "value": {"name": "宫保鸡丁", "price": "二十八块五"}}
    }])
):
    return dish

/docs 里会出现下拉框，顾客可以选择不同示例一键填入。

15特殊数据类型

除了 str/int/float/bool，FastAPI 还支持这些类型，参数、模型字段里都能用：

类型说明餐厅类比
UUID全球唯一编号，格式自动校验会员卡的卡号
datetime日期+时间（2008-09-15T15:53:00）预约到店的时间
date / time只有日期 / 只有时间生日 / 营业时间
timedelta时长（秒数自动转换）等位时长
bytes原始字节（请求体里是 base64 文本）密封的调料包

from datetime import datetime
from uuid import UUID
from decimal import Decimal

@app.post("/orders/{order_uid}")
def create_order(
    order_uid: UUID,                        # 路径参数：自动校验 UUID 格式
    reserve_time: datetime,                 # 请求体参数：预约时间
    total: Decimal                          # 金额：精确小数
):
    return {"单号": order_uid, "预约": reserve_time, "金额": total}

16Cookie 参数

🍽️ 类比：会员卡
Cookie 是浏览器自动随身带的"会员卡"：顾客每次来，不用报名字，卡片一刷就知道是谁。它是浏览器自动附带的，不用写在网址里。
from fastapi import Cookie

@app.get("/profile")
def profile(session_id: str | None = Cookie(default=None)):
    # 从顾客的"会员卡"里读 session_id 字段
    # 顾客没卡（没 cookie）时就是 None
    return {"会员卡号": session_id}
ℹ️ 怎么测试 Cookie
浏览器 /docs 对 Cookie 支持有限，真实场景由前端自动携带。测试可用 Python：requests.get(url, cookies={"session_id": "abc123"})。

17Header 参数

🍽️ 类比：点菜单抬头的附加信息

28PATCH 部分更新

🍽️ 类比
PUT 是"整盘菜换掉"；PATCH 是"只把香菜挑掉，其他不动"——顾客只递要改的字段，没递的保持原样。
from pydantic import BaseModel
from fastapi.encoders import jsonable_encoder

# 更新专用模板：所有字段都可选（顾客想改哪样给哪样）
class DishPatch(BaseModel):
    name: str | None = None
    price: float | None = None

# 假装这是仓库里现有的菜
库存 = {"name": "宫保鸡丁", "price": 28.5}

@app.patch("/dishes/{dish_id}")
def patch_dish(dish_id: int, patch: DishPatch):
    # exclude_unset=True：只拿顾客"真正填了"的字段（没填的不要）
    改动 = patch.model_dump(exclude_unset=True)
    # 把改动合并进库存（真实项目是更新数据库）
    库存.update(改动)
    return {"改了几号": dish_id, "最新信息": jsonable_encoder(库存)}

顾客只提交 {"price": 32} → 只有价格被改，菜名保持"宫保鸡丁"。

💡 记忆
PUT = 全量替换（没给的字段清空），PATCH = 增量修改（没给的字段保留）。关键技巧就是 exclude_unset=True。

29依赖注入基础

🍽️ 类比：雇佣传菜员
多个窗口都要"翻同一页菜单"（分页参数），与其每个窗口自己抄一遍，不如雇个传菜员统一干。写一次，到处挂。
from fastapi import Depends

# 传菜员：统一解析分页参数
def pagination(page: int = 1, size: int = 10):
    # 统一计算"跳过几条"：第2页每页10条 → 跳过前10条
    skip = (page - 1) * size
    return {"skip": skip, "limit": size}

@app.get("/dishes")
def list_dishes(p=Depends(pagination)):
    # p 就是传菜员算好的 {"skip": x, "limit": y}
    return {"跳过": p["skip"], "取几条": p["limit"]}

@app.get("/users")
def list_users(p=Depends(pagination)):
    # 另一个窗口挂同一个传菜员，零重复代码
    return {"用户分页": p}

访问 /dishes?page=3&size=20 → 自动算出 {"skip": 40, "limit": 20}。

💡 本质
Depends(函数) = "先跑这个函数，把它的返回值塞给我"。传菜员的参数（page/size）FastAPI 也会自动从查询参数里解析。

30类作为依赖

依赖多了以后，用类把相关参数打包成一个"岗位"，更整洁。效果和函数依赖一样。

class PageQuery:
    # __init__ 的参数会被 FastAPI 自动从查询参数解析
    def __init__(self, page: int = 1, size: int = 10):
        self.page = page
        self.size = size
        self.skip = (page - 1) * size   # 顺手算好跳过量

@app.get("/orders")
def list_orders(p: PageQuery = Depends()):
    # p 是一个 PageQuery 对象，用点号取属性
    # 注意：类名写进类型标注时，Depends() 里可以省略不写类名
    return {"第几页": p.page, "跳过": p.skip}
ℹ️ 等价写法
p = Depends(PageQuery) 和 p: PageQuery = Depends() 效果相同，后者更短。

31子依赖

🍽️ 类比
传菜员自己也能喊帮手：经理（依赖）喊传菜员（子依赖），传菜员再去仓库拿货。依赖里可以再 Depends 别的依赖，像链条一样。
from fastapi import Depends, HTTPException

# 底层帮手：从请求头里拿令牌
def get_token(authorization: str | None = None):
    if not authorization:
        raise HTTPException(status_code=401, detail="没带令牌")
    return authorization

# 经理：依赖"令牌"，再查出用户
def get_current_user(token=Depends(get_token)):
    # 真实项目里这里会解析 JWT 查数据库，先简化
    if token != "vip888":
        raise HTTPException(status_code=401, detail="令牌无效")
    return {"name": "会员大大", "level": 3}

# 窗口：只挂经理，链条自动跑完整条
@app.get("/me")
def me(user=Depends(get_current_user)):
    return user

# 经理还能继续被依赖：查"是不是店长"
def get_admin(user=Depends(get_current_user)):
    if user["level"] < 5:
        raise HTTPException(status_code=403, detail="需要店长权限")
    return user

链条：/me 窗口 → get_current_user → get_token，每层出错都会在正确的位置停下并报错。

32yield 依赖：自动开关门

🍽️ 类比
仓库管理员：顾客来了开门，顾客走了锁门——不管交易成功与否，门必须锁。用 yield 写依赖：yield 前是"开门"，yield 后是"锁门"，保证执行。
from fastapi import Depends

def get_db():
    # ---- yield 之前：开门（建立连接）----
    db = "一个假的数据库连接"
    print("仓库开门")
    try:
        yield db   # 把连接递给窗口使用
    finally:
        # ---- yield 之后：锁门（关闭连接）----
        # finally 保证：就算窗口里报错了，这里也一定会执行
        print("仓库锁门")

@app.get("/data")
def read_data(db=Depends(get_db)):
    return {"用的连接": db}

真实项目里数据库连接、文件句柄都用这个模式管理，第 39 章的 SQLModel 实战就是这么做的。

33全局依赖与装饰器依赖

两种"不需要返回值、只为检查/拦截"的依赖用法。

装饰器依赖：本窗口的入场检查

from fastapi import Depends, HTTPException, Header

def check_open(x_token: str | None = Header(default=None)):
    # 只检查，不返回有用的值（所以挂在装饰器上，不占函数参数）
    if x_token != "secret":
        raise HTTPException(status_code=403, detail="本店今日歇业")

# dependencies=[...]：进这个窗口前先过检查，但函数里拿不到返回值
@app.get("/vip-room", dependencies=[Depends(check_open)])
def vip_room():
    return {"msg": "欢迎进入包间"}

全局依赖：全店所有窗口统一检查

# 在"盖厨房"时就挂上：每个窗口自动过一遍 check_open
# 适合：全站维护模式、统一鉴权
app = FastAPI(dependencies=[Depends(check_open)])
ℹ️ 三种挂载方式对比
def f(x=Depends(d))：要返回值 → 挂参数上；dependencies=[Depends(d)]：只检查不取值 → 挂装饰器上；FastAPI(dependencies=[...])：全店通用 → 挂 app 上。

34安全概念与 OAuth2 密码流程

🍽️ 类比：会员制度
1) 顾客在收银台出示用户名密码（登录）→ 2) 店里发一张带编号的会员卡（令牌 Token）→ 3) 之后进包间刷卡即可，不用每次报密码（带令牌访问）。这套流程的行业标准叫 OAuth2 Password Flow。

FastAPI 自带的"刷卡器"

# tokenUrl="login" 告诉文档：去 /login 窗口领卡

# 假的用户数据库

# 领卡窗口：OAuth2PasswordRequestForm 是官方标准的登录表单

35JWT 登录完整实例

上章的"令牌=用户名"太假了，谁都能伪造。JWT 是带防伪印章的会员卡：里面写着用户是谁、几点过期，篡改了就会被识破。

pip install PyJWT
jwt_demo.py（完整可运行）
from fastapi import FastAPI, Depends, HTTPException
from fastapi.security import OAuth2PasswordBearer, OAuth2PasswordRequestForm
import jwt                                   # PyJWT：制卡/验卡工具
from datetime import datetime, timedelta, timezone

app = FastAPI(title="JWT 登录演示")

# ========== 制卡车间参数 ==========
SECRET_KEY = "change-me-to-a-long-random-string"  # 防伪印章的印油（绝密！）
ALGORITHM = "HS256"                                # 印章算法
TOKEN_MINUTES = 30                                   # 卡的有效期：30 分钟

刷卡器 = OAuth2PasswordBearer(tokenUrl="login")

# 假用户库（真实项目用数据库 + 密码哈希存储）
假用户库 = {"xiaobai": {"password": "123456", "nickname": "小白"}}

# ========== 制卡：登录成功 → 发 JWT ==========
@app.post("/login")
def login(form: OAuth2PasswordRequestForm = Depends()):
    用户 = 假用户库.get(form.username)
    if not 用户 or 用户["password"] != form.password:
        raise HTTPException(status_code=400, detail="用户名或密码错误")
    # 卡面内容：你是谁(sub) + 几点过期(exp)
    卡面 = {
        "sub": form.username,
        "exp": datetime.now(timezone.utc) + timedelta(minutes=TOKEN_MINUTES)
    }
    # jwt.encode：盖章制成防伪卡
    token = jwt.encode(卡面, SECRET_KEY, algorithm=ALGORITHM)
    return {"access_token": token, "token_type": "bearer"}

# ========== 验卡：受保护窗口 ==========
def get_current_user(token: str = Depends(刷卡器)):
    try:
        # jwt.decode：验印章 + 查有效期，任一不过直接抛错
        卡面 = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
    except jwt.PyJWTError:
        raise HTTPException(status_code=401, detail="卡无效或已过期")
    用户 = 假用户库.get(卡面["sub"])
    if not 用户:
        raise HTTPException(status_code=401, detail="用户不存在")
    return 用户

@app.get("/me")
def me(用户=Depends(get_current_user)):
    return {"欢迎": 用户["nickname"], "身份来源": "JWT 防伪卡"}
⚠️ 上线前必改
① SECRET_KEY 换成足够长的随机字符串并放进环境变量（第 45 章）；② 密码要用 passlib 的 bcrypt 哈希存储，绝不存明文；③ 全站启用 HTTPS，防止卡被截走。

36中间件

🍽️ 类比：门口保安
保安站在门口，每个进来和出去的人都要经过他。适合干"全员通用"的活：计时、记日志、加响应头。
import time
from fastapi import Request

# @app.middleware("http")：给厨房门口挂一个保安
@app.middleware("http")
async def timer_guard(request: Request, call_next):
    start = time.time()                       # 顾客进门，按秒表
    response = await call_next(request)       # 放行，进厨房处理
    cost = time.time() - start                # 出门，再按秒表
    # 在响应头贴小纸条："本次出餐耗时 xx 秒"
    response.headers["X-Process-Time"] = str(cost)
    return response
ℹ️ 中间件 vs 依赖
中间件对所有请求生效，拿不到解析好的参数；依赖只对挂了它的窗口生效，能用 FastAPI 的参数解析。全员检查用中间件，按窗口检查用依赖。

from fastapi import FastAPI, HTTPException, Depends
from sqlmodel import SQLModel, Field, Session, create_engine, select

# ========== 货架图纸（数据库表） ==========
class Book(SQLModel, table=True):   # table=True：同时是一张数据库表
    id: int | None = Field(default=None, primary_key=True)  # 主键，自动编号
    title: str = Field(min_length=1)
    author: str = Field(min_length=1)
    price: float = Field(gt=0)

class BookCreate(SQLModel):   # 添书表单（顾客不用填 id）
    title: str
    author: str
    price: float

# ========== 盖仓库 ==========
engine = create_engine("sqlite:///library.db")  # 仓库=当前文件夹的 library.db
SQLModel.metadata.create_all(engine)             # 按图纸搭货架（已存在则跳过）

# ========== 仓库管理员（yield 依赖，见第32章） ==========
def get_session():
    with Session(engine) as session:
        yield session   # 开门递钥匙，用完自动锁门

app = FastAPI(title="带数据库的图书馆")

# --- 上架 ---
@app.post("/books", response_model=Book, status_code=201)
def create_book(book_in: BookCreate, db=Depends(get_session)):
    book = Book(**book_in.model_dump())  # 表单 → 待上架的书
    db.add(book)       # 放入仓库（暂存）
    db.commit()        # 盖章确认（真正写入）
    db.refresh(book)   # 刷新拿到自动编的 id
    return book

# --- 查全部（带分页，复习第29章） ---
@app.get("/books", response_model=list[Book])
def list_books(offset: int = 0, limit: int = 10, db=Depends(get_session)):
    # select：选货架；offset：跳过前几条；limit：最多取几条
    return db.exec(select(Book).offset(offset).limit(limit)).all()

# --- 查一本 ---
@app.get("/books/{book_id}", response_model=Book)
def get_book(book_id: int, db=Depends(get_session)):
    book = db.get(Book, book_id)   # 按主键精确取
    if not book:
        raise HTTPException(status_code=404, detail="这本书不存在")
    return book

# --- 部分更新（PATCH，复习第28章） ---
class BookPatch(SQLModel):   # 更新表单：全部可选
    title: str | None = None
    author: str | None = None
    price: float | None = None

@app.patch("/books/{book_id}", response_model=Book)
def patch_book(book_id: int, patch: BookPatch, db=Depends(get_session)):
    book = db.get(Book, book_id)
    if not book:
        raise HTTPException(status_code=404, detail="这本书不存在")
    # exclude_unset=True：只取顾客真正填了的字段
    for key, value in patch.model_dump(exclude_unset=True).items():
        setattr(book, key, value)   # 逐字段更新
    db.add(book)
    db.commit()
    db.refresh(book)
    return book

# --- 下架 ---
@app.delete("/books/{book_id}")
def delete_book(book_id: int, db=Depends(get_session)):
    book = db.get(Book, book_id)
    if not book:
        raise HTTPException(status_code=404, detail="这本书不存在")
    db.delete(book)
    db.commit()
    return {"消息": f"《{book.title}》已下架"}

  • 保活：用 systemd 或 pm2 让程序崩溃后自动重启
⚠️ 上线检查清单
关掉 /docs 或加访问控制；SECRET_KEY 进环境变量；CORS 不要用 *；密码哈希存储；数据库换正式库并备份。

49常见坑 FAQ（15 个）

1. 改了代码没反应？启动时忘了加 --reload。
2. uvicorn 不是命令？改用 python -m uvicorn main:app --reload。
3. POST 一直 422？JSON 格式错了（单引号、多逗号），或字段类型不对。去 /docs 用它的格式试。
4. 路径参数 404？装饰器路径和函数参数名必须一致：/items/{item_id} 配 def f(item_id: int)。
5. /items/me 被 /items/{item_id} 抢走？具体路径写在参数路径前面。
6. 数据重启就丢？你用的是列表存数据，上数据库（第 39 章）。
7. 前端连不上，报 CORS？忘配 CORSMiddleware（第 37 章）。
8. 敏感字段泄漏给前端？忘用 response_model 过滤（第 21 章）。
9. 端口被占用？换门牌：uvicorn main:app --port 8001。
10. Form/File 报 "Did you forget to install python-multipart"？pip install python-multipart。
11. async def 和 def 怎么选？小白阶段全用 def；用了 async 就不能在里面写耗时的同步代码（如 time.sleep），会堵住所有顾客。
12. yield 依赖里锁门代码没执行？把清理代码放进 try...finally 的 finally 里（第 32 章写法）。
13. Depends 里想用 Query 默认值但顺序报错？带默认值的参数放后面，或全部用关键字参数。
14. 测试时报 import 错误？test 文件和被测文件放同一目录，或在 pytest 运行时加 python -m pytest。
15. 生产环境 /docs 打不开？可能是部署时关了 docs_url，或 Nginx 没转发对应路径。
