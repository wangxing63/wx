一句话记住：看不懂代码，十有八九不是逻辑难，是卡在几个英文单词和符号上 —— 下面全部拆开。

前面说了「每个英文都翻译」，这里把原生 JavaScript、浏览器、HTML、CSS 的词一次列全。全书代码块里第一次出现时也会就地注一句；重复出现的词，回来查这张表即可。

读一行代码的三步法（比背单词更快）

① 先找 =：谁把值给了谁。　② 再看 .：读作「的」，一层层往下取。　③ 最后看 ( )：括号里是「交给它的东西」。
例：document.querySelector('#num').textContent = count; → 「文档 的 查找方法（找 #num）的 文字内容　＝　count」。第 1 章有这张逐词对照图。

01Vue 是什么

一章只回答一件事：Vue 替你省掉了哪一步。

一句话记住：以前要自己动手改网页，现在只改数据，网页自己变。

1.1 先看没有 Vue 时有多麻烦

做一个最简单的计数器：页面上有个数字，点一下按钮加 1。用原生 JavaScript 要写两件事 —— 先改数据，再亲手找到页面上的那个位置把它改掉。

原生 JavaScript（对照用，不用抄）每个词都拆给你看
let count = 0;
#  let = 声明一个「以后可以再改」的变量；count = 计数（自己起的名字）
#  = 是「把右边放进左边」，不是数学的等于；0 = 初始值；; = 这一句写完了
function add() {
#  function = 函数／一段能反复执行的代码；add = 函数名（自己起的）
#  () = 参数列表（这里不用传东西）；{ } = 这对大括号中间就是函数的内容
  count = count + 1;
  #  第 1 步：改数据（内存里的数字）；+ 1 = 加一；= 把结果存回 count
  document.querySelector('#num').textContent = count;
  #  第 2 步：还得亲手去页面里找到 #num，把文字改成新数字
  #  这一行的 7 个零件，下面用图和表逐个拆开讲 ↓
}
#  } = 函数到此结束；这一整段都要自己写、自己维护，页面一多就漏
document.querySelector('#num').textContent = count;
逐词拆解（含标点，一个都不跳过）
documentdocument 英文＝「文档」。浏览器把整个网页当成一份文档，用这个内置对象代表它。想碰页面上的任何东西，都要从它开始。
.（点号）读作「的」。document.querySelector ＝「文档的查找方法」。JS 用点号一层层往下取东西，和中文「我的书包的拉链」一个道理。
querySelectorquery ＝ 查询，selector ＝ 选择器。合起来＝「按 CSS 选择器找元素」，返回找到的第一个元素。另有 querySelectorAll ＝ 找出全部（All ＝ 所有）
( )小括号＝「把参数交给这个函数」。里面写要找谁；add() 里空着就是不用传参数。
'#num'单引号包住的是字符串（一段文字）。# 表示按 id 找，num 是那个元素的 id 名。整句＝「找 id 等于 num 的那个元素」。同理 . 开头是按 class 找
.textContenttext ＝ 文本，content ＝ 内容。指元素「里面显示的文字」。读它是取文字，给它赋值就是把页面上的字换掉。近亲 innerHTML ＝ 连 HTML 标签一起换；value ＝ 输入框里的值
=赋值号，读作「把右边放进左边」，不是数学里的「两边相等」。判断相等要写 ===。
count我们自己起的变量名，装着刚加完 1 的数字。
;分号＝这一句代码写完了。JS 里可以省略，本书统一写上，方便你看清断句。
一句话人话版

「去网页里找到 id 叫 num 的那个位置，把它显示的文字，改成 count 现在的值。」
后面所有代码里的英文和符号，都会这样逐个注明；想一次查全，看 开篇「代码关键字速查表」。

页面少的时候还行。页面一多，每个数字变了，都要记得改哪几处，漏一处就显示错。绝大多数前端 bug 就是这么来的。

1.2 Vue 把第 2 步接管了

Vue 写法（第 3 章会手把手带你建这个文件）App.vue · 每个词都拆开
<script setup>
#  <script> = 写 JS 的那一块；setup = 设置，Vue 3 的语法糖标记；</script> = 这块结束
import { ref } from 'vue'
#  import = 导入；{ } = 只拿括号里这几样；ref = 引用／响应式盒子；from = 从……来
#  'vue' = 包名，单引号包住的是文字字符串；这一行＝从 vue 包里把 ref 拿进来用
const count = ref(0)
#  const = 常量（不再重新赋值）；count = 自己起的变量名；= 把右边放进左边
#  ref(0) = 调用函数 ref，括号里传 0；合起来＝把 0 包成「会被盯着的数据」
</script>

<template>
#  template = 模板；这一块写「页面长什么样」，里面就是 HTML 标签
  <button @click="count++">点我 +1</button>
#  button = 按钮标签；@click = 绑定点击事件（@ 是 v-on: 的简写，click = 点击）
#  "count++" = 点一下就执行这句；++ = 加 1；引号里写的是 JS 表达式
  <p>现在：{{ count }}</p>
#  p = paragraph 段落标签；{{ }} = 插值，把数据显示在这里；模板里不用写 .value
</template>
这里没有一行代码去操作网页。改 count，那句 {{ count }} 自己就变。这就是 Vue 全部的价值。
打个比方（全书只用这一个）

把 Vue 想成 一张会自动重算的 Excel 表格：

① 数据＝表格里的单元格（A1 里写着 3）。
② 页面＝写了公式的另一个格子（=A1*2，显示 6）。
③ 你把 A1 改成 5，那个公式格不用你管，自动变成 10。

05模板语法与指令总表

5.1 插值：把数据塞进文字里

template 里能写什么照着改 App.vue 试
<p>{{ message }}</p>
#  {{ }} = 插值（interpolation）；把 message 的值显示在这里
<p>{{ 1 + 2 }}</p>          #  能算简单式子 → 显示 3
<p>{{ ok ? '是' : '否' }}</p>  #  三元判断：ok 为真显示「是」，否则「否」
<p>{{ name.toUpperCase() }}</p> #  能调方法：toUpperCase = to 转 + Upper 大写 + Case；() = 执行这个方法
#  name.toUpperCase() 里的点号 . 读作「的」＝「name 的转大写方法」
#  ? : 是三元判断：问号前是条件，冒号前＝成立时的值，冒号后＝不成立时的值
#  '是' 用单引号包住＝一段文字（字符串）；{{ }} 里只能写一个表达式，不能写语句
{{ }} 里只能写一个表达式（能算出一个值的式子），不能写语句：{{ if (ok) {...} }}、{{ for(...) }}、{{ let a = 1 }} 全部报错。要判断就用三元，要循环就用 v-for，要复杂计算就用第 9 章的 computed。
写法作用提醒
{{ msg }}显示文本最常用；内容里的 HTML 会被当纯文字显示（安全）
v-text="msg"同上，写成指令形式会覆盖标签里原有文字
v-html="htmlStr"把字符串当 HTML 渲染只放自己写的内容；放用户输入会有 XSS 风险
v-pre这标签里不编译，{{ }} 原样显示写教程文档时才用
v-once只渲染一次，之后数据变也不更新极少数优化场景
v-cloak配合 CSS 隐藏未编译的 {{ }}用 Vite 基本用不上

5.2 一个指令的完整长相

指令格式（拿 v-on 举例）拆开记
<form v-on:submit.prevent="save">
#  v-on   = 指令名：绑定事件（on 就是「当……发生时」）
#  :submit= 参数 arg：监听 submit 提交事件
#  .prevent = 修饰符 modifier：阻止表单默认刷新页面
#  ="save" = 值：事件发生时执行 save 函数

<form @submit.prevent="save">
#  @ = v-on: 的简写；2026 年实际项目几乎都写 @ 这种
v-指令:参数.修饰符="值"　→　@事件.修饰符="处理函数"
v-Vue 指令的固定前缀，v 就是 Vue。看见 v- 就知道「这行 HTML 被 Vue 特殊处理」。
on / bind / if / for / model指令名：分别是事件 / 绑定属性 / 条件 / 循环 / 双向绑定。
:submit冒号后面是参数（argument）＝「具体对哪个东西生效」。
.prevent点号后面是修饰符（modifier）＝「附带一个小动作」，可以连写多个。
"save"引号里是 JS 表达式，不是字符串常量；写函数名就是「事件来了调它」。
@ / :@ ＝ v-on: 简写；: ＝ v-bind: 简写。这两个符号全书都会出现，务必记住。

事件绑定与修饰符@ 写法
<button @click="add">+1</button>

<button @click="count += 2">+2</button>
#  也可以直接写一句简单表达式；+= = 加等于
<input @input="onInput">
#  input = 输入事件，每敲一个字触发一次
<form @submit.prevent="save">...</form>
#  submit = 提交；.prevent = preventDefault 阻止默认行为（不让页面刷新）
<div @click="parentFn">
  <button @click.stop="childFn">我</button>
#  .stop = stopPropagation 阻止冒泡：点按钮不再触发外层 div 的 parentFn
</div>
<input @keyup.enter="search">
#  keyup = 松开按键；.enter = 只在回车键触发；search = 要执行的函数
修饰符英文全名 / 意思典型场景
.preventpreventDefault ＝ 阻止浏览器默认动作表单提交不刷新页面
.stopstopPropagation ＝ 阻止事件往外层冒点弹窗里的按钮不触发遮罩关闭
.onceonce ＝ 只触发一次「同意协议」按钮

① 文字 {{ }}／属性 :／事件 @，三选一不会错。
② 引号里想当 JS 用，必须加冒号；href="url" 与 :href="url" 天差地别。

07条件渲染与列表渲染

页面上的「有时有、有时没有」和「一串一样的东西」，就靠这四个指令。

一句话记住：v-if 决定生不生成，v-show 只管藏不藏，v-for 负责重复，:key 给每项发身份证。

7.1 v-if 与 v-show：看着一样，其实不一样

条件渲染照抄体验
<p v-if="score >= 60">及格</p>
#  v-if = if 如果；条件为真才创建这个 p 元素；>= 是大于等于
<p v-else-if="score >= 40">补考</p>
#  v-else-if = else if 否则如果；必须紧跟在 v-if 后面
<p v-else>不及格</p>
#  v-else = else 否则；兜底分支，不写条件

<p v-show="isShow">我一直在 DOM 里</p>
#  v-show = show 显示；不管真假都创建，靠 display:none 藏起来

<template v-if="login">
#  template = 隐形包裹标签；想一次控制多个元素又不想多套一层 div，就用它
  <h3>欢迎回来</h3><p>退出登录</p>
</template>
对比v-ifv-show
条件为假时元素根本不存在（DOM 里被删掉）元素还在，只是 display:none
切换开销大（要创建 / 销毁，子组件会走生命周期）小（只改一个 CSS 属性）
首次开销小（假就不创建）大（不管怎样都创建）
什么时候用很少切换、或条件初始多为假（权限区、登录后才显示）频繁切换（Tab 页、展开收起、弹窗）

7.3 数组变了，页面一定会变吗

Vue 3 用 Proxy 监听数组，下面两类方法都能触发更新，但写法不同：

分类方法怎么写
变更方法（改原数组）push 末尾加、pop 末尾删、shift 开头删、unshift 开头加、splice 任意增删、sort 排序、reverse 反转直接 list.push(新项)，页面自动更新
替换方法（返回新数组）filter 过滤、concat 拼接、slice 切片、map 映射、展开运算符 [...list]必须赋值回去：list.value = list.value.filter(...)，否则页面不动
常见坑：改了但页面没变对照记
const list = ref([{ id: 1, name: '苹果' }])
#  ref = 包成响应式；[ ] = 数组；{ } = 对象；id/name = 字段名

list.value.push({ id: 2, name: '香蕉' })
#  ✅ 直接 push 就能更新（Vue 3 已监听数组方法）

list.value = list.value.filter(item => item.id !== 2)
#  ✅ filter 返回新数组，必须重新赋值给 list.value；!== = 不等于

list.value.filter(item => item.id !== 2)
#  ❌ 忘了赋值 → 算完就丢，页面不会有任何变化

list.value[0] = { id: 9, name: '新' }
#  ✅ Vue 3 用 Proxy，直接按下标改也能被检测到（Vue 2 不行，老教程会说不行）

① 很少切换用 v-if，频繁切换用 v-show。
② v-for="(项, 下标) in 数组" :key="项.id"，key 用唯一 id，别用下标。

08表单双向绑定

输入框里打字，数据自己跟着变；数据变，输入框自己也变。

一句话记住：v-model ＝ :value + @input 打包成一行。

8.1 先看它替你省了什么

等价写法对照理解用
<input v-model="name">
#  model = 模型／数据；整句＝输入框和数据 name 双向绑住

#  上面这一行，等价于下面手写的两件事：
<input :value="name" @input="e => name = e.target.value">
#  :value = 把数据填进输入框（数据 → 页面）
#  @input = 输入时把新值取回数据（页面 → 数据）；e.target.value = 输入框当前文字
类比

普通绑定像单向喇叭：数据喊一声，页面听到。v-model 像对讲机：页面里改了，数据也收到。表单之所以要双向，因为值本来就是用户敲进去的。

8.2 各种表单控件怎么写

src/App.vue · 表单全家逐词注释
<script setup>
import { ref } from 'vue'
const name = ref('')
#  ref('') = 空字符串；文本框初始值
const agree = ref(false)
#  false = 假；单个复选框用布尔值
const hobbies = ref([])
#  [ ] = 空数组；多个复选框用数组装选中的值
const sex = ref('女')
#  单选框用字符串，值等于被选中那一项的 value
const city = ref('bj')
#  下拉框同理，'bj' 是默认选中的 option 的 value
</script>

<template>
  <input v-model="name" placeholder="输入名字">
  <p>你好，{{ name }}</p>
#  边打字边变，不需要任何事件函数

  <input type="checkbox" v-model="agree"> 同意协议
#  type = 类型；checkbox = check 勾选 + box 框＝复选框；勾选后 agree 变 true
#  true / false = 真 / 假（布尔值）；ref(false) 表示初始未勾选；ref([]) 的 [ ] = 空数组

  <input type="checkbox" value="篮球" v-model="hobbies">
#  多个 checkbox 绑同一个数组；选中就把 value 放进数组
  <input type="checkbox" value="音乐" v-model="hobbies">

  <input type="radio" value="男" v-model="sex">
  <input type="radio" value="女" v-model="sex">
#  radio = 单选按钮；同一组绑同一个变量

  <select v-model="city">
    <option value="bj">北京</option>
    <option value="sh">上海</option>
  </select>
#  select = 下拉框；option = 选项；注意 v-model 写在 select 上，不是 option 上
  <p>当前选择：{{ city }}</p>
</template>
检查点

在输入框打字，下面「你好，xxx」边打边变；勾复选框，agree 在 true/false 之间跳；选下拉框，city 变成 bj 或 sh。一行事件代码都没写，这就是 v-model 的价值。

8.3 三个修饰符

写法英文意思解决什么
v-model.lazylazy ＝ 懒的默认每次输入都同步；加了它改成失去焦点 / 回车时才同步（少算几次）
v-model.numbernumber ＝ 数字输入框拿到的永远是字符串，加了它自动转数字，避免 "1" + "2" = "12"
v-model.trimtrim ＝ 修剪自动去掉首尾空格，用户名、搜索框必备
修饰符可以连写常见组合
<input v-model.number.trim="age" type="number">
#  .number = 转数字；.trim = 去空格；age = 数据变量；type="number" = 数字输入框
组件上用 v-model（第 17 章细讲）

自己写的组件也想要 v-model，2026 年用 defineModel() 一行搞定：const model = defineModel()，然后组件里 <input v-model="model">。父组件照旧 <MyInput v-model="name" />。老教程里手写 modelValue + update:modelValue 的写法，现在只需了解。

归纳 · 本章

① v-model 只用在表单元素或组件上，普通 div 上无效。
② 文本框 / 单选 → 字符串；单复选框 → 布尔；多复选框 / 多选下拉 → 数组。
③ 要数字加 .number，要去掉空格加 .trim，要省性能加 .lazy。

09计算属性与侦听器

三个都是「数据变了自动做事」，区别只在：算出新值，还是顺便干点别的。

一句话记住：要得到一个新值用 computed；要顺手做件事（发请求、存本地）用 watch。

9.1 computed：会缓存的公式格

src/App.vue · 购物车总价逐词注释
<script setup>
import { ref, computed } from 'vue'
#  import = 导入；computed = compute 的过去分词＝「被计算出来的」
const price = ref(12)
const qty = ref(2)
const total = computed(() => price.value * qty.value)
#  computed(函数) = 定义一个计算属性；() => = 箭头函数，返回一个值
#  price.value * qty.value = 单价 × 数量；只要这两个变了，total 自动重算
#  没变就用上次缓存的结果，不会白白重算（这叫缓存）
</script>

<template>
  <input type="number" v-model.number="qty">
  <p>总价：{{ total }} 元</p>
#  模板里用 computed 和用 ref 一样，直接写名字，不写 .value
</template>
类比

computed 就是 Excel 里的公式格：=A1*B1。它自己不存数据，只存「怎么算」；A1、B1 没变时，Excel 不会每帧重算一遍（缓存）。methods（普通函数）则像你每次都手动按一次计算器，用几次算几次。

computed 能不能改？

默认只读。硬要可写就传 { get(){}, set(v){} }，但新手阶段用不到。不要在 computed 里发请求、改别的数据、弹窗 —— 它只负责「算出一个值」，要副作用请用 watch。

▶ 可以点一下：computed 自动重算（对应第 1 章那个 Excel） 交互演示
单价 12 ×2数量 → 总价
24 元
① qty 变 → ② computed 发现依赖变了 → ③ total 重算并刷新页面
依赖不变时（比如只改了别的无关数据），第 ② 步不会亮：这就是「缓存」。

9.2 watch：数据变了，顺手做件事

侦听器的四种常见写法逐词注释
import { ref, watch } from 'vue'
#  watch = 观看／监视；「盯着某个数据，一变就执行后面的函数」
const keyword = ref('')

watch(keyword, (newVal, oldVal) => {
#  第 1 个参数 = 要盯的数据；第 2 个参数 = 变化时执行的回调
#  newVal = new value 新值；oldVal = old value 旧值
  console.log('搜索词变了：', newVal)
#  console.log = 在浏览器控制台打印，用来调试
})

watch(() => user.value.age, (n) => { /* ... */ })
#  () => 这种叫 getter 函数：只想盯对象里某个字段时这样写

watch([a, b], ([na, nb]) => { /* ... */ })
#  [ ] = 一次盯多个；回调里拿到的也是数组，顺序对应

watch(obj, (n) => { /* ... */ }, { deep: true, immediate: true })
#  deep: true = 深度监视，对象里层字段变了也触发
#  immediate: true = 立即，绑定时就先执行一次（不等变化）
选项意思典型场景
deep: truedeep ＝ 深的，连对象内部一起盯整个表单对象改动都要保存
immediate: trueimmediate ＝ 立即，先跑一次进页面就按默认值发一次请求
flush: 'post'post ＝ 之后，等 DOM 更新完再执行回调里要读页面元素尺寸
once: trueonce ＝ 一次，触发后自动停止只等第一次数据到位
返回值 stop()stop ＝ 停止；const stop = watch(...); stop()组件销毁前手动取消
2026 年写法：请求要能取消

搜索框边打边发请求，旧请求要取消，否则结果会乱序。Vue 3.5+ 可以直接导入 onWatcherCleanup：watch(keyword, async () => { const c = new AbortController(); onWatcherCleanup(() => c.abort()); ... })。零基础先知道有这回事，第 25 章实战会用简单版。

watchEffect(() => {
#  不写盯谁！函数里用到谁，Vue 就自动盯谁；并且立刻先执行一次

#  document.title = 浏览器标签页标题；反引号模板字符串里用 ${} 插值
})

「页面要显示一个算出来的数」→ computed。

10组件与单文件组件

页面大了就拆成一块块积木，每块单独存成一个 .vue 文件。

一句话记住：组件 = 可以反复用的「一小段自带数据和样式的 HTML」。

10.1 为什么要拆

第 3 章那个页面只有几行，写在一个 App.vue 里没问题。真实项目里有头部、菜单、商品卡片、购物车……如果全塞一个文件，会有几千行，改哪里都怕碰坏别处。拆开之后：

好处说人话
能复用商品卡片写一次，列表里循环 20 次就是 20 张，不用复制 20 遍
好找按钮样式不对 → 只改 MyButton.vue，不用翻几千行
互不干扰每个组件有自己的数据；A 卡片的数字变了，不会串到 B 卡片
类比

组件是乐高积木，App.vue 是拼好的成品。更贴切地说：它像 Excel 里做好的一张表格模板 —— 表头、公式都写好了，用的时候只要往几个空格里填数（这就是第 11 章的 props）。

10.2 一个 .vue 文件的三段

src/components/MyButton.vue · 新建文件三段结构
<template>
#  第 1 段：template 模板＝页面长什么样（必写）
  <button class="my-btn" @click="count++">
    {{ text }}（点过 {{ count }} 次）
  </button>
</template>

<script setup>
#  第 2 段：script 脚本＝数据和逻辑；setup = 设置，写了它就能直接用组合式 API
import { ref } from 'vue'
#  import = 导入；ref = 包响应式数据的函数；from 'vue' = 从 vue 包来
const count = ref(0)
const props = defineProps({ text: String })
#  defineProps = 定义外部传进来的参数；text = 参数名；String = 要求传字符串
#  （下一章细讲；只想看结构的话这行可以先删掉，改成 const text = '按钮'）
</script>

<style scoped>
#  第 3 段：style 样式（可省略）；scoped = 作用域受限，只影响本组件的按钮
.my-btn { background: #42b883; color: #fff; border: 0; border-radius: 8px; padding: 8px 16px; }
</style>
<script setup> / <style scoped>
template模板。写 HTML + Vue 指令。一个组件只能有一个根级模板块。
script脚本。写 JS：数据、函数、导入其它组件。setup 是 Vue 3 的语法糖标记（第 14 章讲透）。
style样式。写 CSS。
scopedscoped ＝ 限定作用域的。编译后给本组件元素加唯一属性，样式不会污染别的组件。
definePropsdefine ＝ 定义，Props ＝ properties 属性。声明「别人用我时要传什么」。

10.3 在 App.vue 里用它

src/App.vue · 三步：导入 → 当标签用复制即可
<script setup>
import MyButton from './components/MyButton.vue'
#  import = 导入；MyButton = 给它起的本地名字；from = 文件路径
#  ./ = 当前目录（src）；.vue 后缀不能省
#  用了 <script setup> 之后，导入的组件自动可用，不需要再注册
</script>

<template>
  <MyButton text="保存" />
  <MyButton text="取消" />
#  同一个组件用两次，各自有各自的 count：点第一个不会让第二个变
#  text="保存" = 传字符串常量；想传变量要写 :text="变量名"
</template>
检查点

页面上出现两个绿色按钮，分别点，各自计数，互不影响。看到这个就说明「组件实例互相独立」这件事懂了。

命名小规矩

组件文件用大驼峰：MyButton.vue、UserCard.vue；模板里可以写 <MyButton />，也可以写 <my-button />，两种都认。别起 Button.vue 这种和原生 HTML 标签重名的，容易分不清。

归纳 · 本章

① 一个 .vue ＝ <template> + <script setup> + <style scoped>。
② 用组件只要两步：import 名字 from '路径.vue' → 模板里写 <名字 />。
③ 每个组件实例数据各自独立；scoped 让样式不串台。

11组件之间传值

四种关系，四句话讲完：往下、往上、隔了几层、父要主动调子。

一句话记住：父传子用 props，子通知父用 emit，隔代用 provide/inject，全家共用去第 21 章用 Pinia。

11.1 父 → 子：props

子组件 src/components/UserCard.vue收数据
<script setup>
const props = defineProps({
#  defineProps = define + Props 定义属性；这是编译宏，不用 import
  title: String,
#  title = 属性名；String = 类型必须是字符串
  count: { type: Number, default: 0 },
#  Number = 数字类型；default = 没传时的默认值 0
  user: { type: Object, required: true }
#  Object = 对象；required: true = 必传，不传会在控制台警告
})
#  props 是只读的：子组件里 props.count++ 会警告，且不该这么做
</script>

<template>
  <h3>{{ title }}</h3>
  <p>{{ user.name }}　共 {{ count }} 项</p>
#  模板里直接用属性名，不用写 props.title（会自动解包）
</template>
父组件 src/App.vue发数据
<script setup>
import { ref } from 'vue'
import UserCard from './components/UserCard.vue'
const total = ref(3)
const me = ref({ name: '小明' })
</script>

<template>
  <UserCard title="我的资料" :count="total" :user="me" />
#  title="我的资料" = 传固定字符串（不加冒号）
#  :count="total" = 传变量 total（必须加冒号）；:user="me" 同理
</template>
第一大坑：忘了冒号

写 count="total" 传过去的是四个字母 "total"，子组件拿到字符串，页面显示怪东西甚至类型警告。只要传的是变量、数字、布尔、对象、数组，一律加 :。

11.2 子 → 父：emit

子组件：按钮被点时「喊一声」不带数据 / 带数据
<script setup>
const emit = defineEmits(['add', 'delete'])
#  defineEmits = 定义我要往外抛哪些事件；[ ] = 事件名数组
#  emit = 发射／发出；拿到一个「喊话用的函数」
function onAdd() {
  emit('add', 1)
#  第 1 个参数 = 事件名；第 2 个起 = 带给父组件的数据（可以多个）
}
</script>

<template>
  <button @click="onAdd">加一项</button>
  <button @click="emit('delete', 2)">删两项</button>
#  模板里也可以直接调 emit；'delete' = 事件名，2 = 带出去的数字
</template>
父组件：接住这一声@事件名
<UserCard @add="n => total += n" @delete="n => total -= n" />
#  @add = 监听子组件抛出的 add 事件；n = 子组件带过来的数据
#  n => total += n = 箭头函数：拿到 n，把父组件的 total 加上 n
#  写成 @add="handleAdd" 再在 script 里定义 handleAdd(n){...} 更清楚

11.3 双向：defineModel（2026 年推荐）

子组件 src/components/MyInput.vue一行搞定双向
<script setup>
const model = defineModel()
#  defineModel = 定义双向绑定的数据；返回一个 ref；Vue 3.4+ 起稳定，2026 年首选
</script>
<template>
  <input v-model="model">
#  子组件里改了 model，父组件那个变量同步变，不用 emit
</template>
父组件照旧写 v-model
<MyInput v-model="name" />
#  底层仍等价于 :modelValue + @update:modelValue，只是不用你手写
<MyInput v-model:title="title" />
#  带参数可以绑多个：子组件写 defineModel('title') 接收

11.4 隔了几层：provide / inject

祖先组件提供 · 任意深度的子孙取用不用一层层传
#  ---- 祖先组件 ----
import { provide, ref } from 'vue'
#  provide = 提供／供应；inject = 注入／接收
const theme = ref('dark')
provide('theme', theme)
#  第 1 个参数 = 钥匙（字符串）；第 2 个 = 要共享的数据（传 ref 才保持响应式）

#  ---- 任意深度的后代组件 ----
import { inject } from 'vue'
const theme = inject('theme', 'light')
#  用同一把钥匙取；第 2 个参数是找不到时的默认值
类比

props 像一层层往下传纸条，隔五层就得传五次；provide/inject 像在公告栏贴一张纸，下面所有层自己来看；Pinia 像公司共用的一张总表，谁都能改、改动全员可见（第 21 章）。

11.5 父要主动调用子：defineExpose + 模板引用

子组件暴露方法 · 父组件调用Vue 3.5 新写法
#  ---- 子组件 ----
function reset() { count.value = 0 }
defineExpose({ reset })
#  defineExpose = 暴露；<script setup> 默认对外全封闭，写了它父组件才够得着

#  ---- 父组件 ----
import { useTemplateRef } from 'vue'
#  useTemplateRef = 3.5 新增：拿到模板里那个组件实例（老写法是 const child = ref(null)）
const child = useTemplateRef('child')
function doReset() { child.value.reset() }
#  child.value = 子组件实例；.reset() = 调它暴露出来的方法

<Child ref="child" />
#  ref="child" = 模板里打个标记；字符串要和 useTemplateRef 里写的一致
关系用什么一句话
父 → 子defineProps传数据，只读；变量要加 :
子 → 父defineEmits + @事件子喊一声，父决定怎么改
父子双向defineModel一行顶替 props + emit
隔了很多层provide / inject公告栏贴纸，谁用谁取
兄弟 / 全站共用Pinia（第 21 章）共用总表，别硬传
父调子的方法defineExpose + useTemplateRef能不用就不用，优先 emit
归纳 · 本章

① 数据往下、事件往上，子组件永远别直接改 props。
② 四种方式按「关系」选，不要一律用 props 硬传。
③ 最常忘的是冒号和 <script setup> 里组件不用注册这两件事。

12插槽与组件进阶

把组件做得更灵活，再补上课程里那几个「听起来高级、其实很直白」的功能。

一句话记住：props 传数据，slot 传一整块页面内容；其余进阶功能都是「特殊场景的开关」。

12.1 插槽：给组件留个空位

子组件 Card.vue · 留空位默认 / 具名 / 作用域
<template>
  <div class="card">
    <header>
      <slot name="title">默认标题</slot>
#  slot = 插槽／空位；name="title" = 给空位起名（具名插槽）
#  标签中间的文字 = 父组件没塞内容时的兜底内容
    </header>
    <main><slot></slot></main>
#  没写 name 的就是默认插槽，父组件写的内容默认全进这里
    <footer><slot name="foot" :list="items"></slot></footer>
#  :list="items" = 把子组件的数据传给插槽 → 这叫「作用域插槽」
  </div>
</template>
父组件 · 往空位里塞内容# 是 v-slot: 的简写
<Card>
  <template #title><h2>订单详情</h2></template>
#  #title = v-slot:title 简写；把这段 HTML 塞进 name="title" 的空位

  <p>这里是正文，会自动进默认插槽</p>
#  不在 template 里的内容，统统进没有名字的那个 slot

  <template #foot="{ list }">
#  { list } = 解构取出子组件通过 :list 传来的数据
    <small>共 {{ list.length }} 条</small>
  </template>
</Card>
类比

组件是带空格的表格模板：props 是「往格子里填数字」，slot 是「这一格干脆让你自己贴一整张图」。作用域插槽则是：模板顺便把「共几条」这个数递给你，你怎么排版自己定。

12.2 属性透传：多写的属性去哪了

父组件写 <MyButton class="big" data-x="1" @click="fn" />，但子组件没声明这些 props —— Vue 会把它们自动贴到子组件的根元素上，这叫 fallthrough attributes（透传）。

不想让它自动贴 / 想手动贴3 个开关
#  ① 关掉自动透传（在子组件另开一个普通 script 块）
<script>
export default { inheritAttrs: false }
#  export default = 默认导出配置对象；inherit = 继承；Attrs = attributes 属性
#  false = 别自动往根元素贴，我自己决定贴哪
</script>

#  ② 在模板里手动贴到指定元素
<button v-bind="$attrs">...</button>
#  $attrs = Vue 内置变量，装着所有没被 props 认领的属性和事件

#  ③ 在 script setup 里拿（Vue 3.3+）
import { useAttrs } from 'vue'
const attrs = useAttrs()
#  useAttrs = 使用属性；等价于模板里的 $attrs，但不是响应式的
多根节点要注意

子组件模板如果有两个平级根元素（Vue 3 允许），Vue 不知道 class 该贴哪个，会警告 Extraneous non-props attributes。解决：显式写 v-bind="$attrs" 到你想贴的那个元素上。

12.3 动态组件与 KeepAlive

Tab 切换 · 别把组件销毁又重建逐词注释
<script setup>
import { ref, shallowRef, markRaw } from 'vue'
import A from './A.vue'
import B from './B.vue'
const cur = shallowRef(markRaw(A))
#  shallowRef = 浅层响应式；markRaw = 标记为「别代理我」
#  组件对象不是数据，包成响应式会白白浪费性能，所以这两个常一起用
</script>

<template>
  <button @click="cur = A">A 页</button>
  <KeepAlive :max="3">
#  KeepAlive = 保持存活；切走的组件被缓存而不是销毁，回来时输入内容还在
#  :max="3" = 最多缓存 3 个；还可写 include="A,B" / exclude="C"
    <component :is="cur" />
#  component = Vue 内置的特殊标签；:is = 「现在到底渲染哪个组件」
  </KeepAlive>
</template>
被缓存时的两个钩子

组件被 KeepAlive 切走 / 切回时，不会触发 onUnmounted / onMounted，而是 onDeactivated() / onActivated()。想「每次切回来刷新数据」就写在这两个钩子里。

12.4 Teleport：把弹窗挪到 body 下

模态框不被父元素的 overflow / z-index 困住一行
<Teleport to="body">
#  Teleport = 瞬移；to = 目标；整句＝把里面这段 DOM 渲染到 body 末尾
  <div v-if="show" class="modal">我是弹窗</div>
</Teleport>
#  注意：只是 DOM 位置变了，组件逻辑、props、provide 关系完全不变

12.5 自定义指令：给 DOM 加个动作

src/main.js · 自动聚焦的 v-focus全局指令
const app = createApp(App)
app.directive('focus', {
#  directive = 指令；'focus' = 名字（用的时候写 v-focus）；{ } = 钩子集合
  mounted(el) { el.focus() }
#  mounted = 元素挂载后触发；el = element 那个真实 DOM 元素；focus() = 聚焦
})
app.mount('#app')
#  注意：创建了 app 变量后再 mount，别写成两行 createApp
局部指令（只在这个组件里能用）script setup 写法
const vFocus = { mounted: (el) => el.focus() }
#  命名规则：v + 大写字母开头 = 局部指令；vFocus 自动对应模板里的 v-focus
<input v-focus />
指令钩子什么时候触发
created元素属性刚创建，还没插进页面
mounted元素插进页面后（最常用：聚焦、初始化第三方库）
updated所在组件更新后
unmounted元素被移除（清理定时器、解绑事件）

12.6 异步组件与 Suspense

大组件等用到时再下载减小首屏体积
import { defineAsyncComponent } from 'vue'
#  define = 定义；Async = asynchronous 异步；Component = 组件
const Chart = defineAsyncComponent(() => import('./Chart.vue'))
#  () => import(...) = 用到 Chart 时才去下载这个文件的代码

<Suspense>
#  Suspense = 悬念／等待；等异步内容就绪前显示 fallback 兜底
  <template #default><Chart /></template>
  <template #fallback>加载中...</template>
#  fallback = 退路／兜底内容
</Suspense>
别急着用

路由懒加载（第 20 章）已经解决了大部分体积问题。Suspense 在 2026 年仍是实验性特性，入门项目不用碰，认识即可。

归纳 · 本章

① slot 传内容、props 传数据；#名字 是 v-slot:名字 简写。
② 没声明的属性自动贴根元素，用 inheritAttrs:false + $attrs 接管。
③ 切 Tab 想保住输入内容 → KeepAlive；弹窗被裁切 → Teleport；要操作真实 DOM → 自定义指令。

14.1 两种 API，一件事

选项式 API（Options API）· 老项目里会见到只需看懂
<script>

#  export default = 默认导出一个配置对象；default = 默认
  data() { return { count: 0 } },
#  data = 数据；必须 return 一个对象；count = 数据名
  methods: { add() { this.count++ } },
#  methods = 方法集合；this = 当前组件实例；count++ = 加 1
  computed: { double() { return this.count * 2 } },
#  computed = 计算属性；double = 名字；返回 count 的两倍
  mounted() { console.log('就绪') }
#  mounted = 挂载完成这个时机
}
</script>
组合式 API + 语法糖 · 本教程全程用这个功能完全一样

#  import = 用哪个函数就导入哪个；不用 import 一整个 Vue
const count = ref(0)

#  () => 箭头函数；这里没有 this，直接改变量

</script>

选项式像按抽屉分类的柜子：所有袜子一个抽屉、所有帽子一个抽屉，找一套搭配要拉开好几个。组合式像按场合分好的收纳盒：「运动」那一盒里袜子帽子全齐。功能少时没差别，功能一多，后者好找得多。

没有语法糖时，原本要写这么多认识即可，别抄

15ref 与 reactive

课程用三节课讲的响应式数据，压缩成一页：两种盒子 + 一条选型规则。

一句话记住：拿不准就用 ref；它什么都能装，只是 JS 里读写要加 .value。

15.1 ref：装任何数据的盒子

src/App.vue · ref 基本用法逐词注释
<script setup>
import { ref } from 'vue'
#  ref = reference 引用；把普通值装进一个「会被盯着」的盒子
const count = ref(0)
const name = ref('小明')
const user = ref({ age: 18 })
#  数字、字符串、对象、数组都能装；对象内部也会被自动代理成响应式

function change() {
  count.value++
#  ★ JS 里读写 ref 必须 .value；value = 值
  user.value.age = 20
#  .value 拿到对象后再 .age；两层不要写成 user.age
}
</script>

<template>
  <p>{{ count }} / {{ name }} / {{ user.age }}</p>
#  ★ 模板里自动解包，不用写 .value；写了反而取不到值
  <button @click="count++">+1</button>
#  模板里直接 count++ 也行，Vue 自动帮你补 .value
</template>
为什么要有 .value（人话版）

JS 里一个普通数字 0 没法被「盯住」—— 它被复制走之后，Vue 就找不到了。所以 Vue 给你一个盒子对象，数字放在盒子的 .value 里；盒子本身不变，Vue 只要盯着盒子就行。模板里 Vue 会自动开盒，所以看不到 .value。

15.2 reactive：只装对象的另一种盒子

reactive 基本用法对比 ref
import { reactive } from 'vue'
#  reactive = 反应式的；把「对象」整个变成响应式代理
const state = reactive({ count: 0, user: { name: '小明' } })
#  ★ 只能传对象 / 数组 / Map / Set，传数字字符串会警告且不生效

state.count++
state.user.name = '小红'
#  ★ 不用 .value，像普通对象一样直接改（这是它唯一的好处）
state.list.push('新项')
#  数组方法也能直接触发更新

15.3 reactive 的三个局限（课程专门用一节课讲）

局限会怎样怎么绕开
① 只能装对象reactive(0) 无效基本类型用 ref
② 解构会丢响应式const { count } = state 之后改 count，页面不动用 toRefs(state)（第 16 章），或干脆别解构
③ 整个替换会断state = { count: 1 } 直接报错（const 不能重赋值）；就算用 let，页面也不再跟着变换成 ref，写 data.value = {...}；或 Object.assign(state, 新对象)
② 和 ③ 的真实代码看懂就避开坑
let state = reactive({ count: 0 })
const { count } = state
#  ❌ count 现在是普通数字 0 的拷贝，和 state 再无关系
count++
#  页面不动（而且严格模式下这行本身会报错）

state = reactive({ count: 9 })
#  ❌ 换了个新代理，但模板还盯着旧代理 → 页面不动

const data = ref({ count: 0 })
data.value = { count: 9 }
#  ✅ ref 整个替换没问题：盒子没换，只是盒子里的值换了

15.4 底层一句话：Proxy 是什么

Vue 3 用 JS 内置的 Proxy（代理）包住你的对象。你可以把它想成给对象装了个门卫：谁读了（get）就记下「谁在用」，谁改了（set）就喊一声「变啦，快更新」。

示意代码（不用写进项目）理解原理
const raw = { count: 0 }
const state = new Proxy(raw, {
#  new = 创建；Proxy = 代理；raw = 原始对象；{ } = 门卫规则
  get(target, key) { return target[key] },
#  get = 有人读属性时；target = 原对象；key = 属性名
  set(target, key, value) { target[key] = value; 更新页面(); return true }
#  set = 有人改属性时；value = 新值；改完顺手通知页面
#  target[key] = 原对象「的」这个属性（[ ] 中括号＝按键名取值）；return true = 告诉代理「改好了」
#  get / set 后面跟 (参数) { } ＝ 这也是函数，只是名字写在对象里，叫「方法」
})
类比收口

ref 是带感应器的保险箱（什么都能放，取放要开箱 = .value）；reactive 是装了摄像头的房间（只能放「一堆东西」，进出随意但不能把整个房间搬走）。两者都是为了实现第 1 章那件事：改动被门卫看见 → 自动重算公式格。

归纳 · 本章

① 拿不准全用 ref；script 里 .value，template 里不写。
② reactive 只装对象、免 .value，但不能解构、不能整个替换。
③ 底层是 Proxy 门卫：读时记依赖，写时通知页面。

16.1 第一组：判断与拆包（isRef / unref / toRef / toRefs）

四个小工具逐词注释
import { ref, reactive, isRef, unref, toRef, toRefs } from 'vue'
#  is = 是……吗；un = 去除；to = 转换成

const a = ref(1)
isRef(a)
#  isRef = 是不是 ref 盒子？返回 true / false（布尔值）
unref(a)
#  unref = 如果是 ref 就返回 .value，不是就原样返回；等价于 isRef(x) ? x.value : x

const state = reactive({ name: '小明', age: 18 })
const nameRef = toRef(state, 'name')
#  toRef = 把对象的「某一个属性」变成 ref，且和原对象保持联动
#  改 nameRef.value，state.name 跟着变，页面也更新
const { name, age } = toRefs(state)

16.2 第二组：只要表层（shallow / triggerRef）

浅层响应式逐词注释
import { shallowRef, shallowReactive, triggerRef } from 'vue'
#  shallow = 浅的；只盯最外面一层，里面不管（数据很大时省性能）

const big = shallowRef({ list: [1, 2] })
big.value.list.push(3)
#  ❌ 改里面：页面不动，因为只有 .value 本身被盯着
big.value = { list: [1, 2, 3] }
#  ✅ 整个替换 .value：页面更新
triggerRef(big)
#  trigger = 触发；手动喊一声「我改过了，快更新」，专门配 shallowRef 用

const obj = shallowReactive({ a: 1, nested: { b: 2 } })
obj.a++
#  ✅ 第一层属性会触发更新
obj.nested.b++
#  ❌ 嵌套对象内部不会触发更新
类比

普通 ref 是每个房间都装摄像头；shallowRef 是只在大门装一个：屋里怎么挪摄像头看不见，除非你换整栋楼（替换 .value）或手动按警铃（triggerRef）。数据几万条、又只整体替换时，这样能省很多开销。

16.3 第三组：只读与还原（readonly / toRaw / markRaw / isProxy）

保护数据 / 拿回原始对象逐词注释
import { reactive, readonly, shallowReadonly, toRaw, markRaw, isProxy } from 'vue'
#  readonly = read only 只读；toRaw = 还原成原始；markRaw = 标记为原始
#  isProxy = 是不是代理对象；proxy = 代理

const src = reactive({ n: 1, inner: { m: 2 } })

#  ❌ 控制台警告：Set operation on key "n" failed: target is readonly（目标是只读的）
#  但改 src.n 仍然会更新 ro.n —— 只读是「这一层入口」不许写，不是复制一份

#  toRaw = 拿回被代理前的原始对象；改 raw 不会触发页面更新（门卫被绕过了）
#  典型用途：把数据交给第三方库（图表、地图），不希望它被 Vue 代理

#  markRaw = 给对象盖个章「永远别代理我」；之后塞进 reactive 也保持原样

16.4 第四组：自己造一个 ref（customRef）

防抖搜索框 · 停手 300ms 才更新课程 49 课时
import { customRef } from 'vue'
#  custom = 自定义；customRef = 自己控制「什么时候读、什么时候通知」
function useDebouncedRef(value, delay = 300) {
#  use 开头 = 组合式函数的命名习惯；delay = 延迟毫秒数，默认 300
  let timer
#  let = 可重新赋值的变量；timer = 装定时器编号
  return customRef((track, trigger) => {
#  track = 追踪，读的时候调用它「记下依赖」
#  trigger = 触发，改的时候调用它「通知页面」
    return {
      get() { track(); return value },
#  get = 有人读这个 ref 时；先记依赖，再返回当前值
      set(newVal) {
#  set = 有人赋值时；newVal = 新值
        clearTimeout(timer)
#  clearTimeout = 取消上一个定时器（防抖关键：连续输入只算最后一次）
        timer = setTimeout(() => { value = newVal; trigger() }, delay)
#  setTimeout = 延迟执行；delay 毫秒后才真正改值并通知页面
      }
    }
  })
}

function clear() { model.value = ''; emit('clear') }
defineExpose({ clear })
#  允许父组件通过 ref 主动调用 clear()
</script>

<template>
  <label>{{ label }}
    <input v-model="model" :maxlength="props.max" />
#  maxlength = 最多输入几个字符；props.max = 取 props 里的 max
  </label>
  <button @click="clear">清空</button>
</template>
三个规矩

① 编译宏只能在 <script setup> 顶层调用，不能放进 if、函数里。
② 不能 import，也不要试图把它们存进变量再调。
③ useAttrs / useSlots 带 use 开头，是普通函数，必须 import，别和宏搞混。

17.2 组合式函数：把逻辑装进一个函数

课程 47、48 两节课做的事，用一句话说就是：把 <script setup> 里那几行复制到一个 useXxx.js 文件里，然后 return 出来。就这么简单。

src/composables/useCounter.js · 新建文件逐词注释
import { ref, computed, onUnmounted } from 'vue'
#  composables 目录 = 放组合式函数的约定文件夹，名字可以自己起

export function useCounter(start = 0) {
#  export = 导出（别的文件才能 import）；function = 函数
#  useCounter = 组合式函数命名约定：use + 功能名；start = 起始值，默认 0
  const count = ref(start)
  const double = computed(() => count.value * 2)
  function add(n = 1) { count.value += n }
#  n = 每次加多少，默认 1；+= = 加等于
  return { count, double, add }
#  ★ 把外面要用的都 return 出去；不 return 就等于私有
}
任意组件里用两行
<script setup>
import { useCounter } from './composables/useCounter.js'
const { count, double, add } = useCounter(10)
#  { } = 解构，把函数返回的三样东西分别取出来；10 = 从 10 开始数
#  每个组件调用一次 → 各自一份独立数据，互不干扰
</script>
<template>
  <button @click="add()">{{ count }} 的两倍是 {{ double }}</button>
</template>
类比

组合式函数像一张可以复印的表格模板：模板里写好公式和按钮（count / double / add），每个组件复印一份，各自填各自的数。Pinia 则是全公司只有一张、大家共用（第 21 章）—— 这就是两者的分界线。

三条约定（照着做就不会乱）

① 函数名以 use 开头：useMouse、useFetch、useChart。
② 在 setup 顶层同步调用（不要在 onMounted 里调，因为要注册生命周期钩子）。
③ 返回 ref 组成的对象，别返回普通值，否则解构会丢响应式（第 15.3 节）。

再给一个真正常用的：跟着鼠标走含清理
import { ref, onMounted, onUnmounted } from 'vue'
export function useMouse() {
  const x = ref(0), y = ref(0)
#  x / y = 鼠标横纵坐标；一行声明两个变量用逗号隔开
  function update(e) { x.value = e.clientX; y.value = e.clientY }
#  e = event 事件对象；clientX / clientY = 鼠标在窗口里的坐标
  onMounted(() => window.addEventListener('mousemove', update))
#  window = 浏览器窗口对象；. 读作「的」；addEventListener = add 添加 + Event 事件 + Listener 监听器
#  'mousemove' = 鼠标移动这个事件名；update = 事件发生时执行的函数（自己定义的）
  onUnmounted(() => window.removeEventListener('mousemove', update))
#  ★ removeEventListener = 移除监听；不写这行，组件没了监听还在 → 内存泄漏
  return { x, y }
}
别重复造轮子

2026 年现成的组合式函数库 VueUse（第 22 章）里已经有 useMouse、useLocalStorage、useDebounce 等上百个。先去查有没有，再自己写。这里手写一遍是为了让你看懂原理。

归纳 · 本章

① defineProps / defineEmits / defineModel / defineExpose / defineOptions 五个宏覆盖 95% 的组件接口。
② 组合式函数 = 把 setup 里的逻辑搬进 useXxx() 并 return，用来复用逻辑。
③ 复用「逻辑」用组合式函数，复用「一份共享数据」用 Pinia —— 分清楚这一条就够了。

TS 最小够用对照 JS 看

19.2 二次封装：只写一次基础地址和报错

src/utils/request.js · 新建项目里所有请求都走它
import axios from 'axios'

const request = axios.create({
#  create = 创建一个「定制版 axios 实例」，不影响全局 axios
  baseURL: import.meta.env.VITE_API_BASE,
#  baseURL = 基础地址；以后写 '/users' 就会拼成 'http://.../users'
  timeout: 10000
#  timeout = 超时毫秒数；10 秒还没响应就报错，别让用户一直等
})

request.interceptors.request.use(config => {
#  interceptors = 拦截器；request = 请求发出前；use = 注册一个处理函数
#  config = 这次请求的配置对象
  const token = localStorage.getItem('token')
#  localStorage = 浏览器本地存储；getItem = 按键名取值
  if (token) config.headers.Authorization = `Bearer ${token}`
#  if = 如果；headers = 请求头；Authorization = 授权字段；Bearer = 令牌类型约定
  return config
#  ★ 拦截器最后必须 return config，否则请求发不出去
})

request.interceptors.response.use(
  res => res.data,
#  成功时：直接把 res.data 返回，业务代码里就不用层层 .data 了
  err => {
#  err = error 错误对象；失败时统一处理
    console.error('请求失败', err.response?.status)
#  ?. = 可选链：response 可能不存在，写了不会崩
    return Promise.reject(err)
#  Promise.reject = 把错误继续抛出去，让调用它的地方能 catch
  }
)
export default request
#  export default = 默认导出；别处 import request from '@/utils/request.js'
使用：一行搞定业务代码变干净了
import request from '@/utils/request.js'
const users = await request.get('/users')
#  已经是接口返回的 data，不用再 .data
await request.post('/login', { name, pwd })
#  post = 提交数据；第 2 个参数是请求体（body）

19.3 跨域：为什么本地请求会红

浏览器有条规矩叫同源策略：网页在 http://localhost:5173，却去请求 http://localhost:8080，端口不同就算「外人」，默认拦下，控制台报 CORS。

vite.config.js · 加一段 server.proxy改完重启 dev
export default defineConfig({
  server: {
    proxy: {
#  proxy = 代理／代转
      '/api': {
#  以 /api 开头的请求都走这条规则
        target: 'http://localhost:8080',
#  target = 目标服务器（后端地址）
        changeOrigin: true,
#  changeOrigin = 改请求头里的来源，后端常要求这个
        rewrite: p => p.replace(/^\/api/, '')
#  rewrite = 改写路径；把 /api/users 变成 /users 再转给后端
#  p = path 路径；replace = 替换；/^\/api/ 是正则，匹配开头的 /api
      }
    }
  }
})
检查点

前端写 request.get('/api/users')，浏览器 Network（网络）面板里看到的是 http://localhost:5173/api/users，状态码 200、有数据 → 代理成功。上线后 /api 要由 nginx 转发（第 25 章）。

20.4 导航守卫：进页面之前先检查

src/router/index.js · 全局前置守卫登录拦截就靠它
router.beforeEach((to, from, next) => {
#  beforeEach = before（之前）+ each（每一次）＝ 每次跳转前都执行
#  to = 要去哪条路由；from = 从哪来；next = 放行的函数
  document.title = to.meta.title || '我的网站'
#  顺手改浏览器标签标题；|| = 或者（没设 title 就用默认）
  const token = localStorage.getItem('token')
  if (to.meta.requiresAuth && !token) {
#  && = 并且；! = 取反（没有 token）；requiresAuth = 路由 meta 里标的「需登录」
    return next({ path: '/login', query: { redirect: to.fullPath } })
#  next(路径) = 改道去登录页；query.redirect = 记下原本想去哪，登录后跳回去
  }
  next()
#  ★ 别忘了放行；不写 next() 也不 return，页面会永远卡住不动
})
守卫什么时候写在哪
router.beforeEach ★任何跳转之前router/index.js（权限、标题、进度条）
router.beforeResolve组件和异步数据都解析完、导航确认前router/index.js
router.afterEach跳转完成后（不能改道）router/index.js（埋点、关 loading）
beforeEnter进入某一条路由前路由表里那条规则
onBeforeRouteLeave离开当前组件前组件内（「有未保存内容，确定离开？」）
onBeforeRouteUpdate同一组件参数变了（/user/7 → /user/8）组件内（重新拉数据）
2026 年推荐写法：直接 return，不用 next

next 容易漏写。新写法可以只接 (to) 两个参数，返回 false 取消、返回路径对象改道、什么都不返回就放行：router.beforeEach(to => { if (需要登录 && 没令牌) return { path:'/login' } })。两种写法都对，本教程实战用 return 版。

21Pinia 全解

课程 83–91 九节课，讲的是同一件事：全站共用的那一份数据放哪。

一句话记住：组件自己的数据放 ref，很多页面都要用、都要改的数据放 Pinia 的 store。
类比收口（还是那张 Excel）

每个组件的小 ref 是自己电脑里的一份表；Pinia 的 store 是公司服务器上唯一的一张总表：谁改了，所有人屏幕上立刻同步。购物车、登录用户、侧边菜单、主题 —— 都是典型的总表数据。

▶ 可以点一下：两个「页面」共用同一份数据 交互演示
页面 A（Header.vue）
购物车：0
页面 B（Cart.vue）
购物车：0
不用 props 一层层传、不用 emit 一层层喊 —— 两边都读同一个 store，天然同步。这就是 Pinia 存在的唯一理由。

21.1 装与建

终端2026 年版本 4.1.0（只支持 ESM，需 Node 22+）
$ npm install pinia
#  pinia = 官方状态管理库；Vuex 已停止新功能开发，2026 年新项目一律用 Pinia
src/main.js · 装插件一行
import { createPinia } from 'pinia'
#  createPinia = 创建 Pinia 实例（和 createApp / createRouter 一个命名套路）
createApp(App).use(createPinia()).use(router).mount('#app')
#  .use() 可以连写；注意都在 .mount() 之前
src/stores/cart.js · 定义一个 store组合式写法（推荐）
import { defineStore } from 'pinia'
#  defineStore = define（定义）+ Store（仓库）；一个 store 就是一个「总表」
import { ref, computed } from 'vue'

export const useCartStore = defineStore('cart', () => {
#  export const = 导出常量；useCartStore = 命名约定 use + 名字 + Store
#  第 1 个参数 'cart' = store 的唯一 id（调试工具里显示的名字，不能重复）
#  第 2 个参数 = 一个函数，里面写法和 <script setup> 完全一样
  const items = ref([])
#  state（状态）＝ 数据：购物车里的商品数组
  const total = computed(() => items.value.reduce((s, i) => s + i.price * i.qty, 0))
#  getters（计算）＝ 由数据算出来的值；reduce = 累加求和
  function add(goods) { items.value.push(goods) }
#  actions（动作）＝ 改数据的函数；push = 末尾加一项
  function remove(id) { items.value = items.value.filter(i => i.id !== id) }
#  filter = 过滤；★ 返回新数组要赋值回 items.value（第 7.3 节）
  return { items, total, add, remove }
#  ★ 想让外面用的，都要 return 出去（和组合式函数一个规矩）
})

21.2 组件里怎么用（四种常见操作）

任意 .vue 组件逐词注释
<script setup>
import { useCartStore } from '@/stores/cart.js'
import { storeToRefs } from 'pinia'
#  storeToRefs = store 转 refs；只把「数据」转成 ref，函数保持原样

const cart = useCartStore()
#  ★ 拿到 store 实例；全应用共享同一个，任意组件调用拿到的是同一份
const { items, total } = storeToRefs(cart)
#  ★ 直接 const { items } = cart 会丢响应式（第 15.3 节），必须包一层
#  解构之后 JS 里用 items.value，模板里直接 items

cart.add({ id: 1, price: 12, qty: 2 })
#  调 action 改数据；函数不用 storeToRefs，直接从 cart 上取
cart.$patch({ items: [] })
#  $patch = patch 打补丁：一次改多个字段，只触发一次更新
cart.$patch(state => { state.items.push({ id: 2, price: 8, qty: 1 }) })
#  传函数版适合改数组；state = store 里的状态对象
cart.$reset()
#  $reset = 重置回初始值；★ 组合式 store 需要自己写 $reset，见下方提示
cart.$subscribe((mutation, state) => {
#  $subscribe = 订阅：数据一变就回调；mutation = 变更信息，state = 最新状态
  localStorage.setItem('cart', JSON.stringify(state.items))
#  JSON.stringify = 把对象转成字符串，才能存进 localStorage
})
</script>
<template>
  <p>共 {{ items.length }} 件，合计 ¥{{ total }}</p>
#  模板里直接写名字，不用 .value，和 ref 一样
</template>
组合式 store 的 $reset 要自己写

选项式 store 自带 $reset()；组合式写法（我们用的这种）默认没有。两种办法：
① 自己定义一个 function $reset() { items.value = [] } 并 return 出去；
② 用现成插件 npm i pinia-plugin-persistedstate，顺便把「刷新后数据不丢」也解决了 —— 课程项目实战里购物车、页签导航都靠它。

21.3 另一种写法：选项式 store（看懂即可）

src/stores/user.js · 老教程 / 课程里常见对照看

})

按业务拆，不要全塞一个 store目录示例

什么时候不该用 Pinia

22.4 部署：静态托管 + nginx 解决刷新 404

History 模式下，浏览器刷新 /user/7 时，服务器会傻乎乎地去找 user/7 这个文件，找不到就 404。解决办法：找不到的统统返回 index.html，让前端路由自己判断。

/etc/nginx/conf.d/vue-app.conf（片段）逐词注释
server {
    listen       80;
#  listen = 监听端口；80 = HTTP 默认端口
    server_name  example.com;
#  server_name = 你的域名
    root         /usr/share/nginx/html;
#  root = dist 目录上传后放的位置（把 dist 里的文件拷到这儿）

    location /api/ {
#  location = 匹配网址前缀；/api/ 开头的请求转给后端
        proxy_pass http://127.0.0.1:8080/;
#  proxy_pass = 转发到哪；末尾的 / 会把 /api 前缀去掉
    }

    location / {
        try_files $uri $uri/ /index.html;
#  ★ try_files = 依次尝试：先找这个文件、再找这个目录、都没有就返回 index.html
#  $uri = 用户请求的路径；这一行就是「刷新不 404」的关键
    }
}

  onMounted(() => {
    chart = echarts.init(el.value)
#  init = initialize 初始化；把 div 变成一张画布
    chart.setOption(option.value ?? option)
#  setOption = 设置配置项（真正画出图）；?? = 前面是 undefined 就用后面
    window.addEventListener('resize', resize)
#  监听浏览器窗口大小变化
  })

  onUnmounted(() => {
    window.removeEventListener('resize', resize)
#  ★ 移除监听；不写会内存泄漏
    chart && chart.dispose()
#  dispose = 销毁图表实例；切走页面必须清掉，否则反复进出会越来越卡
  })

  if (option && option.value !== undefined) {
    watch(option, (o) => { chart && chart.setOption(o, true) }, { deep: true })
#  ★ 数据异步回来后 option 变了 → 自动重画；true = 不合并、整份替换
  }

  return { el }
}
课程里踩过的坑：图表实例别放进 ref

ECharts 实例是个「带大量内部方法的重型对象」，被 Vue 的 Proxy 包住后容易出各种怪问题（Cannot read properties of undefined、tooltip 错乱）。用普通 let chart = null 存，或用第 16 章的 markRaw() 盖个章。

1灰框里绿色 # 开头的行要敲吗？不要。只敲带蓝色 $ 的行，$ 本身也不用敲；注释里的 = 是「意思是」，不是命令语法。见开篇说明。
2.value 到底什么时候写？JS 里写、模板里不写。<script setup> 中改 ref 要 count.value++；<template> 里 {{ count }}、@click="count++" 由 Vue 自动解包。
3ref 和 reactive 选哪个？拿不准全用 ref：什么都能装、能整个替换，代价只是多写 .value。reactive 只装对象、免 .value，但不能解构、不能整个替换。见 15.4 图。
4v-if 和 v-show 怎么选？很少切换 / 初始多为假 → v-if（不生成元素）；频繁切换 → v-show（只切 CSS）。见 7.1 与可点演示。
5:key 为什么不能用 index？删中间一项后，下标会对不上人，Vue 会复用错行，导致输入框、勾选状态串位。用数据里唯一且稳定的 id。见 图 7-1。
6computed 和 watch 分不清？要「算出一个值显示在页面上」→ computed（有缓存）；要「顺手做件事」（发请求、存本地、打日志、比新旧值）→ watch。见 图 9-1。
7子组件能直接改 props 吗？不能。props 只读。想改就让子组件 emit('事件', 新值)，父组件决定怎么改；要双向就用 defineModel()。见 第 11 章。
8{{ }} 里能写 if / for 吗？不能，只接受一个表达式。判断用三元 a ? b : c 或 v-if；循环用 v-for；复杂计算用 computed。
9为什么传过去的 props 变成了字符串？忘了冒号。count="total" 传的是四个字母；变量、数字、布尔、对象、数组一律写 :count="total"。见 11.1。
10能在 <script setup> 顶层直接 await 吗？能但会变成异步组件，外层必须有 <Suspense>。零基础请放进 onMounted 或普通 async 函数里发请求。见 14.2、19.1。
11Pinia、组合式函数、provide/inject 怎么分？逻辑要复用、数据各自独立 → 组合式函数；隔了很多层只想读一份配置 → provide/inject；多个不相邻页面共用并修改同一份数据 → Pinia。见 17.2、21.4。
12打包上线后，刷新子页面就 404？服务器不认识前端路由。nginx 加 try_files $uri $uri/ /index.html;，或改用 createWebHashHistory()。见 22.4、25.4。
