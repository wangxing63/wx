1.1 你本来要写的代码

假设要往数据库里加一个用户、再把名字带「小」的人查出来。不用任何工具，你得自己拼 SQL 字符串：

不推荐：手写 SQL 字符串只是对比，别照抄
#  下面这段是「老办法」，只用来看问题出在哪
import sqlite3
#  import = 导入；sqlite3 = Python 自带的 SQLite 数据库驱动（驱动＝真正会跟数据库说话的零件）
conn = sqlite3.connect("demo.db")
#  conn = connection 连接；connect = 连上；"demo.db" = 数据库文件名；= 把右边的结果放进左边
cur = conn.cursor()
#  cur = cursor 游标，可以理解成「执行单据的那支笔」；. = 的；() = 调用，这里不传参数
cur.execute("INSERT INTO user (name) VALUES (?)", ("小明",))
#  execute = 执行；(?) = SQL 里留的空位；(  "小明", ) = 真正要填的值，逗号表示这是一个「元组」
conn.commit()
#  commit = 提交，让刚才的改动真正生效
cur.execute("SELECT id, name FROM user WHERE name LIKE '%小%'")
#  SELECT = 挑选；FROM = 从哪张表；WHERE = 条件；LIKE = 模糊匹配；% = 任意字符
print(cur.fetchall())
#  print = 打印到屏幕；fetchall = fetch 取回 + all 全部；结果是一堆元组 [(1, '小明')]

麻烦在哪？① SQL 要自己写对（换数据库语法还不一样）；② 查回来的是一堆没名字的元组，取第几列要数；③ 每次都要自己开连接、提交、关连接；④ 字符串一拼接就容易被注入。项目一大就乱了。

    session.add(User(name="小明"))
#  add = 加入购物车；User(...) = 造一个用户对象；缩进 4 格 = 这行属于 with 里面
    session.commit()
#  commit = 结算，一次把购物车里的改动写进库
    users = session.scalars(select(User).where(User.name.like("%小%"))).all()
#  select = 造查货单；where = 加条件；like = 模糊匹配；scalars = 只要第一列；all = 全拿回来
    print(users[0].name)
#  users[0] = 列表第 1 个；.name = 它的名字属性；有名字，不用数列号

你只写了「要什么」，没写「SQL 长什么样」。SQLAlchemy 负责把 Python 翻成 SQL、发给数据库、再把结果变成有名字的对象。

打个比方（全书只用这一个）

把数据库想成「一个网上仓库」：一张表＝一排货架，一行＝一件货，主键＝货号。SQL 是仓库内部专用的单据语言，写得慢还容易写错。
SQLAlchemy 就是仓库管理员：你用 Python 说「我要存一件叫小明的货」「把带小字的货找出来」，管理员替你填单、跑腿、把找来的货贴好标签（变成 user.name 这样有名字的对象）递回给你。
全书所有零件都挂在这套说法上，不会中途换比喻：Engine＝仓库门口的收发通道；Session＝购物车；add＝放进购物车；flush＝先把清单报给仓库备货；commit＝结算下单；rollback＝取消整单；模型类＝货品规格卡；Alembic＝改造货架的施工单。

4.4 flush 和 commit，差在哪

动作做了什么数据库变了吗还能反悔吗

session.rollback()整轮作废，购物车清空↩️ 回到这一轮开始前的样子—

#  server_default = 让「数据库服务器」自己填；func.now() = SQL 里的 now()/CURRENT_TIMESTAMP

class Base(DeclarativeBase):

class Book(Base):

    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str] = mapped_column(String(100), unique=True)
#  unique=True = 书名不许重复；重复插入会抛 IntegrityError
    stock: Mapped[int] = mapped_column(default=1)
#  default=1 = 不填就默认有 1 本
    loans: Mapped[list["Loan"]] = relationship(back_populates="book")
#  relationship = 关系；让 book.loans 直接拿到这本书的所有借阅记录
#  list["Loan"] = 一个「Loan 对象」列表；类名加引号是因为 Loan 定义在下面（前向引用）
#  back_populates="book" = 两边互相对应，改一边另一边也知道

    def __repr__(self) -> str:
        return f"《{self.title}》 库存 {self.stock}"

class Loan(Base):
    __tablename__ = "loan"
    id: Mapped[int] = mapped_column(primary_key=True)
    book_id: Mapped[int] = mapped_column(ForeignKey("book.id"))
#  ForeignKey("book.id") = 这一列的值必须来自 book 表的 id；"表名.列名" 是固定写法
    borrower: Mapped[str] = mapped_column(String(30))
    returned: Mapped[bool] = mapped_column(default=False)
#  returned = 是否已还；bool = 真假；False = 刚借出时还没还
    borrowed_at: Mapped[datetime] = mapped_column(server_default=func.now())
#  server_default = 让数据库自己填当前时间；func.now() = SQL 的 now()
    book: Mapped["Book"] = relationship(back_populates="loans")
#  反向关系：loan.book 能直接拿到那本书的对象，不用自己再查一次

    def __repr__(self) -> str:
        return f"{self.borrower} 借了《{self.book.title}》 已还={self.returned}"

def borrow(title, who):
    with SessionLocal() as s:
        book = s.scalars(select(Book).where(Book.title == title)).one_or_none()
#  one_or_none = 恰好一条或没有；找不到返回 None，不会抛异常
        if book is None or book.stock <= 0:
#  or = 或者；is None = 没这本书；<= 0 = 库存不够；两个条件满足任一个就执行下面
            print(f"② 借不了：{title} 没书了")
            return
#  return = 直接结束这个函数，后面的代码不再执行
        book.stock -= 1
#  -= = 减一再存回去，等价于 book.stock = book.stock - 1
        s.add(Loan(book_id=book.id, borrower=who))
#  加一条借阅记录；book_id 填刚才那本书的主键（外键）
        s.commit()
#  一次结算：UPDATE book 减库存 + INSERT loan 加记录，两句 SQL 一起成功或一起失败
        print(f"② {who} 借走《{title}》，剩 {book.stock} 本")

def give_back(who):

        loan = s.scalars(
            select(Loan).where(Loan.borrower == who, Loan.returned == False)
#  where 里写两个条件用逗号隔开，等价于 AND（并且）

        s.commit()

11.1 开轮的四种写法

文件：transaction.py对照用，推荐①和②
from sqlalchemy.orm import Session, sessionmaker

#  ① 最常用：with 自动开关购物车，transaction 边界靠 commit/rollback
with Session(engine) as s:
    s.add(User(name="小甲", age=20))
    s.commit()

#  ② 推荐：begin() 把事务也包进 with，退出自动提交，出错自动回滚
with Session(engine) as s:
    with s.begin():
#  begin = 开一轮事务；缩进里的改动在退出时自动 commit
        s.add(User(name="小乙", age=21))
#  这里不用写 commit；写反而会报「事务已经结束」

#  ③ 工厂：配置一次，到处造购物车
SessionFactory = sessionmaker(engine, expire_on_commit=False)
#  sessionmaker = session + maker；expire_on_commit=False = 提交后对象属性仍可直接读
with SessionFactory() as s:
    print(s.scalars(select(User)).all())

#  ④ 嵌套事务（SAVEPOINT）：里面那轮可以单独回滚，不影响外面
with Session(engine) as s:
    with s.begin_nested():
#  begin_nested = 开一个「存档点」（SQL 的 SAVEPOINT）
        s.add(User(name="试试看", age=1))
        s.flush()
    #  如果里面抛异常，只回滚这一小段，外面的改动还在
    s.commit()

14.2 完整可运行异步例子

文件：async_demo.py整段复制进文件
import asyncio
#  asyncio = asynchronous IO，Python 自带的异步调度器
from sqlalchemy import select
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, selectinload
from sqlalchemy.ext.asyncio import (create_async_engine, async_sessionmaker,
                                        AsyncSession, AsyncAttrs)
#  ext = extension 扩展；asyncio = 异步扩展包
#  create_async_engine = 造异步通道；async_sessionmaker = 异步购物车模子
#  AsyncSession = 异步购物车；AsyncAttrs = 让属性也能 await（可选）

class Base(AsyncAttrs, DeclarativeBase):
#  两个父类：AsyncAttrs 让属性可等待，DeclarativeBase 让它成为模型基类
    pass

class User(Base):
    __tablename__ = "user_account"
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str]

engine = create_async_engine("sqlite+aiosqlite:///async.db", echo=True)
#  连接串里多了 +aiosqlite：告诉它用「异步版 SQLite 驱动」；echo=True 打印 SQL
AsyncSessionLocal = async_sessionmaker(engine, expire_on_commit=False)
#  expire_on_commit=False = 提交后对象属性仍可直接读（异步里几乎必设，避免隐式 IO）

async def main():
#  async def = 定义一个「异步函数」；调用它不会立刻执行，要 await
    async with engine.begin() as conn:
#  async with = 异步版的 with，进入/退出都要等；engine.begin() = 开事务
        await conn.run_sync(Base.metadata.create_all)
#  await = 等这件慢事做完再往下；run_sync = 把「同步的 create_all」搬到异步连接上跑

    async with AsyncSessionLocal() as session:
        session.add_all([User(name="小明"), User(name="小红")])
        await session.commit()
#  注意：commit 是慢操作，前面必须 await；漏了 await 什么都不会写进库

    async with AsyncSessionLocal() as session:
        result = await session.execute(select(User).order_by(User.id))
#  execute = 执行查货单，返回 Result；异步里也要 await
        for u in result.scalars():
#  scalars() = 只取每行第一列（这里就是 User 对象）；这一步本身不再 await
            print(u.id, u.name)

    await engine.dispose()
#  dispose = 释放连接池；异步版也要 await

asyncio.run(main())
#  asyncio.run = 启动异步调度器并把 main() 跑完；普通同步函数里就这样「点火」
你会看到（程序自己的两行输出）
1 小明
2 小红
检查点：看到这两行＝异步全流程跑通。echo=True 打印的 SQL 和同步版完全一样，只是多了 await。

同步（前面章节）异步（本章）多的东西

14.4 异步常见报错急救

报错原因与修法

16.1 事件：每次执行 SQL 前后，插一句话

文件：events.py整段复制进文件
import time
from sqlalchemy import event
#  event = 事件；time = 计时用的标准库
from sqlalchemy.engine import Engine

@event.listens_for(Engine, "before_cursor_execute")
#  @ = 装饰器，贴在函数上面给它加一层能力
#  listens_for = listen 监听 + for 为了；第 1 个参数＝监听谁，第 2 个＝监听什么时刻
#  before_cursor_execute = before 在…之前 + cursor 游标 + execute 执行：SQL 发出去之前
def before(conn, cursor, statement, parameters, context, executemany):
#  这些参数由 SQLAlchemy 自动传进来：conn 连接、cursor 游标、statement SQL 文本
#  parameters 参数、context 上下文、executemany 是否批量
    conn.info["start"] = time.perf_counter()
#  conn.info = 连接上挂的一个字典，可以存自己的临时数据；perf_counter = 高精度计时

@event.listens_for(Engine, "after_cursor_execute")
def after(conn, cursor, statement, parameters, context, executemany):
    cost = time.perf_counter() - conn.info["start"]
#  cost = 耗时；现在时间 减 刚才记下的开始时间
    print(f"[SQL {cost*1000:.1f} ms] {statement[:80]}")
#  f"..." = 格式化字符串；{cost*1000:.1f} = 毫秒数保留 1 位小数；[:80] = SQL 只截前 80 字
事件名英文原意什么时候触发
before_cursor_execute / after_cursor_execute执行前 / 执行后每条 SQL；做耗时日志、审计
connectconnect 连接池里新建一条连接时；设 PRAGMA、时区
checkout / checkin借出 / 归还连接池借还时；查连接泄漏

最常见的连接泄漏

写了 session = Session(engine) 却没关，又放在循环里，几十轮之后池子被借空，报 TimeoutError: QueuePool limit of size 5 overflow 10 reached。解法只有一个：永远用 with Session(engine) as session:，让 Python 自动归还连接。

16.4 性能清单（照着从上往下查）

优先级检查项怎么做
①N+1 查询（最常见）开 echo=True 看是不是刷出一堆相似 SELECT；用 selectinload 合并（第 10 章）
②只查需要的列select(User.id, User.name) 而不是 select(User)（大表、宽表明显）
③批量写入session.execute(insert(User), [字典, 字典, ...]) 或 add_all；别在循环里逐条 commit
④分页用 limit/offset别 .all() 之后再在 Python 里切片；超大分页用 keyset pagination
⑤给常查的列建索引Index("ix_name", User.name)；外键列通常也该建
⑥流式读大结果session.scalars(stmt).yield_per(500) 或 stream_scalars，别一次全进内存
⑦关掉 echo 与过期上线 echo=False；读多写少可设 expire_on_commit=False 少一次查询
⑧利用编译缓存同一条 select() 结构复用；SQLAlchemy 会缓存编译结果，别每次用原始字符串拼
⑨别在事务里做慢事发邮件、调外部 API 放到 commit() 之后，缩短持锁时间

会用 echo=True 定位 N+1、会用 with 防连接泄漏、知道 pool_pre_ping 治断连，这章就够了。

#问题回答
1SQLAlchemy 是数据库吗？要装 MySQL 吗？不是，它是库（工具包）。 本教程全程用 SQLite，Python 自带，一个 .db 文件就是数据库，什么都不用额外装。第 5 章才讲怎么换成 PostgreSQL / MySQL
2我不会 SQL，能学吗？能。第 3 章的代码一行 SQL 都不用写。开 echo=True 后反过来「看它生成了什么 SQL」，是最轻松的 SQL 入门方式；第 12 章再正式认单词
3add() 之后为什么查不到 / 数据库文件没变？add 只放进购物车，没结算。 要 commit()（第 4、7 章）。另外别忘了文件可能在你没看的那个文件夹，用 pwd 确认
4flush() 和 commit() 到底差在哪？flush＝先发 SQL、还能 rollback；commit＝flush＋结算、别人也能看见、不能反悔。购物车比喻见第 4.4 节，可点动画在第 3 章
5改了模型类，为什么表没多一列？create_all() 只建不存在的表。练习期删掉 .db 重跑；正式项目必须用 Alembic（第 15 章）
6为什么 select() 写了却什么都没发生？它只是造单子。要交给 session.scalars(stmt).all() 或 execute(stmt) 才真的查（第 4、8 章）
7execute() 和 scalars() 用哪个？查单个 ORM 类用 scalars()（直接拿对象）；查多列或聚合用 execute()（拿 Row）。对照表见第 8.2 节
8echo=True 打印的 ? 是什么？绑定参数占位符。真正的值在下一行单独显示，值和 SQL 分开传才不会被注入（第 4.2、12.2 节）
9为什么我用了 and 就报错？SQLAlchemy 表达式要用 and_() / or_() 或 & / |，不能用 Python 的 and（第 8.1 节、18.3 节）
10主键 id 要自己填吗？不用。Mapped[int] + primary_key=True 时数据库自动编号；想提前拿到就先 flush()（第 7.1 节）
11Windows 上报 unable to open database file 或中文路径出错？路径问题，不是库的 bug。用正斜杠 "C:/data/demo.db" 或原始字符串 r"C:\data\demo.db"；连接串用四个斜杠＋绝对路径（第 5.1、18.4 节）
12我装的是 2.0.55 / 1.4，本教程还能用吗？2.0 几乎全能用（标 2.1 的少数 API 除外，第 19 章列了）；1.4 建议先升级，老写法对照见第 20 章。装指定版本：pip install SQLAlchemy==2.1.8
