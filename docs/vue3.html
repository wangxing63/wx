01

Vue 是什么：热身运动

用一个比喻搞懂「前端框架」到底解决什么问题

在写任何代码之前，先回答三个问题：前端开发在干嘛、为什么需要 Vue、Vue 到底怎么运作。这一章不讲技术，只讲比喻和直觉——它们是理解一切命令的地基。

1.1 前端开发：帮页面「变活」的手艺人

一个网页通常由三件事组成：

名字负责什么生活化类比
HTML页面的内容和结构（有哪些元素）毛坯房的砖墙和房间
CSS页面的外观和样式（颜色、大小、位置）房内的装修和家具摆放
JavaScript页面的行为（点击、计算、数据变化）房里的电路和水管，让它有生命

JavaScript 负责让网页"动起来"。但当你直接用原生的 JavaScript（jQuery、DOM 操作）控制页面，很快会发现：

  • 改数据很啰嗦——你改了一个数字，还得手动去页面上找到那个已经变化的文本节点，再手动更新它。
  • 数据和界面容易失同步——人一多、功能一多，常常出现"数据改了、页面没跟上"或"页面改了、数据没跟上"的 bug。
  • 代码难维护——到处是 document.querySelector 和事件监听，像一团乱麻。
类比想象你在老式钟表店里打工。每有一块表的时间变了，你都要亲手拆开机芯，把指针一个个拨到对的位置（手动更新界面）。表多、改动频繁时，你的手根本忙不过来，还容易拨错。这就是"纯 JavaScript 手动操作界面"的真实写照。

1.2 Vue 是干什么的：一个"自动对齐指针"的表盘

Vue（发音类似"view"）是一个 JavaScript 前端框架。它最核心的本事只有一个——让"数据"和"界面"始终保持同步：你只管把数据显示出来，并告诉它"这个数字变了"，剩下的页面对照更新它全自动完成。

来，直接看一个最直观的对比。同样是"一个数字，点击按钮让它加 1"：

方式 A · 原生 JavaScript（先手动找节点，再手动改）
let count = 0;                       // 声明一个数字变量，初始为 0
count = count + 1;                    // 数字 +1（注意：此时页面上的文字并不会变！）
// 麻烦来了：页面还是显示旧的 0，你得自己去"找到那个按钮旁边的小字"，手动改成 1：
document.getElementById('num').textContent = count;  // 手动更新界面，一处也没改好则漏
方式 B · Vue（只改数据，界面自动更新）
<template>                          // Vue 的"模板"，就是页面的 HTML 部分
  <p>{{ count }}</p>              // 把 count 的值"插"到这一行显示（{{ }} 是插值）
</template>

<script setup>                       // Vue 的"逻辑"部分（组合式 API，后文详解）
const count = ref(0)                  // 声明一个"响应式"数字，初始 0（ref 表示可被监听）
count.value++                         // 让它 +1。神奇的事发生了：
// 页面上的 {{ count }} 会自动变成 1，你什么都不用手动做！
</script>
类比如果说原生 JS 是「钟表店里用手拨指针」，那么 Vue 就是「一块电子表」——你只需要说"现在的时间变得了"，电子表的指针自己会转到正确位置。这个「自动对齐指针」的魔法，就叫响应式系统（Reactivity），是 Vue 的灵魂。

1.3 Vue 和 Vue3 里的常用称谓

学习 Vue 时你会在各种文章里看到这些词，先分清，避免迷茫：

术语一句话理解
Vue2 / Vue3Vue 的两个大版本。Vue3 是最新版，本教程只讲 Vue3。
选项式 APIVue2 时代的写法，把逻辑按「数据、方法、生命周期」等大堆在一起。
组合式 APIVue3 推荐的写法（script setup），按「功能」聚合逻辑，更灵活，本教程采用。
SFC 单文件组件把「模板 + 样式 + 逻辑」写在同一个 .vue 文件里，是 Vue 日常开发的标准构件。
CDN / 构建工具CDN 是「在网页里直接引一条链接就能用 Vue，零配置」；构建工具（如 Vite）是「正式项目的脚手架，功能更强」。两者都会在本教程覆盖。

02

创建第一个 Vue 应用

三条路线任选，零配置的 CDN 最适合新手起步

动手之前最怕"配环境"。好消息是：Vue3 给新手留了一条完全不配环境的路（CDN），一条正式项目的路（Vite）。这一章两种都讲，并手把手帮你做出第一个"Hello World"。

2.1 路线对比：你该走哪条？

路线配置难度适合场景本教程建议
CDN 直接引用近乎零配置学概念、写小 demo、快速试学习阶段的主力
Vite 工程化项目要装 Node.js，但一条命令搞定正式开发、多人协作、要热更新进阶与部署章节使用
技巧作为超级小白，先用 CDN 把概念一个个吃透，不要一上来就被「脚手架、包管理、构建」这些词吓到。等第 16 章再升级到 Vite 正式项目，你会毫无压力。

2.2 路线 A：用 CDN 秒开一个 Vue 应用（推荐新手）

CDN 的中文作用是「内容分发网络」，简单说就是别人把 Vue 的文件托管在服务器上，你引一条链接就能用。麻雀虽小五脏俱全，请按下面步骤操作：

  1. 新建一个 HTML 文件：在电脑上新建 first-vue.html（用记事本/VS Code 打开）。
  2. 引入 Vue：在 <head> 里加一条 <script> 标签，写上 CDN 的链接。
  3. 写一个挂载点：放一个 <div id="app">，Vue 会"接管"这个区域。
  4. 创建应用：在脚本里调用 createApp 创建 Vue 应用，并 mount 到挂载点上。
  5. 用浏览器打开：双击这个 HTML 文件，浏览器里就能看到效果。
first-vue.html · 用 CDN 创建的第一个 Vue 应用，每行都有注释
<!DOCTYPE html>                      // 声明这是 HTML5 文档
<html lang="zh-CN">                  // 语言设为简体中文
<head>
  <meta charset="UTF-8">            // 字符集 UTF-8，保证中文不乱码
  <title>我的第一个 Vue 应用</title>  // 浏览器标签页上显示的标题
  <!-- ↓ 用官方 CDN 引入 Vue3，global 是全局构建，可直接在浏览器里用 -->
  <script src="https://unpkg.com/vue@3/dist/vue.global.js"></script>
</head>
<body>
  <!-- ↓ 挂载点：下面这块区域交给 Vue 来"接管"和"控制"，id 是 app -->
  <div id="app">
    <!-- {{ }} 叫"插值"，作用是：把 Vue 里 count 变量的值，显示到这一行 -->
    <p>你点了 {{ count }} 次</p>
    <!-- @click 是 Vue 的"事件绑定"：用户点击按钮时，执行 increment 这个方法 -->
    <button @click="increment">点我加 1</button>
  </div>

  <script>
    // Vue 对象由刚才引入的 CDN 提供，Vue.createApp 用来"新建一个应用"
    const app = Vue.createApp({
      // setup 是"组合式 API"的入口，应用的逻辑都写在这里
      setup() {
        // ref() 声明一个"响应式数据"：count 初始值 0。它像一个"会通知别人的盒子"
        const count = Vue.ref(0)

        // 一个方法：让 count 增加 1。因为是响应式，界面会自动跟着变
        function increment() {
          count.value++   // 注意：ref 数据要用 .value 来读和改（盒子里的"东西"）
        }

        // 把 count 和 increment "交出去"，模板里才能用 {{ count }} 和 @click
        return { count, increment }
      }
    })

    // 把应用挂载到 id="app" 的 div 上，Vue 就正式接管这块区域了
    app.mount('#app')
  </script>
</body>
</html>

2.3 路线 B：用 Vite 创建工程化项目（正式开发）

当你的项目变大、组件变多，就会想用「正式的工程结构」：自动刷新、打包、管理依赖。Vite 是目前 Vue 官方推荐的构建工具，一条命令就能开一个新项目。先决条件：电脑上装好 Node.js（去 nodejs.org 装 LTS 版即可）。

  1. 打开终端：Windows 用 PowerShell / CMD，Mac / Linux 用终端。
  2. 执行创建命令：输入 npm create vue@latest，按提示给项目起名（如 my-app）。
  3. 进入项目并装依赖：cd my-app 再执行 npm install。
  4. 启动开发服务器：执行 npm run dev，终端会给出一个本地网址（如 http://localhost:5173），浏览器打开即可实时预览。
终端里的完整命令序列
npm create vue@latest      # 官方脚手架，按向导起名、勾选功能
# 提示 Project name: 时输入 my-app 回车；其余大部分一路回车用默认即可

cd my-app                  # 进入刚创建的项目文件夹
npm install                # 根据 package.json 安装所有依赖（第一次会稍慢）
npm run dev                # 启动开发服务器，浏览器打开 http://localhost:5173
技巧npm run dev 启动后，你改保存 .vue 文件，页面会瞬间自动刷新，这就是「热更新」（Hot Reload），开发体验极爽。

2.4 通用别人的代码：几个阅读约定

本教程之后大量使用「组合式 API 的简写」<script setup>，它是 Vue3 很受欢迎的写法，省去手动 return。看懂它很简单：

script setup · App.vue 的骨架
<script setup>                  // setup 是"魔法标签"：里面声明的东西，模板可直接用，不用 return
import { ref } from 'vue'       // 从 vue 包导入 ref 函数

</script>

<template>                       // 页面结构（HTML）
  <p>当前：{{ count }}</p>
</template>

<style scoped>                  // 样式，scoped 表示"只作用于本组件"，不污染外面
p { color: blue; }
</style>

03

模板语法：怎么写界面

插值、指令、绑定——让 HTML 拥有"会变"的能力

Vue 里写页面的那部分叫模板（Template）。它本质上还是 HTML，只是被 Vue 增加了几种"魔法"写法，让静态的 HTML 能显示数据、根据条件变化、响应点击。这一章把这些魔法逐一讲透。

3.1 插值：把数据"灌进"页面 {{ }}

最常见的一种魔法叫插值（Text Interpolation），用双花括号 {{ 表达式 }} 把 Vue 里的数据显示到页面上。花括号里的内容是一个合法的 JavaScript 表达式（能算出值的式子）。

插值示例
<script setup>
const user = { name: '小明', age: 18 }   // 一个对象数据
const hour = new Date().getHours()      // 当前小时数
</script>

<template>
  // 直接在文本里插入数据：
  <p>你好，{{ user.name }}！</p>      // 输出：你好，小明！

  // 支持任何能算出值的表达式（算术、三元、字符串拼接都可以）：
  <p>你今年 {{ user.age + 1 }} 岁（虚岁）</p>   // 19
  <p>{{ hour < 12 ? '上午' : '下午' }}好</p>    // 三元：判断是上午还是下午
  <p>{完整名字：'' }}</p>  // 字符串拼接
</template>
注意花括号里只能写表达式，不能写语句（比如 if、for、let 声明）。如果里面有太复杂的逻辑或副作用，别硬塞进模板，留到计算属性（第 5 章）里做。

3.2 v-bind：把数据绑到 HTML 属性上

插值只管"文本内容"。但像 href、src、class 这类属性（attribute）上的值，需要用 v-bind 指令来绑定。常用的简写是冒号 :。

v-bind 绑定属性的例子
<script setup>
const url = 'https://vuejs.org'            // 一个网址字符串
const isActive = true                      // 一个布尔值
const styleObj = { color: 'red' }          // 一个 CSS 样式对象
</script>

<template>
  // :href 就是从 Vue 里取值赋给 href 属性（完整写法是 v-bind:href）
  <a :href="url">去 Vue 官网</a>

  // :class 可以绑定对象：当 isActive 为 true 时，加一个 light 的 CSS 类
  <p :class="{ light: isActive }">这个段落的背景会随 isActive 变化</p>

  // :style 绑定样式对象
  <p :style="styleObj">这行是红色的</p>
</template>

3.3 指令导读：模板里的"咒语"

以 v- 开头的属性统称指令（Directives），它们让元素拥有各种"附加能力"。这一章先用一张速览表让你眼熟它们，后面的章节会逐个给出完整例子。

指令作用的一句话概括配套简写
v-bind把数据绑定到属性上:
v-on监听事件（如点击）执行方法@
v-if / v-else条件渲染：成立才显示—
v-for列表渲染：循环生成多条—
v-model表单双向绑定（数据 ⇄ 输入框）—
v-show按条件显示/隐藏（只是切 display，元素还在）—
类比Vue 的指令就像家电上的电源开关：v-if 是"这条灯亮不亮"，v-for 是"这排开关循环控制多个灯"，v-on:click 是"人按开关时触发动作"，v-bind 是"把遥控器上的数据传到设备上"。

04

响应式：数据会动

ref 与 reactive——Vue 的灵魂，让数据变化自动驱动界面

这一章是全书的核心。理解了「响应式」，你就理解了 Vue 活着的意义。核心就一句话：把一个普通数据变成"会通知别人"的响应式数据，界面就会跟着它自动更新。Vue 提供两个最常用的工具：ref 和 reactive。

4.1 为什么普通变量不行？

试想：如果没有响应式，你写 let count = 0; count++，浏览器根本不知道 count 变了对它有什么影响——因为普通变量"不会通知别人"。Vue 里要把数据"升级"成会通知别人的状态，才会触发界面更新。

类比普通变量像一个不出声的哑巴盒——你往里面换东西，外面没人知道。响应式数据像一个带喇叭的快递箱——每次内容变化，它就"叮咚"响一声，通知 Vue："我变了，快检查哪些界面需要更新！" 于是界面就会自动刷新。

4.2 ref：给单个数据装上"喇叭"

ref 用来包装单个值（数字、字符串、布尔、对象……）。被 ref 包住后，读和改都要通过它返回的对象的 .value 属性。

ref 的用法，注意 .value
<script setup>
import { ref } from 'vue'              // 从 vue 里导入 ref 工具

const count = ref(0)                   // 造一个响应式数字，初始 0（count 变成一个带 .value 的对象）

// 在 JS 里读值：
console.log(count.value)               // 输出 0

// 在 JS 里改值：
count.value = 5                        // 改 .value，Vue 侦测到变化

// 但注意：在模板里，Vue 会自动"拆箱子"，不用写 .value：
</script>

<template>
  <p>计数：{{ count }}</p>            // 这里直接写 count，Vue 自动读它的 .value
</template>
技巧记不住什么时候加 .value？就记一条：在 JS（script）里用，要加 .value；在模板（template）里用，不用加。Vue 在模板里会自动帮你拆包。

4.3 reactive：给一整个"对象"安装监听

当你有一整个对象（里面很多字段，像一份简历），逐个用 ref 包装太啰嗦。此时用 reactive：直接传一个对象进去，它里面的所有字段都变成响应式，而且访问不用 .value，就像直接用普通对象一样。

reactive 的用法，访问不用 .value
<script setup>
import { reactive } from 'vue'         // 导入 reactive

const user = reactive({               // reactive 传一个对象，整本都变响应式
  name: '小明',
  age: 18
})

// 读写都不用 .value，跟普通对象一样：
user.age = 19                          // 改 age，界面若显示 user.age 会自动更新
</script>

<template>
  <p>{{ user.name }} 今年 {{ user.age }} 岁</p>
</template>
对比项refreactive
适合包装单个值 / 也常用对象整个对象
脚本里访问需 .value直接访问属性
模板里访问自动解包，不用 .value直接访问属性
是否推荐主力Vue 官方推荐，写法统一适合对象，但注意不能整体替换
注意reactive 有个坑：如果你用 reactive 包对象后又想「整本替换成另一个对象」（例如 user = someNewObj），会丢失响应性。另外，它不能用在基本类型（数字、字符串）上。化解办法是：干脆都用 ref——ref 既能包装基本类型，包对象时访问也只是多一层 .value，写法最省心。这也正是 Vue 官方现在的推荐。

4.4 ref 包对象：现代 Vue 的推荐姿势

Vue3 的官方建议里，现在更推崇「一律用 ref」——包括对象。区别只是你用的时候要记住 .value.属性。好处是整体替换、拆解逻辑都简单。

用 ref 包对象（推荐写法）
<script setup>
import { ref } from 'vue'

const user = ref({                       // ref 也能包对象
  name: '小红',
  age: 20
})

// 读取：user.value.age
// 修改：user.value.age = 21
function happyBirthday() {
  user.value.age++                       // 记得 .value 再 .age
}
</script>

<template>
  <p>{{ user.name }} {{ user.age }} 岁</p>
  // 模板里 Vue 自动解开最外层 .value，所以直接 user.name 即可
  <button @click="happyBirthday">过生日</button>
</template>

05

计算属性与侦听器

computed 算新值，watch 看变化——把"算"和"盯"交给 Vue

写界面时你会需要两件事：根据已有数据算出新值（比如"价格×数量=总价"），以及在数据变化时做点额外动作。Vue 给了两个好帮手：computed（计算属性）与 watch（侦听器）。

5.1 computed：像"公式"一样的派生数据

计算属性的用处是：它依赖其他响应式数据，当那些数据变时，它自动重新计算，你只需把它当普通数据用。

类比计算属性就像 Excel 里的公式栏：你在 A1 里输入"=B1*C1"，B1 或 C1 只要一变，A1 立刻自动更新。你不用每隔一秒手动去算一次——Vue（Excel）替你盯着。
computed：根据单价和数量算出总价
<script setup>
import { ref, computed } from 'vue'

const price = ref(10)                  // 单价 10 元
const quantity = ref(2)                // 数量 2 件

// computed 接收一个"求值函数"，返回的值会缓存，依赖变化才重算：
const total = computed(() => {
  return price.value * quantity.value  // 总价 = 单价 × 数量
})
// 注意：computed 返回的也是个 ref 式的对象，脚本里要用 total.value
</script>

<template>
  <p>单价 {{ price }} 元 × {{ quantity }} 件</p>
  <p><b>总价：{{ total }} 元</b></p>  // 模板里直接 total，自动算总价
  <button @click="quantity++">加一件</button> <span class="cmt">// 数量一变，total 自动更新</span>
</template>
技巧什么时候用 computed，什么时候直接把表达式写在模板里？原则是：只要这个"算出来的值"在模板里出现了两次以上，或逻辑已经超过一行，就值得抽成 computed。它还会自动缓存，性能更好。

5.2 watch：数据一变，去"做事情"

侦听器用于「当数据变化时，执行一段副作用代码」——比如发请求、存到本地、打印日志、弹提示。它和 computed 的区别：computed 是"算返回值给人用"，watch 是"变化后去干活，不在乎返回值"。

watch：监控一个 ref，变化时打印
<script setup>
import { ref, watch } from 'vue'

const name = ref('小明')                 // 一个名字

// watch(要监控的数据, 变化后执行的回调)
// 回调收到两个参数：新值 newVal 和 旧值 oldVal
watch(name, (newVal, oldVal) => {
  console.log('名字从', oldVal, '变成了', newVal)  // 每次 name 变都打印
})

function changeName() {
  name.value = '小红'                    // 触发 watch，控制台打印
}
</script>

<template>
  <p>当前名字：{{ name }}</p>
  <button @click="changeName">换名字</button>
</template>

5.3 watch 监听"对象里的某个属性"

当你要监听的是 reactive 对象里的某一个属性，不能直接 watch(obj.prop)，要传一个 getter 函数（返回你想看的那个值）。

watch 单个属性，用 getter 函数
<script setup>
import { ref, watch } from 'vue'

const user = ref({ name: '小明', age: 18 })

// 传一个 getter：() => user.value.age，表示"观测 age 这个字段"
watch(() => user.value.age, (newAge, oldAge) => {
  console.log('年龄从', oldAge, '→', newAge)
})
</script>
注意像 watch 会被「对象被整体替换」或链式引用搞晕，本教程只需掌握两种最常用形态：① watch(ref变量, ...) 监听单个；② watch(()=>obj.字段, ...) 监听某字段。复杂场景（深度监听）进阶再学。

06

事件处理

@click、@input 等——让用户操作触发你的逻辑

界面不只是"显示数据"，更要能"响应用户"。当用户点击、输入、移动鼠标时，Vue 用 v-on（简写 @）让你轻松挂上处理函数。这一章解决「事件怎么绑、参数怎么传、怎么阻止默认行为」。

6.1 给元素绑定事件：@事件名

语法：@click="处理函数"。最常见的是点击 click，还有输入 input、提交 submit、键盘 keyup 等。写法如下：

三种常见事件绑定写法
<script setup>
import { ref } from 'vue'

const text = ref('')                     // 输入框的文字

// 1. 无论带不带参数都可以绑：
function onSave() {
  console.log('保存了', text.value)
}

// 2. 想拿"原生事件对象"（比如 input 的输入值），可以带 $event 参数：
function onInput(evt) {
  text.value = evt.target.value          // 从事件里取输入框当前值
}
</script>

<template>
  // 按钮点击：绑一个无参函数
  <button @click="onSave">保存</button>

  // 输入框：@input 时把事件对象 $event 传进去
  <input @input="onInput" />

  // 也可以直接在模板里写小逻辑
  <p @click="text = ''">点击这段文字清空输入</p>
</template>

6.2 传参数：@click="函数(参数)"

给处理函数传自己定义的值也很简单，直接在模板里写：

给事件传参，并把事件对象 $event 一起传
<script setup>
import { ref } from 'vue'
const score = ref(0)

// 接收一个增量 n，加到分数上
function add(n) {
  score.value += n                      // score 加 n
}
</script>

<template>
  <p>当前分数：{{ score }}</p>
  <button @click="add(1)">+1</button>     // 传参 1
  <button @click="add(5)">+5</button>     // 传参 5
  // 想既传自己的参数又要原生事件对象，用 $event：
  <button @click="add(10)">+10</button>
</template>

6.3 事件修饰符：干干净净地处理常见需求

有些事件需求非常常见，Vue 提供了修饰符，让你不用在函数里手写一堆判断。最常用的几个：

修饰符作用示例
.stop阻止事件冒泡（不让父元素也触发）@click.stop
.prevent阻止默认行为（如按钮的不必提交表单）@submit.prevent
.once只触发一次@click.once
.enter仅在按回车时触发（键盘事件用）@keyup.enter
.self仅当事件目标是自身时触发@click.self
修饰符实战：回车提交 + 阻止表单默认提交
<script setup>
import { ref } from 'vue'
const msg = ref('')

function submit() {
  console.log('已提交：', msg.value)     // 按回车或点按钮触发
}
</script>

<template>
  // @keyup.enter：输入框里按回车时调用 submit()
  <input v-model="msg" @keyup.enter="submit" />

  // 用一个 form 包起来，@submit.prevent 阻止真的跳页提交
  <form @submit.prevent="submit">
    <button type="submit">提交</button>
  </form>
</template>
注这里出现了 v-model（第 8 章详细讲），它让输入框和 msg 双向绑定——输入什么，msg 就存什么。这章先带着感觉看，下一章就会系统讲。

07

条件与列表渲染

v-if 显示不显示，v-for 循环生成一堆——把"动态"玩明白

页面打交道时最常做的两件事：按条件显示/隐藏某块内容，以及根据数组循环生成一列内容。Vue 用 v-if 和 v-for 来完成，本章彻底讲透。

7.1 v-if / v-else / v-else-if：条件显示

v-if 表示"条件为真才渲染这个元素"。配合 v-else、v-else-if，可以写成多个分支，类似 if-else。

v-if / v-else-if / v-else 三级判断
<script setup>
import { ref } from 'vue'
const score = ref(85)                    // 考生分数
</script>

<template>
  // 分数 ≥ 90：优秀
  <p v-if="score >= 90">优秀！</p>
  // 否则若 ≥ 60：及格
  <p v-else-if="score >= 60">及格</p>
  // 否则：不及格
  <p v-else>不及格，加油</p>

  // 布尔判断显示/隐藏：用 v-show 也行（见下）
  <p v-show="score > 0">有成绩显示</p>
</template>
类比v-if 像厨房里"这道菜做不做"——决定不做，就根本不进厨房（不渲染该元素）。v-show 像"菜做好了但先盖个罩子"——菜一直做在那里（元素一直存在），只是看不见（用 CSS 藏起来）。频繁切换用 v-show（省事），很少切换用 v-if（省资源）。
对比v-ifv-show
原理真才创建元素，假就移除只是设置 display:none
元素是否存在否（被移除）是（一直存在）
首次渲染开销创建才花销总是渲染
适合很少切换、条件初始化频繁切换

7.2 v-for：循环渲染列表

v-for 用来"对数组里的每一项，生成一个元素"，几乎能循环任何东西——数组、对象、数字。

v-for 遍历数组、带索引、带 key
<script setup>
import { ref } from 'vue'
const fruits = ref(['苹果', '香蕉', '橙子'])   // 一个水果数组
</script>

<template>
  <ul>
    // 遍历 fruits，每一项叫 fruit，还有索引 i
    <li v-for="(fruit, i) in fruits" :key="i">
      {{ i + 1 }}. {{ fruit }}            // 显示 编号. 水果名
    </li>
  </ul>
</template>
注意循环里一定要给 :key（一个稳定、唯一的标识）。它像身份证，帮 Vue 在列表增删改时精准复用元素，提升性能、避免 bug。不要用索引当 key，最好用数据里已有的唯一 id。

7.3 遍历对象与数字

v-for 遍历对象属性 和 连续数字
<script setup>
import { reactive } from 'vue'
// reactive 的对象可以直接 for 遍历它的字段
const info = reactive({ name: '小明', city: '北京' })
</script>

<template>
  // 遍历对象：用 (值, 键) 的顺序
  <ul>
    <li v-for="(value, key) in info" :key="key">{{ key }}：{{ value }}</li>
  </ul>

  // 遍历数字：1 到 5
  <p v-for="n in 5" :key="n">第 {{ n }} 个</p>
</template>

7.4 列表交互：增删改

配合响应式数组，你能做出完整的增删功能。注意：能用数组方法（push、splice 等）就不要用下标直接赋值，这样 Vue 才能侦测到变化。

用 v-for 做一个待办清单（增、删）
<script setup>
import { ref } from 'vue'

const todos = ref([                      // 初始待办数组，每项带唯一 id
  { id: 1, text: '写 Vue 教程' },
  { id: 2, text: '买菜' }
])
const newText = ref('')                  // 输入框内容

function addTodo() {
  // push 往数组末尾加一项；id 用 Date.now() 保证唯一
  todos.value.push({ id: Date.now(), text: newText.value })
  newText.value = ''                     // 清空输入框
}

function removeTodo(id) {
  // filter 返回"去掉该项"的新数组，赋值回去
  todos.value = todos.value.filter(t => t.id !== id)
}
</script>

<template>
  <input v-model="newText" placeholder="输入待办" />
  <button @click="addTodo">添加</button>
  <ul>
    // key 用每项的唯一 id（正确姿势）
    <li v-for="t in todos" :key="t.id">
      {{ t.text }}
      <button @click="removeTodo(t.id)">删除</button>
    </li>
  </ul>
</template>

表单输入绑定

v-model：让"输入框"和"数据"变成一个硬币的两面

前面你已经多次看到 v-model 的"惊鸿一瞥"。这一章把它彻底讲透：它是 Vue 里最省心、最常用的指令之一，让"用户输入什么"直接同步到"你的数据里"，反过来数据变，输入框也变——这叫双向绑定。

8.1 手动 vs v-model：双向绑定省在哪

没有 v-model 时，你要自己做"输入→存数据"和"数据变化→改输入框"两件事。用 v-model 后，全自动。

v-model 在文本框上的最简用法
<script setup>
import { ref } from 'vue'
const message = ref('')                   // 输入框绑定的数据
</script>

<template>
  // v-model="message"：用户输入什么，message.value 就变成什么
  <input v-model="message" placeholder="随便打点字" />
  // 同时 message 变，输入框也会变。下面实时显示：
  <p>你正在输入：{{ message }}</p>
</template>
类比想象一个传话筒（对讲机），两头分别是"输入框"和"数据"。你说一句话（输入），数据端立刻同步听见；反过来你改动数据，输入框也立刻念出来。v-model 就是这根双向传话筒——省去你手动搭线。

8.2 不同表单控件的 v-model

v-model 不止适用文本框，单选、复选、下拉框都给咱们想好了。

多种控件的 v-model（下拉、勾选、单选）
<script setup>
import { ref } from 'vue'
const city = ref('北京')         // 下拉框选中的城市
const agreed = ref(false)        // 是否勾选同意条款
const gender = ref('')           // 单选性别
</script>

<template>
  // 下拉框：选中值会存进 city
  <select v-model="city">
    <option>北京</option>
    <option>上海</option>
    <option>广州</option>
  </select>

  // 勾选框：agreed 变为 true / false
  <label><input type="checkbox" v-model="agreed" /> 我已阅读条款</label>

  // 单选框：选中的 value 存进 gender
  <label><input type="radio" value="男" v-model="gender" /> 男</label>
  <label><input type="radio" value="女" v-model="gender" /> 女</label>

  <p>城市：{{ city }} ｜ 性别：{{ gender }} ｜ 同意：{{ agreed }}</p>
</template>

8.3 数字与修饰符

有时你希望输入的内容自动转成数字，或去掉首尾空格，v-model 自带修饰符：

v-model.number 转数字、.trim 去空格
<script setup>
import { ref } from 'vue'
const age = ref(0)      // 默认按文本存，加 .number 后自动转成数字类型
const keyword = ref('') // 加 .trim 后自动去除首尾空格
</script>

<template>
  <input type="number" v-model.number="age" />   // 存成数字，不是字符串
  <input v-model.trim="keyword" />               // 自动 trim 首尾空格
</template>
技巧`.number`、`.trim` 这类叫修饰符，可以直接加在 v-model 后面。遇到"输入框明明存的是字符串却当数字用"的坑，多半是忘了加 v-model.number。

09

组件基础：搭积木

把页面拆成一块块可复用的"积木"，是 Vue 开发的灵魂

前面你也算会"写页面"了，但直接 app 里堆内容会越写越乱。Vue 的杀手锏是组件化：把一个页面拆成许多小部件（组件），每个小部件自己管自己的模板、样式和逻辑，还能互相嵌套、复用。这一章带你迈入组件世界。

9.1 组件是什么：一块"能复用的积木"

组件（Component） = 一段可复用的 UI + 逻辑块。你可以把「导航栏」「卡片」「按钮」各做成一个组件，就像搭积木一样拼出整个页面。

一个最基础的组件（.vue 单文件组件）
// 文件：MyButton.vue —— 一个"我的按钮"组件
<template>                          // ① 模板：这个组件长什么样
  <button class="btn">点我</button>
</template>

<script setup>                       // ② 逻辑：这个组件的脚本
// 这里可有自己的响应式数据、方法，但都不会泄漏到外面
let count = 0
console.log('MyButton 组件被创建')
</script>

<style scoped>                      // ③ 样式：scoped 表示只对本组件生效
.btn { background: #42d392; color: #fff; padding: 10px 16px; border-radius: 8px; border: none; }
</style>

9.2 在父组件里使用子组件

写好组件后，要"放"到别的地方用。用 import 导入，然后在模板里像用 HTML 标签一样写它（组件名建议大写开头，区分原生标签）。

App.vue 里引入并使用 MyButton
<script setup>
import MyButton from './MyButton.vue'   // 导入组件（注意路径 .vue）
</script>

<template>
  // 像普通标签一样使用它，可重复用多次
  <h2>首页</h2>
  <MyButton />
  <MyButton />
  <MyButton />
</template>
类比组件就像乐高积木：你先做出「轮子」「车厢」「车头」几块积木（组件），然后想拼什么车就拼什么车。每个积木都有自己的样子和功能，且能被反复使用。改一处积木，所有用到它的地方一起变。

9.3 为什么需要组件：好处一目了然

  • 复用：同样一个"卡片"，写一次，到处用。
  • 隔离：每个组件的样式（scoped）、数据、逻辑互不干扰，改一处不炸全站。
  • 可读：页面变成"组件清单"，别人一眼看懂结构。
  • 可维护：出 bug 只需定位到那一个组件修。

9.4 组件里也能有自己的数据与事件

组件不是空壳——它自己有响应式数据，也能绑事件、用 v-for，和普通页面写法完全一样，只是"关在自己盒子里"。

计数器组件 Counter.vue：自己管自己的状态
<script setup>
import { ref } from 'vue'
const count = ref(0)               // 组件自有的响应式数据（不影响外部同名变量）
</script>

<template>
  <div class="card">
    <p>计数：{{ count }}</p>
    <button @click="count++">加一</button>
  </div>
</template>

<style scoped>
.card { border: 1px solid #ddd; padding: 16px; border-radius: 12px; }
</style>

新手常问"拆多细"。经验法则：凡是长得像、可重复、或独占一片逻辑的东西，就值得拆成组件。一开始不要过度拆，随着"同类代码出现两次"再抽。

技巧怎么判断？如果有一段 HTML+逻辑，你发现有复制粘贴第 2 次的冲动，就打住——把它抽成组件吧。

10

Props 与事件：组件之间怎么说话

父传子用 props，子传父用 emit——搭好积木之间的"插头和电线"

只用组件还不够——组件之间还要传数据。Vue 的规矩非常清晰：数据从父组件传给子组件（Props），子组件要通知父组件就发事件（emit）。这一章把"积木之间怎么连电线"讲透。

10.1 为什么要有 Props：积木上的"插孔"

如果组件是积木，那 Props（属性）就是积木上允许"插入不同参数"的插孔。父组件往插孔里塞值，子组件就能拿到并显示。这样同一个组件能显示不同内容。

子组件：声明它接受哪些 props（defineProps）
// 文件：Greet.vue —— 一个"打招呼"组件，接受一个 name prop
<script setup>
// defineProps 声明这个组件允许接收哪些属性。这里接收一个叫 name 的字符串
defineProps({
  name: String
})
</script>

<template>
  // 直接用 prop 名（模板里自动可用）
  <p>你好，{{ name }}！</p>
</template>
父组件：往插孔里传不同的值
<script setup>
import Greet from './Greet.vue'    // 导入打招呼组件
</script>

<template>
  // 每次用 Greet 时，都给它传一个不同的 name
  <Greet name="小明" />
  <Greet name="小红" />
  <Greet name="陌生人" />
</template>
类比想想名片机（标签打印机）：机器（组件）本身长一个样，但你每次放一张不同内容的小纸条（prop）进去，它就打出一张不同名字的卡片。name 就是那个可以被塞进不同内容的小纸条。

10.2 组件标签上能不能绑数据？能，用动态绑定

prop 的值不只是固定字符串，也可以是响应式数据——用前面学的 : 绑定。

把响应式数据作为 prop 传下去
<script setup>
import Greet from './Greet.vue'
import { ref } from 'vue'
const currentUser = ref('小红')     // 一个会变化的用户名
</script>

<template>
  // 用 : 绑定：currentUser 一变，子组件自动显示新名字
  <Greet :name="currentUser" />
  <button @click="currentUser = '小刚'">换成小刚</button>
</template>

10.3 子传父：用 emit 发"信号"

props 是"父 → 子"。那子组件想通知父组件（比如"我点击了""我要删除自己")怎么办？用 emit（触发自定义事件）：子组件 emit('事件名', 数据)，父组件用 @事件名 监听。

子组件：点击时 emit 一个 filled 事件，附带参数
// Child.vue 子组件
<script setup>
// defineEmits 声明这个组件"能向外发哪些事件"
const emit = defineEmits(['close'])

function handleClose() {
  // emit('close') 表示发出一个 close 信号，可带一个数据参数
  emit('close')
}
</script>

<template>
  <button @click="handleClose">关闭</button>
</template>
父组件：监听这个自定义事件
<script setup>
import Child from './Child.vue'
const show = ref(true)

function onClose() {
  show.value = false               // 子组件点关闭后，父组件把内容藏起来
}
</script>

<template>
  <Child v-if="show" @close="onClose" />
</template>
注props 是单项向下的：父传子很容易，但绝不建议子组件直接改 prop。要是子组件想改变状态，正确做法是「发事件让父组件来改」。这条约定保证数据流向清晰，别说成习惯，但这是 Vue 的架构哲学。

10.4 完整小例子：一个"待办项"组件

综合 props（传内容）+ emit（通知删除），做一个可复用的待办项：

TodoItem.vue：接收 text，点击可发删除事件
<script setup>
// 接收两个 props：text（文本）、id（唯一标识）
const props = defineProps({
  text: String,
  id: Number
})
const emit = defineEmits(['remove'])     // 声明可发 remove 事件

function onRemove() {
  emit('remove', props.id)               // 发 remove 事件，把 id 带给父组件
}
</script>

<template>
  <li>
    {{ text }}
    <button @click="onRemove">删除</button>
  </li>
</template>
App.vue：用 v-for 渲染，监听 remove 删除对应项
<script setup>
import TodoItem from './TodoItem.vue'
import { ref } from 'vue'

const todos = ref([
  { id: 1, text: '学习 props' },
  { id: 2, text: '学习 emit' }
])

function removeTodo(id) {
  todos.value = todos.value.filter(t => t.id !== id)
}
</script>

<template>
  <ul>
    // 给每个待办传两个 prop，并监听它的 remove 事件
    <TodoItem
      v-for="t in todos"
      :key="t.id"
      :text="t.text"
      :id="t.id"
      @remove="removeTodo"
    />
  </ul>
</template>

插槽：积木上的"插口"

slot 让父组件把内容"塞进"子组件的指定位置，布局更灵活

前面我们用 props 传"数据"，但有时你想传的是"一段 HTML（内容）"——比如给一个弹窗组件塞进"标题 + 正文 + 按钮"。这就是 插槽（Slot） 的用武之地，相当于给积木留了个"可往里塞内容的插口"。

11.1 插槽是什么：给组件开一道"可装东西的口子"

普通的组件，标签之间一般是空的：<Card />。但用插槽后，父组件可以把任意 HTML 放进 <Card>...</Card> 里面，子组件用 <slot> 占个位，那块位置就会被塞入的内容替换。

子组件：留一个 slot 占位
// Card.vue —— 卡片组件，中间留一个 slot
<template>
  <div class="card">
    <h4>卡片标题</h4>
    <slot />   // ← 这是"插口"：父组件塞进来的内容会出现在这里
  </div>
</template>

<style scoped>
.card { border: 1px solid #e5e5e5; padding: 20px; border-radius: 12px; }
</style>
父组件：往插口里塞不同内容
<script setup>
import Card from './Card.vue'
</script>

<template>
  // 每次给 Card 塞不同的内容，卡片就能显示不同信息
  <Card>
    <p>这是一段普通说明文字</p>
  </Card>

  <Card>
    <ul>
      <li>第一项</li>
      <li>第二项</li>
    </ul>
  </Card>
</template>
类比插槽就像相框：相框（组件）本身固定，但你可以在框里换不同的照片（父组件塞的内容）。同一个相框，放不同的照片就成了不同的作品。

11.2 具名插槽：一个组件多个口子

当组件有不止一个插口时（比如"头部""尾部"），可以用具名插槽给每个 slot 起名字，父组件用 v-slot:名字（简写 #名字）指定往哪个口子塞。

Layout.vue：带 header 和 footer 两个具名插槽
<template>
  <div>
    // 具名插槽：name="header" 这个口子放头部内容
    <header><slot name="header" /></header>
    // 不写 name 的默认插槽，放主体内容
    <main><slot /></main>
    <footer><slot name="footer" /></footer>
  </div>
</template>
父组件：用 #名字 往指定口子塞内容
<script setup>
import Layout from './Layout.vue'
</script>

<template>
  <Layout>
    // #header 表示塞进 header 口子；#footer 塞进 footer 口子
    <template #header>
      <h1>网站标题</h1>
    </template>

    // 没写 # 的 = 默认插槽，塞进主体位置
    <p>这里是页面主体内容</p>

    <template #footer>
      <small>版权信息</small>
    </template>
  </Layout>
</template>

11.3 插槽 vs props：什么时候用哪个？

场景用哪个为什么
要传"一个值"（数字、字符串、对象）props传数据用 props 最直接
要传"一整段界面结构（HTML）"插槽 slot传界面用插槽更灵活
组件只是"套壳"，我关心里面的内容插槽 slot内容/布局由调用方决定

12

生命周期：组件的"人生"

创建、挂载、更新、销毁——在关键节点挂上你的"作业"

每个组件从「出生」到「销毁」都要经历几个固定阶段，叫生命周期。Vue 允许你在这些时间点"挂了钩子函数"，去做该做的事（比如页面挂载后请求数据）。掌握它，你就能在正确时机写代码。

12.1 四个关键阶段（顺手记两个就够）

对新手来说，真正常用的钩子没几个。强烈建议先熟练这两个：

钩子触发时机常用场景
onMounted组件首次挂载到页面后拉取初始数据、启动定时器、绑定第三方窗口事件
onBeforeUnmount组件即将被销毁前清理定时器、移除事件监听，防止"内存泄漏"
生命周期全貌（示意图 + 打印）
<script setup>
import { onMounted, onUpdated, onBeforeUnmount } from 'vue'
import { ref } from 'vue'

const count = ref(0)

// ① 挂载后：组件第一次出现在页面上时执行一次
onMounted(() => {
  console.log('组件已挂载，页面可见了')
})

// ② 更新后：每次响应式数据变化、界面刷新后执行
onUpdated(() => {
  console.log('组件更新了，当前 count =', count.value)
})

// ③ 卸载前：组件即将离开页面时执行（清理现场）
onBeforeUnmount(() => {
  console.log('组件即将被销毁，做清理')
})
</script>

<template>
  <p>count = {{ count }}</p>
  <button @click="count++">加一</button>
</template>
类比把组件想成一家餐厅的经营管理：
  • onMounted = 餐厅开业那天，邀请员工、备好食材（拉初始数据）；
  • onUpdated = 每次顾客点菜出餐时更新（数据变→界面刷新）；
  • onBeforeUnmount = 打烊前，关灯锁门、清点结账（清理定时器、移除监听）。

12.2 实战：用 onMounted 拉取数据 + 定时器，销毁时清理

最常见的真实用途：页面一打开就去后端拿数据展示；同时要小心定时器这类会一直跑的玩意儿，销毁组件时记得清掉。

定时器 + onMounted + 清理
<script setup>
import { onMounted, onBeforeUnmount, ref } from 'vue'

const now = ref('')       // 显示当前时间
let timer = null          // 定时器的句柄

onMounted(() => {
  // 组件挂载后开始：每秒更新一次时间
  timer = setInterval(() => {
    now.value = new Date().toLocaleTimeString()
  }, 1000)
})

// 组件销毁前：清掉定时器，否则它会在后台一直跑
onBeforeUnmount(() => {
  clearInterval(timer)    // 关键！防止内存泄漏/性能损耗
})
</script>

<template>
  <p>现在时间：{{ now }}</p>
</template>
注意新手常见病：在 setup 里直接 setInterval 而从不到期清理。组件销毁了定时器还在跑，越积越多拖垮页面。切记：有开就有关——开了定时器 / 监听，就在 onBeforeUnmount 里关掉。

组合式 API：逻辑的"抽屉收纳"

把一个功能抽到一起，代码不再东一块西一块

你已经用了很多"组合式 API"的语法（setup、ref），这一章要解决它真正优雅的地方：把一个功能的逻辑集中起来，还能抽出去复用。对比一下旧写法，你就明白它为什么是 Vue3 的主角。

13.1 为什么要组合式：想象你的"生活抽屉" vs "一个万能大纸箱"

写一个功能（比如"搜索"）往往牵扯数据 + 逻辑 + 生命周期好几样。在传统写法里，它们被打散在不同区块（数据区、方法区、生命周期区），改一个功能要上下翻。组合式 API 则允许你把一个功能的所有相关代码放在一起。

类比选项式写法像一个没有分隔的大收纳箱——衣服、鞋子、工具全堆里面，找"秋天的一双鞋"要翻遍整箱。组合式 API 像分格抽屉——每个格子（一个功能）装它自己的所有东西，想要什么、改什么都顺藤摸瓜、互不打扰。

13.2 把一个功能"抽"成函数：可组合（Composable）

组合式 API 最棒的用法是：把一段"数据 + 方法"包成一个自定义函数，多个组件都能调用它，这就是 可组合函数（composable）。习惯上函数名以 useXxx 开头。

useCounter.js：把"计数器"逻辑做成可复用函数
// 文件：useCounter.js（普通 js 文件，不是组件）
import { ref } from 'vue'

// 一个返回数据+方法的函数，谁调用谁就拿到一套独立计数器
export function useCounter(start = 0) {
  const count = ref(start)     // 起始值由外部传入

  function add() { count.value++ }        // 加一
  function reset() { count.value = start }// 复位到起点

  return { count, add, reset }  // 把需要暴露的东西交出去
}
在组件里使用这个可组合函数
<script setup>
import { useCounter } from './useCounter'

// 一行拿到整套计数器逻辑，组件里直接用
const { count, add, reset } = useCounter(100)
</script>

<template>
  <p>计数：{{ count }}</p>
  <button @click="add">加一</button>
  <button @click="reset">复位</button>
</template>

13.3 可组合函数的好处

  • 复用：同一段逻辑，一个函数多处组件都能 import 使用。
  • 隔离：同一个 `useCounter` 被两个组件调用，各自有独立的 count，互不干扰。
  • 可读：组件变成"我用了哪些可组合函数"，结构一目了然。
  • 可测：把逻辑从组件里抽出来，单独就能测试。

13.4 凭什么用它：拿"鼠标位置"举例（实时 + 清理）

可组合函数还可以利用生命周期钩子，把自己"挂"到组件生命周期上，自动完成初始化和清理。这是它最优雅的地方。

useMouse.js：追踪鼠标坐标，用完自动移除监听
// useMouse.js —— 监听全局鼠标移动并返回坐标
import { ref, onMounted, onBeforeUnmount } from 'vue'

export function useMouse() {
  const x = ref(0)     // 横坐标
  const y = ref(0)     // 纵坐标

  function update(e) { x.value = e.clientX; y.value = e.clientY }

  onMounted(() => window.addEventListener('mousemove', update))      // 挂载后开始监听
  onBeforeUnmount(() => window.removeEventListener('mousemove', update)) // 销毁前移除 -> 自动清理

  return { x, y }
}
任意组件里直接显示鼠标坐标
<script setup>
import { useMouse } from './useMouse'
const { x, y } = useMouse()    // 一行接入，自动管理监听与清理
</script>

<template>
  <p>鼠标位置：{{ x }}, {{ y }}</p>
</template>
技巧看到 `useCounter`、`useMouse` 这类名字了吗？「useXxx」是可组合函数的标准命名习惯，像"接口说明书"，一看就知道它能做什么。写 Vue3 时，凡是"逻辑可以抽出去、被多个地方复用"的场景，都值得包成 useXxx。

14

依赖注入与跨层传参

provide / inject——让"爷爷"直接给"孙子"递东西，不用一层层传

普通情况父子传参（props）就够了。但当组件层级很深（爷爷→爸爸→儿子→孙子都要同一个数据），一级级 @removes 传下去会非常啰嗦。provide / inject 让"高层"直接"提供"，"深层"直接"注入"，像一座直达电梯。

14.1 什么时候需要它：避免"传参传到手软"

想象：App（爷爷）想给最底层的 Level3（孙子）传一个主题色。用 props 得「爷爷传爸爸、爸爸传儿子、儿子传孙子」三级接力。用 provide/inject，爷爷 provide 一次，孙子 inject 一次直接拿到。

类比props 像层层转交的传令兵——司令的命令要经过团长、连长、班长才能到士兵，每层都要转一道，慢又容易错。provide/inject 像总司令直接打电话给基层士兵——跨过中间所有层级，一个电话直达。

14.2 provide：高层"提供"数据

在高层组件里用 provide('键名', 值) 提供数据。

App.vue（爷爷）：provide 一个主题色和一个主题状态
<script setup>
import { provide, ref } from 'vue'

// provide('data是主题'.'键', '值')：把值"广播"给所有后代（哪怕隔了很多层）
provide('theme', 'dark')

// 甚至可以 provide 一个响应式数据（常见做法）
const theme = ref('dark')
provide('theme', theme)      // 后代改 theme，所有用到的地方一起变
</template>
注意上面示例的模板标签只是示意，重点是序列：先用 ref 造数据，再用 provide 传出去。真正用于主题、user 信息等全局状态时，常配合 readonly 防止后代胡乱改动（进阶话题，此处了解即可）。

14.3 inject：深层"注入"拿到数据

在任意后代的组件里，用 inject('键名') 就能拿到祖先 provide 的值，一次到位，无需层层传递。

Level3.vue（孙子）：直接 inject 拿到爷爷的 theme
<script setup>
import { inject } from 'vue'

// inject('theme')：直接拿爷爷 provide 的那个值，不用经过爸爸、儿子传递
const theme = inject('theme')

// 如果想给"可能不存在"的值提供默认值：
const font = inject('font', '16px')   // 找不到 font 就用 '16px'
</script>

<template>
  <p>我是小孙子，拿到的主题是：{{ theme }}</p>
</template>

14.4 provide/inject vs props 怎么选

场景推荐
相邻父子之间传数据props（直接、清晰）
跨多层共享一份数据（主题、日志、登录态）provide/inject
要严格单向流动、类型声明的props
注意provide/inject 虽然方便，但也有代价：数据来源在哪里不容易一眼看出。最好只用于"明确定义的全局状态"，别到处滥用，否则项目也会变得像乱接线的盘根错节。

15

过渡与动画：让页面「动起来」

用电梯开门、公交播报的类比，学会给元素的出现、离开、移动加动画

页面不是死了的一张图，而是"活的表演"。数据变化时，元素快速出现和突然消失会让人觉得生硬。这一章学怎么给它们加过渡动画，让出现、离开、移动都"优雅丝滑"。

15.1 为什么要有动画：把「生硬」变成「自然」

想象你在等电梯：门哗地瞬间打开和缓缓滑开，哪种体验更好？当然是缓缓打开——因为我们的眼睛会期待一个连续的过程。

类比动画就是给"状态变化"加一个过渡过程。没有动画，界面就像"打板切换"：一个画面啪没了，另一个啪出现；有动画，就像"摄影机摇移"，观众能跟上变化，知道发生了什么。

Vue 内置了两个组件负责这件事：<Transition>（管单个元素的进出）和 <TransitionGroup>（管一组列表的增删和移动）。

15.2 第一个过渡：元素消失/出现变平滑

思路就三步：① 用 <Transition> 把要动画的元素包起来；② 给它命名（比如 name="fade"）；③ 写 6 个"状态类"的 CSS 控制不同时刻的样式。

  1. 包一层：在 <Transition name="fade"> 里面放 <p v-if="show">。
  2. 起个名字：给过渡起名字 fade，名字会成为 CSS 类名的前缀。
  3. 写动画：Vue 会自动在合适时机给元素加上 fade-enter-active 等类，你只要给这些类写样式。
fade 过渡 · 淡入淡出的完整例子，每行注释
<!-- Transition 把要加动画的那个元素包起来，name 是过渡的名字 -->
<Transition name="fade">
  // v-show 控制：为 true 显示、为 false 隐藏（v-if 也同理）
  <p v-show="show">这句文字会淡入淡出</p>
</Transition>

// ↓ CSS：Vue 会自动给元素加"状态类"，你负责给这些类写样式
// .fade-enter-active：进入过程在'整个动画期间'生效（这里控制淡入）
.fade-enter-active,
.fade-leave-active {
  transition: opacity 0.5s ease; // 在 0.5 秒里改变透明度，ease 是缓动
}
// 进入的'起点状态'：透明度从 0（完全透明）开始
.fade-enter-from { opacity: 0; }
// 离开的'终点状态'：透明度降到 0（完全看不见）
.fade-leave-to { opacity: 0; }
技巧一般你只需要记住两组：进入用 enter-from（起点，通常设为透明/位移）+ enter-active（过程）；离开镜像对应用 leave-active + leave-to。Vue 在切换那一瞬间自动帮你加类、播完再移除类，你不用自己动手。

15.3 六种状态类：动画的「幕后剧本」

很多教程让你背 6 个类名很头疼，其实它是有规律的——就像出国旅游的过海关清单，我们按"进/出"两幕来记。

阶段类名它管什么时刻生活类比
进入（元素出现）enter-from从"进场前"那一刻的起点样式演员上台前站的位置
enter-active进入动画进行的整个过程演员登台中的动作
enter-to进入完成后的终点样式演员站定的位置
离开（元素消失）leave-from从"离场前"那一刻的起点样式演员起身前
leave-active离开动画进行的整个过程演员下台中的动作
leave-to离开完成后的终点样式演员走下台消失
记忆口诀进是 from → to，出是 from → to，各自再配一个 active 管"过程"。名字前缀 fade- 就是你在 name="fade" 里起的名字，想换就换。

15.4 多种动画效果：位移、缩放、旋转

只是淡入淡出太单调。动画本质上是改 CSS 属性——位移用 transform: translateX/translateY，变大小用 scale，重点是把"起点 state"和"终点 state"写得不同，中间自动过渡。

slide 过渡 · 从右边滑进来的入场动画
<Transition name="slide">
  <p v-if="show">我从右边滑进来</p>
</Transition>

// 过程：0.4 秒内平滑改变位移和透明度
.slide-enter-active,
.slide-leave-active {
  transition: all 0.4s ease;
}
// 进入前：元素整块往右挪 100%，且完全透明 —— 所以看起来是"从右边滑入"
.slide-enter-from {
  transform: translateX(100%);
  opacity: 0;
}
// 离开后：挪回右边并隐藏
.slide-leave-to {
  transform: translateX(100%);
  opacity: 0;
}

15.5 列表动画：用 TransitionGroup 让每一项「排队移动」

加到删除列表项时，剩下的一项会"突然跳"上去补齐位置，很生硬。<TransitionGroup> 专门解决这个：它允许整体移动时，给移动的那一项也加动画。

类比想象一班地铁的乘客排队上车：有人下去了，后面的人会往前补位。<TransitionGroup> 就是给"补位"这件事加了动画——让往前挪的人不是瞬间跳过去，而是平滑地走前面。
列表动画 · v-for + TransitionGroup
// TransitionGroup 用来包一组 v-for 渲染的元素
<TransitionGroup name="list" tag="ul">
  // v-for 循环渲染每个待办，key 是唯一标识（动画靠 key 认人）
  <li v-for="(item, i) in list" :key="item.id">
    {{ item.text }}
    // 点击删除这一项，注意下面传的是 id 而不是下标
    <button @click="remove(item.id)">删除</button>
  </li>
</TransitionGroup>

// 进入和离开的动画，和单元素那套一样写法
.list-enter-active,
.list-leave-active { transition: all 0.4s ease; }
.list-enter-from { opacity: 0; transform: translateX(30px); }
.list-leave-to   { opacity: 0; transform: translateX(30px); }

// 关键：move 是"移动动画" —— 剩下的项目前缓慢补位而不是瞬间跳上去
.list-move { transition: transform 0.4s ease; }
注意列表项一定要写 :key，而且用稳定的 id，不要用下标 index。因为 Vue 靠 key 来"认出"哪一项移动了，用下标会导致顺序乱了就判断错人。

  2. 把上面的滑动动画改成从上方落下来（用 translateY）。
  3. 做一个"待办列表"，添加和删除项都有进出 + 移动动画。

组合式函数与工具链：走向「真正的项目」

从写着玩的 HTML 到多人协作的真项目：路由、状态库、单文件组件与构建工具

前面我们用 CDN + 单个 HTML 文件演示，方便理解。但真实项目会有很多页面、很多共享数据、很多文件。这一章教你用工具链把它们组织起来，像把散件组装成流水线工厂一样。

16.1 单文件组件 SFC：把「外貌」和「大脑」放在一个文件里

之前一个页面把所有 HTML/CSS/JS 混在一起。在真正的项目里，我们把一个组件的界面（模板）、样式（样式）、逻辑（脚本）放进一个 .vue 文件里，叫"单文件组件"（Single File Component，简称 SFC）。

类比一个组件就像一个电子产品包装盒：说明书（模板）、保修卡（样式）、核心芯片（脚本）三样东西装在一个盒子里。用的时候拆开这个盒子拿来即用，不用到处找。
MyButton.vue · 单文件组件的三大段结构
<!-- 第一段：模板 template，决定"外观"长什么样 -->
<template>
  // 一个按钮，点击触发 doClick
  <button class="btn" @click="doClick">{{ label }}</button>
</template>

<!-- 第二段：脚本 script setup，决定"大脑"怎么运作 -->
<script setup>
// defineProps 声明这个组件能接收的参数 label（子组件自己不写死文字）
const props = defineProps({ label: String })
// 绑个点击方法（这里先留空占位）
function doClick() { console.log('我被点了：', props.label) }
</script>

<!-- 第三段：样式 style scoped，只作用在本组件，不污染别人 -->
<style scoped>
// scoped 属性 ="scope"(范围)，让这段 CSS 只影响本组件里的元素
.btn { padding: 8px 16px; background: #3f7cff; color: #fff; border-radius: 6px; }
</style>
小贴士带 .vue 后缀的文件浏览器不能直接打开，需要工具链（Vite）把它"翻译"成浏览器能懂的 HTML/CSS/JS。这就是为什么真实项目要用工具链。

16.2 为什么需要工具链：从「小摊」到「工厂」

一个人写一两百行代码，用 CDN 完全够。可一旦项目大了，就会有新需求：代码拆分成好几百个文件、要热更新（改完立刻看到效果）、要压缩打包上传服务器。

类比CDN 方式像路边小摊：一个人、一口锅就能开工。工具链像工厂流水线：要烧锅炉、流水线、质检、打包车间。前期搭建麻烦，但一旦产品复杂了，工厂完胜。
能力CDN 单文件工具链 Vite 工程
拆分成多个文件麻烦天然支持
改代码立刻看到需手动刷新页面热更新（HMR），秒级
部署到服务器原样拷贝自动压缩、合并、优化
适合规模玩具、演示、Demo真实的网站/App

16.3 用 Vite 创建一个工程：几条命令搞定

Vite 是最流行的 Vue 构建工具。创建新项目只要如下几步（需要电脑已装 Node.js，就是那个能运行 JavaScript 的运行环境）。

  1. 建项目：在终端敲 npm create vue@latest my-site，一路回车选择默认。
  2. 进目录：cd my-site。
  3. 装依赖：npm install，npm 会把项目需要的外部包下载到本地。
  4. 起开发服务器：npm run dev，浏览器打开提示的网址（如 http://localhost:5173）。
  5. 改代码看热更新：编辑 src/App.vue，页面自动刷新。
终端命令 · 创建并运行 Vue 项目的完整流程

16.4 页面之间的导航：Vue Router

一个真正的网站有很多页（首页、关于、联系我们）。Vue Router 是 Vue 官方的"导航地图"，负责"在哪个地址显示哪个组件"。就像图书馆的索引目录：查"坐标"到对应书架取书。

router · 配置两个页面路由
// 引入 Vue Router 提供的两个函数
import { createRouter, createWebHistory } from 'vue-router'
// 引入两个页面组件
import Home from './views/Home.vue'
import About from './views/About.vue'

// 路由：配置"哪个地址 → 显示哪个组件"
const routes = [
  { path: '/',      name: 'home',  component: Home },  // 访问 / 显示首页
  { path: '/about', name: 'about', component: About }, // 访问 /about 显示关于页
]

// 创建路由实例，createWebHistory 表示用浏览器地址（好看）
const router = createRouter({ history: createWebHistory(), routes })
export default router
记忆点用 <router-link to="/about"> 代替普通 <a href> 做跳转；用 <RouterView /> 当"出站口"，被匹配到的组件就渲染在那里。

16.5 全局共享数据：Pinia

有时候好几个组件要共享同一份数据，比如"用户登录状态""购物车里的商品"。如果各存各的，改一个别处不知道，就会乱套。Pinia 就是专管这种"大家共用的数据"的官方状态库。

类比Pinia 就像一个公司公告栏：任何人把信息贴上去，全公司其他人马上都能看到，不用挨个办公室去通知。数据只有一份，改一次全局同步。
useCounter.js · 用 Pinia 管理一个全局计数
// 引入 Pinia 的 defineStore 用来定义一个"仓库"
import { defineStore } from 'pinia'

// useCounter 是仓库名字，返回一个函数供组件调用
export const useCounterStore = defineStore('counter', {
  state: () => ({ count: 0 }),          // state：全局共享的数据 count，初始 0
  actions: {                           // actions：修改这份数据的"方法"
    add(n = 1) { this.count += n }     // 给 count 加 n，默认加 1
  }
})

任何组件里只要 import { useCounterStore } 拿到仓库，就能读到同一个 count、调用同一个 add——一人改，处处同步。

部署上线：发布你的网站给全世界

把写好的 Vue 项目「打包」成静态文件，免费托管到网上让大家访问

项目写完了不发布，别人永远看不到。这一章教你：把开发中的工程构建（打包）成一组浏览器可直接运行的文件，再上传到免费托管平台（GitHub Pages / Netlify），让网址可以被全世界打开。

17.1 什么是「构建」：把半成品加工成成品

开发时我们的文件又长又含注释、还拆成几万个文件，浏览器一个个加载会很慢。构建（build）由构建工具自动完成三件事：压缩（删掉空格注释让体积变小）、合并（把一堆 JS 合并成少数几个文件）、优化（处理资源、加版本号）。

类比开发就像厨师的后厨：砧板、菜、调料散落各处，方便随时改。构建就像端上桌的成品菜：摆盘精致、直接能吃，但没法再回锅改配方。发布上去的就是"成品菜"。
终端命令 · 构建生产版本
# 第1步：执行构建，生成本地预览也行、上传部署也行的"成品"
npm run build

# 第2步：构建完成后，会多出一个 dist 文件夹
# 以后你要部署的就是这个 dist 文件夹里的全部文件
检查构建完在项目根目录会看到 dist/ 文件夹。里面就是 HTML/CSS/JS 的"成品"。记住：上传网站 = 上传这个 dist 文件夹，其他开发文件都不用传。

17.2 部署到 GitHub Pages（免费）

GitHub Pages 是 GitHub 提供的免费静态网站托管。把 dist 里的文件推到仓库，就能得到一个在线网址。步骤如下（假设你已有 GitHub 账号）：

  1. 建仓库：在 GitHub 官网新建一个 Repository（仓库），名字随意，比如 my-vue-site。
  2. 推送成品：进到 dist 文件夹，用 Git 把里面文件推到仓库（或直接在仓库网页上传 dist 里的文件）。
  3. 开启 Pages：进仓库 Settings → Pages，Source 选 main 分支 + /(root) 路径，保存。
  4. 等待：等 1~2 分钟，提示部署成功，网址形如 https://你的用户名.github.io/my-vue-site/。
  5. 访问验证：浏览器打开网址，能看到你构建出来的首页就成功了。
终端命令 · 把 dist 推送到 GitHub（Git 基本操作回顾）
# 前提：你已经在网站根目录完成了 git 初始化并配置好远程仓库

# 第1步：把改动全部加入暂存区（. 表示全部文件）
git add .

# 第2步：提交，写一句说明这次改了什么
git commit -m "fix: 修复首页样式"

# 第3步：推送到远程 main 分支，GitHub Pages 收到就会自动更新
git push origin main
注意GitHub Pages 免费、无需数据库、纯静态——非常适合我们的场景。但它的网址是公开的（任何人可访问），如果你要"只有自己能看"，需要额外的密码锁方案（比如用 Netlify 的访问密码，或把仓库设私有并自己部署）。

17.3 部署到 Netlify（免费、支持密码锁）

Netlify 也是免费托管，优势是：连 GitHub 仓库、每次 push 自动更新，而且免费版提供访问密码保护。如果你需要"上了密码别人才看得到"，这条路径很合适。

  1. 注册登录：去 netlify.com 用 GitHub 账号登录。
  2. 导入项目：点 Add new site → Import an existing project，选你的 GitHub 仓库。
  3. 填构建设置：Build command 填 npm run build，Publish directory 填 dist，然后 Deploy。
  4. 部署完成：得到形如 https://xxxxx.netlify.app 的网址。
  5. （可选）上密码锁：在 Site settings → Access control 里开启 Basic Auth（需在项目根目录放 netlify.toml，配置用户名和密码哈希）。
netlify.toml · 开启访问密码保护的配置示例
# Netlify 配置文件：告诉它怎么构建、以及开不开密码锁
[build]
  command = "npm run build"   # 构建命令：生成成品
  publish = "dist"            # 发布目录：打包结果在 dist 里

# password_protection 块：开启"访问密码保护"
[build.environment]
  # 下面两行告诉 Netlify 用哪个账号和密码哈希
  NETLIFY_BASIC_AUTH_USER = "wangxing"     # 访问用户名
  NETLIFY_BASIC_AUTH_PASSWORD = "$2a$..."  # 密码用 bcrypt 哈希（不存明文）
提示密码哈希不是让你手写，Netlify 后台/或搜索"在线生成 bcrypt 哈希"工具来生成，再把结果填进去。这是真实的服务器级密码锁，比前端遮罩安全得多。
