01

初识 WSL：Windows 里的 Linux

用一栋「合租公寓」理解它是什么、为什么值得装、和虚拟机有啥区别

在敲任何命令之前，先花十分钟搞懂 WSL 是什么。这一章全是故事和比喻——但它们是后面每一条命令的「地图」。

1.1 一个经典的纠结：想吃西餐，家里只有中餐厨房

很多初学者的处境是这样的：主力电脑是 Windows（打游戏、办公、微信都靠它），但想学的东西在 Linux 上——编程课的老师说「请打开 Linux 终端」；教程里的命令全是 apt install；想玩的服务器、Docker、AI 工具链，说明书第一行就写着「要求 Linux 环境」。

于是摆在面前三条路，条条难受：

方案类比痛在哪
装双系统为了吃西餐，把整个厨房拆了重装重启才能切换系统；分区一刀切错可能伤到 Windows 数据；日常还得回 Windows 干活
传统虚拟机（VMware/VirtualBox）为了喝杯水，租了整栋楼再自己装修要划走几 GB 内存和几十 GB 硬盘；开机像开冰箱一样慢；文件互传像跨省快递
租云服务器想吃西餐直接下馆子要花钱、要联网、没有图形界面，对新手门槛高；白嫖的随时会被收回

而微软官方给出的第四条路，就是 WSL（Windows Subsystem for Linux，适用于 Linux 的 Windows 子系统）：不拆厨房、不租楼、不下馆子——直接在自家餐厅里搭一个小小的西餐操作台。

1.2 WSL 是什么：请一位 Linux 房客免费合租

WSL 的官方定义读起来很绕，我们换种说法：

类比把你的 Windows 电脑想象成一栋独栋小楼。WSL 做的事情是：在楼里隔出一间带独立水电的公寓，免费请一位 Linux 房客常住——他自带全套家具（Linux 内核与工具）、自带生活习惯（文件系统、命令行），想找他干活敲一下门就行（打开终端），不找他时他安静睡觉（后台静默、几乎不占资源），哪天不想合租了，一句话请他搬走（wsl --unregister）且不留任何痕迹。

它最妙的地方在于「像呼吸一样自然」：

  • 不用重启——Windows 和 Linux 同时在线，一个窗口切过去就是 Linux；
  • 文件互通——Linux 能直接读写 C:\ 盘，Windows 也能直接翻看 Linux 的家目录；
  • 程序互调——Linux 里能唤起 Windows 的记事本和资源管理器，Windows 里也能一句话执行 Linux 命令；
  • 随开随用——首次启动秒级进入，合上盖子（关机）就一起休息。

1.3 WSL1 与 WSL2：翻译官模式 vs 独立公寓模式

WSL 至今有两代，安装时几乎总会遇到这个选择题（答案先给你：无脑选 WSL2，它也是如今的默认值）。但理解它们的区别，能帮你看懂后面一半的「怪现象」：

对比项WSL1（翻译官）WSL2（独立公寓）
有没有 Linux 内核没有，靠翻译层代劳有，微软官方维护的完整内核
软件兼容性部分软件跑不了（翻译不出来的就罢工）几乎 100%（Docker、大型工具链都行）
访问 Windows 文件（/mnt/c）极快（住在同一层楼，串门零成本）较慢（跨系统「过口岸」，适合偶尔取物）
访问 Linux 自己的文件较慢极快（ext4 文件系统原生速度）
内存占用更省动态伸缩，默认上限较大（可用配置收紧，见第 12 章）
推荐人群特殊场景（如重度依赖 /mnt/c 的老设备）所有人（默认就是它）
一句话记住WSL1 是「请了个翻译陪 Linux 程序在 Windows 楼里办事」；WSL2 是「给 Linux 单独隔了间带真发动机的公寓」。翻译难免有词不达意，独立公寓才能所欲随心——所以本教程全程基于 WSL2（也是官方默认）。

1.4 WSL 能做什么、不适合做什么

它非常擅长它不太合适
· 学习 Linux 命令行（零成本练手）
· 搭建开发环境：Python / Node.js / C/C++ / Go / Rust
· 使用 git、SSH、curl 等命令行工具链
· 运行 Docker 容器（新版 WSL2 原生支持）
· 跑 GUI 图形程序（WSLg，第 13 章）
· AI / 数据科学全家桶（CUDA 还能用上显卡） 		· 需要独占 USB / 蓝牙等硬件直通的任务
· 7×24 小时生产级服务（它随 Windows 作息，关机即休息）
· 对磁盘 IO 极敏感且数据全在 C 盘的场景（跨界访问慢）
· 想完全替代一个「纯 Linux 桌面系统」的体验

02

安装前的体检

两分钟确认「房子够不够格接这位房客」——省去九成的安装报错

WSL 安装失败的原因，90% 都能追溯到本章的两个前置条件：Windows 版本太老，或虚拟化没开。先体检、后安装，一次成功。

2.1 体检第一项：Windows 版本

Windows按 Win + R 打开「运行」，输入 winver 回车；也可以在 PowerShell 里敲：

PowerShell
winver                          # 弹出「关于 Windows」窗口：看第二行的版本与内部版本号
systeminfo | findstr /C:"OS 版本"   # 命令行方式查 OS 版本（findstr 是 Windows 的文本过滤器，类似 grep）
OS 名称:  Microsoft Windows 11 专业版
OS 版本:  10.0.22631 暂缺 Build 22631      ← Build 号 ≥ 19041 即满足 WSL 要求
你的系统能否用「一键安装」不满足怎么办
Windows 11（任意版本）✅ 可以—
Windows 10，Build ≥ 19041（版本 2004 及以后）✅ 可以—
Windows 10，Build 18362~18363（版本 1903/1909）⚠️ 不行，但支持 WSL2走第 3 章的「手动安装」路线
更老的 Windows 10 / Windows 7❌ 不支持 WSL2先升级系统（设置 → Windows 更新）

2.2 体检第二项：虚拟化是否开启（重中之重）

WSL2 的「轻量虚拟机」要靠 CPU 的虚拟化技术（Intel 叫 VT-x，AMD 叫 SVM）供电。

类比虚拟化开关就像房子的三相电闸：WSL2 公寓里那些大功率电器全靠它。电闸没合，装修（安装）看似能走完流程，一开灯（启动发行版）就跳闸报错——最著名的报错 0x80370102 就是这么来的。

检查方法一：任务管理器（最直观）

按 Ctrl + Shift + Esc 打开任务管理器 → 性能 → CPU，看右下角「虚拟化」一栏：

  • 显示 已启用 —— 体检通过，直接进第 3 章；
  • 显示 已禁用 —— 需要进 BIOS 合闸（见下方「合闸指南」）。

检查方法二：命令行

PowerShell
systeminfo | findstr /C:"虚拟化"      # 在系统信息里过滤「虚拟化」行（繁/英文系统请相应换关键词）
虚拟化: 已启用                        ← 出现「已启用」即通过
虚拟化: 已禁用                        ← 出现「已禁用」需要进 BIOS 开启 VT
BIOS 合闸指南重启电脑，开机 LOGO 亮起时狂按 F2（部分主板是 Del、F10 或 Esc，具体看开机画面底部的提示行）进入 BIOS → 找到 Advanced / CPU Configuration 类菜单 → 把 Intel (VMX) Virtualization Technology 或 AMD SVM Mode 设为 Enabled → 保存退出（通常 F10）。各品牌 BIOS 界面不同，认准 Virtualization / VT-x / SVM 这几个关键词即可。

2.3 学会打开「管理员终端」

第 3 章的安装命令必须以管理员身份运行（要动系统功能，普通身份会被拒绝）。两种打开方式：

  • Windows 11右键点击「开始」按钮 → 选 「终端(管理员)」；
  • Windows 10右键点击「开始」按钮（或按 Win+X）→ 选 「Windows PowerShell(管理员)」。

弹出用户账户控制（UAC）询问时点「是」。怎么确认自己开的确实是管理员？试一块试金石：

管理员 PowerShell
net session                     # 试金石：只有管理员身份才不会报错（普通身份会提示「拒绝访问」）
# 管理员身份：显示会话列表或「没有项目...」——总之不报错 = 身份正确
# 普通身份：发生系统错误 5。 拒绝访问。 ← 说明开的不是管理员，请关掉重开
体检清单
  1. 用 winver 确认 Build ≥ 19041（或 Windows 11）；
  2. 任务管理器确认「虚拟化：已启用」（否则先进 BIOS 合闸）；
  3. 确认会打开管理员终端，并用 net session 试过了身份。

三项全绿？下一章两分钟装完。

03

一键安装实战

从 wsl --install 到敲下第一条 Linux 命令——含老系统的手动路线

体检通过后，安装本身出乎意料地简单：一条命令 + 一次重启 + 三行输入。本章还附上老系统的手动路线和验证方法。

3.1 主路线：wsl --install 一条命令

Windows打开管理员 PowerShell（第 2 章的方法），输入：

管理员 PowerShell
wsl --install                   # 官方一键安装：自动启用所需系统功能 + 下载默认发行版 Ubuntu
正在安装: 虚拟机平台
已成功安装 虚拟机平台。
正在安装: 适用于 Linux 的 Windows 子系统
已成功安装 适用于 Linux 的 Windows 子系统。
正在下载: WSL 内核
正在安装: WSL 内核
已成功安装 WSL 内核。
正在下载: Ubuntu
请求的操作成功。直到重新启动系统前更改将不会生效。   ← 提示重启：现在就重启
  1. 执行命令：如上，一条 wsl --install（期间联网下载，耐心等进度条走完）；
  2. 重启电脑：看到「直到重新启动系统前更改将不会生效」即重启；
  3. 等 Ubuntu 开张：重启后可能自动弹出 Ubuntu 黑窗口（安装收尾、解压系统文件，一两分钟）；没弹的话，去开始菜单点 Ubuntu 图标；
  4. 办理入住：见下一节的三行输入。

3.2 入住手续：用户名与密码

WSL·LinuxUbuntu 首次启动会问你要一个「入住身份」：

Ubuntu 终端（首次启动）
Installation successful!       ← 系统解压完成，开始办入住

Enter new UNIX username: xiaowang      ← 自拟一个 Linux 用户名：全小写字母（可带数字），别用 root
New password:                          ← 设置密码（输入时屏幕毫无反应——这是故意的，不是卡了！）
Retype new password:                   ← 再输一遍确认
passwd: password updated successfully  ← 手续办完，进入系统
高能预警Linux 输密码时不显示任何字符（连星号都没有）——这是安全设计：不泄露密码长度。新手 90% 在这里以为自己键盘坏了。放心盲敲，敲完回车即可。这个密码以后在 sudo 借管理员权限时用（第 6 章），忘了也没关系，急救站 14 章有找回办法。

办完手续后看到的这行，就是你的 Linux「车牌」：

Ubuntu 终端
xiaowang@DESKTOP-ABC123:~$    ← 用户名@电脑名:当前目录$ ——~ 表示家目录；$ 结尾=普通用户（root 是 #）
类比这行提示符就像房门上的小铭牌：谁（xiaowang）住在哪台机器（DESKTOP-ABC123）、此刻站在哪个房间（~ 家目录）。以后迷路了看一眼铭牌就知道自己在哪。

3.4 备用路线：老 Windows 10 的手动安装

Build 18362~18363（版本 1903/1909）用不了 wsl --install，手动四步：

管理员 PowerShell · 手动路线
# 第一步：启用「WSL」与「虚拟机平台」两个系统功能（dism 是 Windows 的功能管理器）
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart   # 启用子系统本体
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart             # 启用虚拟机平台（WSL2 必需）

# 第二步：重启电脑（两个功能都需要重启生效）

# 第三步：安装「WSL2 Linux 内核更新包」
# 浏览器打开微软官网 WSL 文档页，下载 wsl_update_x64.msi 并双击安装（一路下一步）

# 第四步：把默认体系设为 WSL2
wsl --set-default-version 2     # 此后新装的发行版都按 WSL2 运行（老命令格式，新系统用不到）

然后从 Microsoft Store 搜索安装 Ubuntu，首次打开同样走 3.2 的入住手续。

说明新系统（满足 2.1 表格前两行）看到的内核更新包说明基本已是历史——wsl --install 全自动代办。手动路线仅供老设备和「自动路线失败」时兜底。

04

发行版管家

像管理 App 一样管理你的 Linux「套餐」：查看、安装、切换、备份、搬家

一间公寓住着不过瘾？WSL 允许你同时装好几个发行版，像手机装多个 App 一样按需切换。Windows本章命令都在 PowerShell 敲。

4.1 查看与安装

PowerShell
wsl -l -v                       # 查看本机已装的发行版：名字、运行状态、WSL 版本号
wsl --list --online             # 列出官方支持在线安装的发行版「菜单」（各地区可选略有差异）
wsl --install -d Debian         # 从菜单里安装 Debian（-d = distribution，指定发行版名）
wsl --install -d Ubuntu-22.04   # 也可以精确指定版本号的 Ubuntu（和已装的可以并存）
wsl --install -d openSUSE-Tumbleweed   # 再来一个滚动更新的 openSUSE？也没问题
以下是可安装的有效发行版的列表：
   Ubuntu                    Ubuntu 24.04 LTS        Debian GNU/Linux
   Kali Linux Rolling        Ubuntu 22.04 LTS        openSUSE Tumbleweed
...                                  ← 菜单示意：名字就是安装时 -d 后面接的参数
显示小怪癖个别旧版本里 wsl -l -v 的输出「字与字之间像隔了空格」，这是旧版 WSL 输出编码的显示问题（内容本身没错）。wsl --update 升级 WSL 本体后即恢复正常。

4.2 切换、进入与转换

PowerShell
wsl                             # 裸敲 wsl：进入「默认」发行版的交互终端
wsl -d Debian                   # 临时进入指定发行版（不改变默认，退出即回）
wsl --set-default Debian        # 把 Debian 设为默认发行版（此后裸敲 wsl 进的就是它）
wsl -d Debian echo hello        # 不进交互：直接在 Debian 里执行一条命令，输出即返回
wsl --set-version Ubuntu 2      # 把某个发行版在 WSL1 / WSL2 之间转换（2 = 转为 WSL2，转换需几分钟）
wsl --status                    # 查看默认发行版、默认体系版本等总览信息
类比-d 像门牌号：楼里住了几户（多发行版），裸敲 wsl 是回自己家（默认户），-d Debian 是去串门。--set-default 则是「搬家换默认门牌」。

4.3 删除与卸载

PowerShell
wsl --unregister Debian         # 彻底删除该发行版：文件、设置、数据全部清除且不可恢复（慎用！）
# 温和路线：设置 → 应用 → 找到 Debian → 卸载（仅移除程序本体，用户数据随 --unregister 才删）
注意--unregister 没有回收站。删之前若有舍不得的数据，先用下一节的导出打包一份。

4.4 整体打包与搬家：export / import

软件管家 apt

7.1 apt 是什么：一座巨大的免费百货商场

类比Ubuntu 官方维护着一份软件源——像一座联网的免费百货商场，几万件商品（软件）明码标价（免费）、经过质检（安全审查）。apt 就是你的购物车：报上商品名，它自动下楼取货、拆箱、安装、摆好，连带把依赖的「零件」一次配齐——再也不用「装个 A 先要去找 B，装 B 又要 C」的套娃地狱。

7.2 四板斧：更新目录、升级、安装、卸载

Ubuntu 终端
sudo apt update                  # 刷新商品目录：把商场的价目表更新到今天（注意：不安装任何东西！）
sudo apt upgrade                 # 把「已买回家」的软件全部升到最新（习惯与 update 连用：先看价目，再补货）
sudo apt install -y htop         # 安装软件：htop 是个彩色任务管理器；-y = 所有确认自动答「是」
sudo apt install -y curl git vim # 一次装多个，空格隔开（这三个是装机三大件）
sudo apt remove htop             # 卸载软件本体（保留个人配置文件，重装不丢设置）
sudo apt purge htop              # 卸载并连配置文件一起清干净（彻底分手版）
sudo apt autoremove              # 大扫除：清掉「为别人装、如今没人要」的孤儿依赖包
apt search 截图                  # 在目录里搜软件（支持模糊关键词；名字视源收录而定）
apt show htop                    # 看某件「商品」的详情页：版本、大小、用途简介
新手最常踩的坑把 sudo apt update 当成「升级软件」——它只是刷新目录，一行软件都不会装。真正的升级是 sudo apt upgrade。记法：update = 更新菜单，upgrade = 按菜单补货。

权限与文件系统

读懂 ls -l 那串天书，学会 chmod 借钥匙——顺带避开两个世界的规则冲突

「Permission denied（权限不足）」是新手最常撞的墙。理解了本章的三把钥匙模型，这堵墙就变成了门。WSL·Linux

8.1 三把钥匙：读、写、执行

Linux 里每个文件都挂着一块「门禁牌」，写着三类人分别持有哪几把钥匙：

Ubuntu 终端
ls -l 演示.txt                   # 长格式查看：权限串就显示在最前面
-rw-r--r-- 1 xiaowang xiaowang 12 9月 13 15:00 演示.txt
└┬┘└┬┘└┬┘   └──┬───┘ └──┬───┘  │      │           └ 文件名
 │  │  │       │       │    │      └ 修改时间
 │  │  │       │       │    └ 大小（字节）
 │  │  │       │       └ 所属组（组名也叫 xiaowang）
 │  │  │       └ 主人是谁（xiaowang）
 │  │  └ 其他人（others）的钥匙：r-- 只能看
 │  └ 同组人（group）的钥匙：r-- 只能看
 └ 主人（owner/user）的钥匙：rw- 能读能写
类比每个文件是一台共享设备：主人（你自己）、同组人（比如同项目组）、其他人（全楼陌生人）各有各的钥匙——read=能看、write=能改、execute=能运行（程序/脚本才需要）。谁没有哪把钥匙，操作时就会被拒之门外。

8.2 发钥匙与改钥匙：chmod 与 chown

Ubuntu 终端
chmod +x 部署脚本.sh              # 给脚本补上「可执行」钥匙（+x = 加上 execute；最常用的一句）
./部署脚本.sh                     # 运行「当前目录下」的脚本（./ 前缀 = 就这个目录里的这个文件）
chmod 644 演示.txt               # 数字法发钥匙：6=主人读写 4=组只读 4=别人只读（r=4 w=2 x=1 相加）
chmod 755 部署脚本.sh             # 7=主人读写执行 5=组读+执行 5=别人读+执行（脚本与目录的常用组合）
chown xiaowang:xiaowang 文件      # 把文件的「主人:组」改成 xiaowang（动别人的东西要 sudo）
数字钥匙组合记忆
7读+写+执行4+2+1=7（全套钥匙）
6读+写4+2=6（文档常用）
5读+执行4+1=5（程序常用）
4只读4（看不能动）

8.3 两个世界的规则冲突（WSL 特供）

冲突一：大小写敏感

Ubuntu 终端
cd ~                            # 回家（在 Linux 自己的地盘演示）
touch readme.txt                 # 创建小写 readme.txt
touch README.TXT                 # 再创建大写 README.TXT
ls                               # 惊喜：两个文件同时存在！Linux 眼里它们毫无关系
# 而在 Windows（/mnt/c）里，这两个名字会被当成同一个文件——从 Windows 拷项目到 Linux 时
# 偶发的「文件突然重复」「编译报错找不到文件」，多半就是大小写惹的祸

冲突二：换行符

Ubuntu 终端
file 部署脚本.sh                  # 让 Linux 鉴定文件：常会写出 "with CRLF line terminators"
sudo apt install -y dos2unix     # 安装换行符转换小工具
dos2unix 部署脚本.sh              # 把 Windows 风格换行（\r\n）转成 Linux 风格（\n）
# 症状速查：脚本明明语法没问题却报错 "\r: command not found" ——九成是它
原理一句话Windows 记事本换行按「回车+换行」两键（CRLF），Linux 只按「换行」一键（LF）。跨世界传脚本和配置文件时留意即可，普通文档无所谓。用 VS Code（10 章）编辑时右下角点「LF/CLF」即可切换。

8.4 行李打包：tar 与 zip

Ubuntu 终端
tar -czvf 行李.tar.gz 我的文件夹   # 打包并压缩（c=创建 z=gzip压缩 v=显示过程 f=文件名）
tar -xzvf 行李.tar.gz             # 解包解压（x=提取；解到当前目录）
tar -xzvf 行李.tar.gz -C 目标目录  # 解压到指定目录（-C = 换到那个目录再解）
sudo apt install -y zip unzip    # 装 zip 家族（Windows 同事打开无障碍）

亲手跑一遍——WSL·Linux启动迷你网页服务器，Windows看效果：

Ubuntu 终端
cd ~                            # 回家目录

9.3 SSH：从「输密码」升级到「刷门禁卡」

WSL 是练习 SSH 的绝佳靶场（连远程服务器、免密操作 GitHub 全靠它）。若你读过《Git 零基础完全教程》第 8 章，这里原理相同、命令一致——只是钥匙生成在 Linux 这边：

Ubuntu 终端
ssh-keygen -t ed25519 -C "xiaowang@qq.com"   # 生成一对门禁钥匙：-t 算法；-C 备注（三连回车用默认即可）
cat ~/.ssh/id_ed25519.pub       # 查看「挂锁」（公钥）：复制输出，贴到 GitHub → Settings → SSH keys
ssh -T git@github.com           # 敲门测试：首次问 yes/no 输 yes；出现 Hi xxx! 即配对成功
ssh 用户名@服务器IP               # 实战：登录一台远程 Linux 服务器（exit 退出）
scp 文件名 用户名@服务器IP:/tmp/   # 跨机传文件：把文件送到对方服务器的 /tmp 目录
类比SSH 密钥仍是那套「挂锁 + 钥匙」：公钥（挂锁）见人就发、挂到 GitHub 或服务器门口；私钥（钥匙）只躺在你 Linux 家里的 ~/.ssh/ 抽屉，从不外传。注意：Windows 侧和 WSL 侧各有自己的一串钥匙——在哪儿生成的，就在哪儿用。

类比工坊（编译、运行、版本管理）开在 Linux 家里，原料成品需要时才运过桥——而不是把整条生产线天天架在桥上跑。VS Code 远程模式正是为这个姿势设计的：客厅（界面）留在 Windows，生产全在 Linux。

11.1 Python：实验室隔离术（venv）

11.4 综合演练：给家目录做一次「体检报告」

把三件套学的技巧串起来：用 Python 写个小脚本统计家目录，再打包备份——全程 Linux 内闭环：

Ubuntu 终端
cd ~                            # 回家目录
cat << 'EOF' > 体检.py           # 写体检脚本（每行 # 开头的是 Python 注释）
import os                        # 导入系统模块：用来遍历目录、读文件大小
total_files = 0                  # 文件计数器
total_size = 0                   # 大小累加器（单位：字节）
for root, dirs, files in os.walk(os.path.expanduser("~")):   # 从家目录开始逐层走访每个文件夹
    for name in files:           # 每到一个文件夹，数一遍它的文件
        total_files += 1         # 计数加一
        try:                     # 有些特殊文件不让读大小，用 try 兜住别让程序崩
            total_size += os.path.getsize(os.path.join(root, name))   # 累加该文件的大小
        except OSError:          # 读不了大小时
            pass                 # 跳过它，继续数下一个
print(f"家目录共有 {total_files} 个文件，合计 {total_size / 1024 / 1024:.1f} MB")   # 打印体检报告（MB 留一位小数）
EOF
python3 体检.py                   # 运行体检
tar -czvf 家目录备份.tar.gz 网站演示 py项目   # 顺手把练过的两个项目打包备份（第 8 章的行李术）
家目录共有 25 个文件，合计 1.4 MB    ← 数字因人而异，看，这就是你的「家底」

深度管理与调优

给公寓装水电表（.wslconfig）、学会总闸（wsl --shutdown）、启用大管家（systemd）

用了一段时间你可能会问：WSL 会不会吃光我的内存？怎么彻底关掉它？怎么把整套系统搬去 D 盘？——本章全是这类「房客管理术」。

12.1 vmmem 是谁？为什么它吃这么多内存

打开任务管理器常看到一个叫 vmmem 的进程——它就是 WSL2 的「轻量虚拟机」本体。Linux 有个习性：内存先占着再说（用作缓存，需要时会让出来），于是 vmmem 看起来总在「暴饮暴食」。两种驯服方式：装「水电表」限额，或拉「总闸」停机。

12.2 Windows装水电表：.wslconfig

在 C:\Users\你的用户名\ 下新建一个纯文本文件，名叫 .wslconfig（用记事本即可），写入：

文件：C:\Users\Administrator\.wslconfig
[wsl2]                          # 小节声明：以下设置只作用于 WSL2
memory=8GB                      # 内存上限：按机器实际配置酌情给（不给此行则几乎「有多少吃多少」）
processors=4                    # CPU 核心数上限
swap=0                          # 交换空间配额：设 0 可避免虚拟内存文件膨胀（磁盘紧张时推荐）
PowerShell · 让水电表生效
wsl --shutdown                  # 总闸：停掉整个 WSL（所有发行版一起休息；改 .wslconfig 后必须重启它）
wsl                             # 重新进入：新限额即已生效（可用 free -h 在里面验证）
类比.wslconfig 是写给「公寓管理处」的水电额度单：每个月最多用多少度电（CPU）、多少吨水（内存）。额度单一交，管理处下次开门就按新规矩执行——但得先拉一次总闸再送电（wsl --shutdown）才生效。

12.3 Windows日常开关与体检

PowerShell
wsl -l -v                       # 体检：各发行版运行状态（Running 运行中 / Stopped 已休息）
wsl -t Ubuntu                   # 单户电闸：只停 Ubuntu 这一个发行版（terminate）
wsl --shutdown                  # 总闸：停掉整个 WSL（下班合盖前想彻底释放内存时用）
wsl --status                    # 总览：默认发行版、默认体系版本
wsl --update                    # 更新 WSL 本体（内核、WSLg 等组件；遇到怪问题时先跑它）
wsl --version                   # 各组件版本号（给技术支持排查问题时展示的就是这份输出）

12.4 WSL·Linux启用大管家 systemd

较新的 WSL 已默认启用 systemd（Linux 的「总管家」，负责启动/守护各种后台服务）。若你的发行版还没开（表现：提示找不到 systemctl 命令），两步打开：

WSL·Linux

第一步：写配置

Ubuntu 终端
sudo nano /etc/wsl.conf          # 编辑发行版私有配置（方括号开头的是「小节」标题）
# 写入两行（nano：Ctrl+O 回车保存，Ctrl+X 退出）：
#   [boot]                       ← 「开机」小节
#   systemd=true                 ← 开机时把大管家叫起来
Windows

第二步：重启生效

PowerShell
wsl --shutdown                  # 拉总闸（wsl.conf 的修改同样要重启才生效）
wsl                             # 重新进入，systemd 已上岗
Ubuntu 终端 · systemd 驾驶术
systemctl status ssh            # 查看某服务（如 ssh）的运行状态：绿色的 active (running) = 正常
sudo systemctl start 服务名      # 启动一个服务；stop 停止；restart 重启
sudo systemctl enable 服务名     # 设为「开机自启」；disable 取消自启
systemctl list-units --type=service | head -n 15   # 看看大管家现在管着哪些服务（取前 15 行）

12.5 备份与搬家（复习 + 升级）

第 4 章的行李系统就是完整备份方案：wsl --export 打包 → 存到 D 盘或移动硬盘 → 重装系统后 wsl --import 恢复。「搬去 D 盘给 C 盘减负」也用同一套：--unregister 原发行版 → --import 到 D:\WSL\...。要点回顾：

搬家三件套① wsl --export Ubuntu D:\备份.tar 打包 → ② wsl --unregister Ubuntu 腾出原地 → ③ wsl --import Ubuntu D:\WSL\Ubuntu D:\备份.tar --version 2 落户新址。搬完记得按 4.4 的方法把默认用户写回 /etc/wsl.conf——不然每次进门都是 root 房东本人。

常见报错急救站

遇到红色报错先深呼吸：WSL 用户基数巨大，你能遇到的坑几乎全部有标准答案。本章按报错原文关键字索引。

报错 / 症状关键字它在说什么急救方案
WslRegisterDistribution failed with error: 0x80370102 虚拟化没开或「虚拟机平台」没启用（三相电闸没合） ① 任务管理器查「虚拟化：已启用」，否则进 BIOS 开 VT-x/SVM（第 2 章）；② 管理员 PowerShell 重跑 wsl --install 自动补功能
error: 0x800701bc（WSL2 需要更新内核组件） WSL2 的 Linux 内核没装或太旧 wsl --update 一条命令补齐；顽固时去微软官网下 wsl_update_x64.msi 手动装
请启用虚拟机平台功能 / Virtual Machine Platform 系统功能开关没打开 管理员 PowerShell 执行第 3 章手动路线的两条 dism 命令，重启电脑
PowerShell 提示无法识别 wsl 命令 Windows 太老，或没装 WSL winver 查版本：不满足就先升级系统；满足则走第 3 章安装流程
下载 Ubuntu / 内核时卡住不动 网络到境外服务器不通畅 换个时段重试；或从 Microsoft Store 直接搜「Ubuntu」安装；先 wsl --update 也常能解
安装时输密码没反应 不是故障：Linux 输密码从不回显 盲敲输完回车即可（第 3 章预警过）
启动后直接是 root@... 发行版是 import 恢复的，默认用户没带过来 按 4.4 补办：编辑 /etc/wsl.conf 写入 [user] + default=名字，再 wsl -t 发行版名 重启
忘了 Linux 密码 密码忘了进不去 sudo PowerShell 敲 wsl -u root（以房东身份旁路进入）→ 里面执行 passwd 你的用户名 设新密码 → exit 回普通身份
vmmem 内存占用巨大 Linux 拿内存当缓存，看着吓人 装「水电表」：.wslconfig 写 memory=8GB 限额 + wsl --shutdown（第 12 章）；不用时拉总闸即可释放
WSL 里ping 不通 / 上不了网 DNS 配置偶发抽风 先 wsl --shutdown 重启网络栈；仍不行临时换 DNS：echo "nameserver 223.5.5.5" | sudo tee /etc/resolv.conf
WSL 里时间不对（常比北京时间慢 8 小时） 睡眠唤醒后时钟没跟上 sudo hwclock -s：把系统时钟同步到硬件时钟，一秒回正
GUI 程序报 cannot open display WSLg 组件未启用或版本过旧 wsl --update 升级 WSL 本体后 wsl --shutdown 重启再试；Windows 10 老版本可能不支持
/mnt/c 下文件权限全是 777 / 000 跨系统挂载的默认宽松权限（正常现象） 不影响日常使用；在意可在 /etc/wsl.conf 的 automount 小节加 metadata 选项（进阶，按需搜索）
wsl -l -v 输出「字间有空格」 旧版 WSL 的输出编码显示问题 内容本身没错；wsl --update 后即恢复正常显示

14.1 万能排查三板斧

  • 第一斧 wsl --update：八成怪病（内核、WSLg、显示、网络）都是版本旧了，先升再说；
  • 第二斧 wsl --shutdown：重启大法对 WSL 同样灵验——很多「玄学故障」重启即愈；
  • 第三斧 搜报错原文：把错误码原样贴进搜索引擎，你永远不是第一个踩坑的人。

最佳实践与进阶路线

几条让人少走弯路的习惯，以及学完本教程之后该去哪

命令层面的知识已经齐了。这一章是「住户守则」——都是不起眼的小习惯，却决定了你的 Linux 生活是顺滑还是灾难。

15.1 六条住户守则

  1. 代码安家 Linux（~/）：性能原生，工具链顺畅；Windows 那边只放「成品」（10.3 的性能铁律）；
  2. 大改动前先打包：wsl --export 一次几秒钟，重装系统/折腾失败时救你全家的数据（12.5）；
  3. 下班前可以拉总闸：wsl --shutdown 彻底释放内存，明天打开照常秒进（正在跑的服务会停，注意别打断正在干活的程序）；
  4. 定期 wsl --update：WSL 本体在快速迭代，很多「怪病」升级即愈；
  5. 遇到陌生命令先 man：说明书永远比搜索结果权威，还能练英语（或安装中文 man 手册包）；
  6. rm 之前先 ls：Linux 没有回收站，删除前多看一眼路径（6.2 的铁律，值得再说一遍）。

15.2 给终端加一点私人定制（别名）

Ubuntu 终端
nano ~/.bashrc                 # 编辑你的 shell 个性化配置（每次开终端都会自动执行一遍它）
# 滚到文件末尾，追加一行（nano：Ctrl+O 回车保存，Ctrl+X 退出）：
#   alias ll='ls -alF'          # 给「ls -alF」起外号 ll（重开终端或 source ~/.bashrc 后生效）
ll                             # 试试：一眼看清权限+隐藏文件+类型标记

15.3 接下来去哪？

  • Linux 命令深度进阶：在线闯关站 linuxjourney.com（英文，配图友好）；中文经典《鸟哥的 Linux 私房菜》；
  • Shell 脚本自动化：把重复操作写成 .sh 脚本——本教程第 8、11 章已埋了伏笔；
  • 版本控制：在 WSL 里练 Git——配套的《Git 零基础完全教程》整本都能在这里实操；
  • Docker 容器：WSL2 是 Windows 上跑 Docker 的官方底座，学完 WSL 正好接上；
  • 最有效的下一步：把你手头任何一个真实项目（笔记、作业、小工具）搬进 ~/，用 VS Code 远程模式开发两周——肌肉记忆自然长成。
结语WSL 的本质，是把「一台电脑」升级成「两个世界的一张工位」：左手的 Windows 负责生活与办公，右手 Linux 负责学习与创造，中间那座桥（/mnt/c、localhost、VS Code 远程）永不堵车。房子已经分好——去住吧。
