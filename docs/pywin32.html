01

初识 pywin32：给 Windows 请一位翻译官

先弄懂它替你解决了什么问题——以及为什么叫「32」

在敲任何代码之前，先花十分钟搞懂三件事：Win32 API 是什么、pywin32 是什么、它俩是什么关系。这一章全是比喻，却是后面所有章节的地图。

1.1 Windows 是一座提供上万项服务的巨型大厦

你每天用的窗口、按钮、键盘响应、文件复制、剪贴板、打印机、音量、任务栏……这一切背后，都由 Windows 操作系统亲自管理和提供。把 Windows 想象成一座巨型服务大厦：一楼大厅有个总服务台，墙上挂着一本厚得吓人的服务目录——上面登记着上万项服务：

  • 「帮我找一个标题叫 XX 的窗口」；
  • 「帮我把这段文字放进剪贴板」；
  • 「帮我启动一个程序 / 结束一个进程」；
  • 「帮我读一下注册表里的某个档案」；
  • 「帮我向那个窗口广播一条消息」……

这本服务目录的真名，叫 Win32 API（Windows 32-bit Application Programming Interface，Windows 应用编程接口）。它从 1995 年的 Windows 95 一路服役至今，是 Windows 世界一切程序（包括 Python 解释器自己）与系统对话的官方唯一渠道。

类比Win32 API = 服务大厦前台的服务目录 + 点单机：任何程序想用系统的能力，都得照着目录「点单」。只是这位前台只懂一门语言——C 语言的方言（函数、句柄、结构体那一套）。

1.2 痛点：Python 说的不是 C 语言

Python 语法优雅、生态丰富，但它天生不会说 C 方言。你没法在 Python 里直接喊一句 Win32 的 FindWindow——就像你拿着中文菜单走进一家只收英语订单的餐厅，服务员（Windows）听不懂，只能对你摊手。

于是有了 pywin32：它把上千个 Win32 服务逐个包装成 Python 函数——名字基本照抄原版、参数翻译成 Python 类型、返回值直接给你 Python 对象。你照常写 Python，它在幕后替你去前台排队、下单、取结果。

类比pywin32 就是花零工资请到的金牌翻译兼跑腿员：你说 Python 他译 C，前台给回执他译回 Python。句柄、常量、消息这些 C 世界的概念他一个不落地带给你，但都换上了 Python 的外衣。

1.3 为什么叫「32」？它能干什么？

「Win32」的 32 来自 32 位时代（Windows 95）。如今系统早已是 64 位，但「Win32 API」这个名字作为整套桌面 API 的统称被沿用了下来——64 位 Windows 完整兼容它（并另有 Win64 扩展）。所以别被名字骗了：你的 64 位 Windows 上，pywin32 照常全功能工作。

02

地基与安装

装好 Python 这台「发动机」，请进 pywin32 这位「翻译官」，再干杯庆祝

pywin32 是个 Python 库，所以先得有 Python。本章从零装齐整套环境，并完成「第一杯咖啡」仪式——一个原生的 Windows 弹窗。

2.1 安装 Python（发动机）

  1. 下载：打开 python.org，下载最新的 Windows installer (64-bit)（页面顶部大按钮即是）；
  2. 安装时勾选 Add python.exe to PATH：这个勾让你在任何命令行里直接敲 python——忘勾是新手第一坑（急救站第 27 章有补救法）；
  3. 验证：开一个命令行（按 Win+R 输入 cmd 回车，或开始菜单搜「cmd」），敲：
命令行（cmd 或 PowerShell）
python --version              # 命令 --version：让 Python 自报版本号；出现 Python 3.12.x 之类即安装成功
pip --version                 # 命令 --version：pip 是 Python 的「包快递员」，随 Python 一起到岗
小提示若已装 Python 但没勾 PATH，最省事的补救：重跑安装包 → Modify → 勾上 Add to PATH 一路下一步。另外本教程假设 Python 3.8 以上，32/64 位均可（建议 64 位与系统一致）。

2.2 安装 pywin32（请翻译官进门）

命令行
pip install pywin32           # 命令 install：让快递员去仓库把 pywin32 取来装进当前 Python
# 网络慢的话先换国内镜像（与 Git/Vite 教程同款技巧）：
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple   # 配置：以后默认走清华镜像仓
pip install pywin32           # 再装一次，速度起飞
Successfully installed pywin32-306    ← 出现 Successfully 即装好（版本号随发布更新）
注意包名与模块名不同安装叫 pywin32，但代码里 import 的名字是 win32api、win32gui 这样的一串——它是一个「工具箱大礼包」，里面装着二十多个模块（第 3 章上地图）。别写出 import pywin32（会报错）。

2.3 体检：三个模块各报个到

命令行
python -c "import win32api, win32gui, win32con; print('pywin32 就绪')"   # -c：把引号里的字符串当 Python 代码直接执行；同时导入三个常用模块验证

2.4 第一杯咖啡：一个原生的 Windows 弹窗

敲下你的第一段 pywin32 程序（照抄到 hello.py 文件里，python hello.py 运行；Win+R 输入 notepad 可快速打开记事本编辑）：

文件：hello.py
import win32api               # 模块 win32api：杂项系统 API 工具箱（api = Application Programming Interface 应用编程接口；弹窗、按键、版本信息等都在这）
import win32con                # 模块 win32con：Windows 常量字典（con = constants 常量；成千上万个系统编号都住这）

# 函数 MessageBox（消息框）：在屏幕上弹出一个 Windows 原生对话框
win32api.MessageBox(           # 调用方式：模块名.函数名(参数...) —— pywin32 的标准姿势
    0,                         # 参数 1（hwnd 父窗口句柄）：0 表示没有父窗口，独立弹出
    "你好，pywin32！",           # 参数 2（lpText 正文）：对话框里显示的文字
    "第一杯咖啡",               # 参数 3（lpCaption 标题）：对话框标题栏的文字
    win32con.MB_OK             # 参数 4（uType 样式）：MB_OK 常量 = 只放一个「确定」按钮（MB = MessageBox 前缀）
    | win32con.MB_ICONINFORMATION   # 常量 MB_ICONINFORMATION：加一个蓝色 i 信息图标；竖线 | 表示「两种样式同时要」
)                              # 运行后会弹窗；点「确定」后函数才返回、程序才结束
庆祝一下这个弹窗不是 print 打在黑窗口里的字，而是一个货真价实的 Windows 窗口——由系统亲手绘制的。你的 Python 代码刚才真的「走进服务大厦办成了一件事」。从这一刻起，整座大厦的上万项服务对你敞开。

04

两大基石：句柄与常量

看懂 HWND「排队号」和 win32con「编号字典」——之后所有 API 都是好懂的排列组合

Win32 世界的一切交互，都建立在两个概念上：句柄（handle）和常量（constant）。把它们变成直觉，后面 24 章的每个 API 你都能「望文生义」。

4.1 句柄（HWND）：服务大厦发的排队号

当你要操作系统里的「某个东西」——某个窗口、某块画布、某个进程——Windows 不会把那件东西整个递给你，而是发给你一张凭条。以后每次来办事，出示这张凭条即可。这张凭条，就叫句柄（handle）。

类比句柄 = 商场寄存处的号牌：你拿到的是「3 号」，不是柜子本身。凭「3 号」可以取放东西、可以转借朋友（把句柄传给别的 API），但别去琢磨「3 号」这三个字有什么含义——它只是个编号。窗口的句柄专称 HWND（H = Handle 句柄，WND = WiNDow 窗口）。

亲手拿一个句柄看看

文件：handle_demo.py
import win32gui               # 模块 win32gui：窗口管理科（本例用它领一个句柄）

hwnd = win32gui.FindWindow(    # 函数 FindWindow（找窗口）：在所有窗口里按条件找第一个匹配的
    None,                      # 参数 1（lpClassName 窗口类名）：None = 不限类名（类名是窗口的「血统」，如记事本是 Notepad）
    "任务管理器"                # 参数 2（lpWindowTitle 窗口标题）：按标题栏文字匹配
)                              # 返回值存入变量 hwnd：拿到句柄（凭条号）；找不到返回 0
print(hwnd)                    # 打印句柄：像 197234 这样的一串数字——每次开窗号码都不同，别背它
197234                         ← 你的「任务管理器」窗口凭条号（数字每次都不同）
三条铁律① 句柄只当凭条用，别做加减运算、别存盘长期保存——窗口一关，凭条立刻作废（再用会报错 1400「无效窗口句柄」）；② 拿到句柄尽快用，隔几秒世界就可能变了；③ 凡返回 0 的查找都意味着「没找到」——先检查标题是否写对（窗口标题每分每秒都在变，如记事本会带文件名前缀）。

4.2 句柄家族：不止窗口有凭条

句柄类型它是谁的凭条怎么来的
HWND窗口（或控件——按钮也是「窗」）FindWindow / EnumWindows 回调
HDC画布（Device Context，设备上下文）GetDC / GetWindowDC（第 14 章）

4.3 常量（win32con）：给魔法数字上户口

Win32 的 C 世界里，样式、状态、命令全是裸数字——「关闭窗口的消息」其实是 0x0010，「带问号图标」其实是 0x20。直接写数字没人看得懂，于是约定了有名字的常量，pywin32 把它们全部收进 win32con 模块：

4.5 错误处理：pywintypes.error 这位「投诉科」

办业务就可能办砸：窗口找不到、权限不够、文件不存在。Windows 会给每个失败一个错误码 + 说明，pywin32 把它们包成统一异常 pywintypes.error：

文件：error_demo.py
import win32gui               # 模块 win32gui：本例用一个「作废的句柄」触发报错
import pywintypes              # 模块 pywintypes：后勤科——error 异常定义在这里

fake_hwnd = 99999999           # 变量 fake_hwnd：一个瞎编的、根本不存在的窗口凭条号
try:                            # 关键字 try：把「可能出事」的代码圈起来
    win32gui.GetWindowText(fake_hwnd)   # 函数 GetWindowText（取窗口标题）：凭条无效，这里必然翻车
except pywintypes.error as e:   # 关键字 except：翻车后接住异常对象，存入变量 e（pywintypes.error 是统一异常类）
    print("错误码:", e.winerror)   # 属性 e.winerror：Windows 的错误编号（1400 = 无效窗口句柄）
    print("说明:", e.strerror)     # 属性 e.strerror：Windows 的官方文字说明
    print("函数名:", e.funcname)   # 属性 e.funcname：是哪个 API 出的事——排错神器
错误码: 1400                    ← 1400：无效的窗口句柄（凭条作废）
说明: 无效的窗口句柄。
函数名: GetWindowText           ← 连「肇事者」名字都告诉你了

5.1 EnumWindows：全楼点名

想知道屏幕上到底开着哪些窗口？用 EnumWindows（Enum = enumerate，逐个枚举）。它的用法有点特别：你不主动去「要」清单，而是派一个应答员站在走廊里——Windows 每数到一个窗口，就喊他一声，把句柄塞给他。

类比EnumWindows = 大厦广播喊话：「请各窗口代表到走廊报到！」每来一个顶层窗口，广播就调用一次你写好的应答函数——这种「你写的、由别人反复调用」的函数，专业名叫回调函数（callback）。你不用管它被调用几次，只要写好「每来一个我干什么」。
文件：enum_basic.py
import win32gui               # 模块 win32gui：窗口管理科——侦查、操控窗口都找它

def report(hwnd, extra):      # 函数 report：自制的「应答员」（回调函数）——每报到 1 个窗口就被自动调用 1 次

win32gui.EnumWindows(report, None)          # 函数 EnumWindows（全楼点名）：参数 1 = 应答员的名字；参数 2（extra 随身行李）会原样转交给应答员，用不上就给 None

5.4 实战：窗口雷达

把本章学的东西串起来：枚举全部顶层窗口 → 筛掉不可见和无标题的 → 按「句柄、血统、标题」排好队打印。这就是很多自动化工具的第一块砖：

文件：radar.py
import win32gui               # 模块 win32gui：窗口管理科

windows = []                  # 变量 windows：空列表——「窗口雷达」的记录本

def radar(hwnd, extra):       # 函数 radar：应答员（回调函数），每报到 1 个窗口就被调用 1 次
    if not win32gui.IsWindowVisible(hwnd):   # 函数 IsWindowVisible：不可见的（隐藏工作窗口）→ 不记录
        return                               # 关键字 return：什么都不做，结束本次应答（返回 None = 请继续点名）
    title = win32gui.GetWindowText(hwnd)     # 函数 GetWindowText：取标题
    if title:                                # 有标题才算「正经窗口」——没标题的大多是无脸工作窗口
        cls = win32gui.GetClassName(hwnd)    # 函数 GetClassName：取血统
        windows.append((hwnd, cls, title))   # 方法 append（列表自带方法）：追加一条记录 (句柄, 血统, 标题)

win32gui.EnumWindows(radar, None)             # 函数 EnumWindows：全楼点名，报数开始

print(f"共发现 {len(windows)} 个可见窗口")    # 内置函数 len：数一数记录本上有几条
for hwnd, cls, title in sorted(windows, key=lambda w: w[2]):   # 内置函数 sorted：排序后再遍历；参数 key 给了个 lambda 迷你函数「w: w[2]」——按每条记录的第 3 项（标题）排
    print(f"{hwnd:>9}  [{cls}]  {title}")  # 逐行打印：句柄右对齐 9 格（:9 加对齐符是格式化指令）+ 血统 + 标题

文件：to_front.py

类比SetWindowPos = 给搬家公司下工单：「把 3 号柜（句柄）搬到第几排（层级）、放在哪面墙的什么位置（x, y）、长宽各多少（cx, cy）、最后顺手做点什么（flags）」。不想动的项目用 SWP_NOMOVE / SWP_NOSIZE 打勾跳过。

6.4 实战：窗口摆放器

把本章四招串成一个能用的工具：找到目标 → 还原 → 量尺寸 → 摆到屏幕左半侧 → 请到最前。改个标题就能摆任何窗口：

文件：half_screen.py
import win32gui               # 模块 win32gui：窗口管理科
import win32con               # 模块 win32con：常量字典

TARGET = "无标题 - 记事本"     # 变量 TARGET：目标窗口的标题——换成你想摆的任何窗口

hwnd = win32gui.FindWindow(None, TARGET)   # 函数 FindWindow：按标题锁定目标
if hwnd == 0:                              # 铁律复查：返回 0 = 没找到
    raise RuntimeError(f"没找到窗口：{TARGET}")   # 关键字 raise：主动抛出异常；RuntimeError 是 Python 内置异常类，括号里是给人看的说明

left, top, right, bottom = win32gui.GetWindowRect(hwnd) # 函数 GetWindowRect：量一下现在的外框，用原尺寸算半屏

win32gui.SetWindowPos(                    # 函数 SetWindowPos：开始摆放
    hwnd,                                 # 目标窗口
    win32con.HWND_TOP,                    # 层级：普通层最上（不抢「永远置顶」特权）
    0,                                    # x：贴屏幕最左边
    0,                                    # y：贴屏幕最上边
    (right - left) // 2,                  # 宽度：原宽的一半（// 是整除——像素数必须是整数）
    bottom - top,                         # 高度：保持原样
    win32con.SWP_SHOWWINDOW               # 修饰开关：顺带显示
)
win32gui.SetForegroundWindow(hwnd)        # 函数 SetForegroundWindow：最后请到最前来
print("摆放完成：目标已就位于屏幕左半侧")   # 收工播报

键鼠模拟：替你动手

让 Python 化身一双看不见的手——打字、按快捷键、点鼠标，系统完全分不清是不是你本人在操作

自动化的终极浪漫：你喝着咖啡，Python 替你敲键盘、点鼠标。本章学「物理按键模拟」——填表格、跑流程、做演示，都靠它。

7.1 原理：向全楼广播「我按了」

键盘和鼠标是全机共享的设备：keybd_event（keyboard event，键盘事件）和 mouse_event（鼠标事件）做的事情，就是向整个系统广播「有一个键被按下了」「左键被点了一下」。系统分不清这是你肉手按的，还是程序喊的——这正是它能工作的原因。

全局广播键鼠模拟敲的是「整个系统」，不是发给某个窗口。敲字的瞬间谁在最前面，字就进谁家——所以动手前务必用第 6 章的 SetForegroundWindow 把目标请到最前。想「隔着窗户递纸条」给指定窗口？那是第 8 章消息机制的活儿。

7.2 模拟按键：keybd_event 与虚拟键码

每个物理键在 Windows 里都有一个编号，叫虚拟键码（Virtual Key code，VK 码）。先看最朴素的「敲一下字母 H」：

文件：key_demo.py
import win32api               # 模块 win32api：杂项工具箱——键鼠模拟住这里
import win32con               # 模块 win32con：常量字典（VK_、KEYEVENTF_ 家族住这里）

win32api.keybd_event(         # 函数 keybd_event（键盘事件）：向系统广播「有一个键……」
    0x48,                     # 参数 1（bVk 虚拟键码）：0x48 = 字母 H 的键码（十六进制写法）
    0,                        # 参数 2（bScan 硬件扫描码）：老键盘时代的遗产，现在一般给 0
    0,                        # 参数 3（dwFlags 修饰开关）：0 = 按下（不带修饰就是「按下」）
    0                         # 参数 4（dwExtraInfo 附加信息）：一般给 0
)                             # ——到这儿只算「按住了」，还没松手！
win32api.keybd_event(0x48, 0, win32con.KEYEVENTF_KEYUP, 0)   # 再广播一次：KEYEVENTF_KEYUP = 松开修饰。按下 + 松开，才算敲了一下
类比敲键 = 拧门把手：拧一下再放手才算「开门」。只按不松（漏了 KEYEVENTF_KEYUP），系统会以为你一直按着 H——记事本里会疯跑出一串 HHHHHH。

消息机制：窗口微信

Windows 的一切交互底层都是「消息」——学会收发消息，你就能隔空指挥任何窗口

上一章的键鼠模拟是「穿你的衣服替你动手」，这一章更进一步：连动手都省了，直接给窗口发短信。这是 Win32 世界最核心的机制，也是最优雅的一章。

8.1 万物皆消息：Windows 的微信系统

在 Windows 里，一切事件都是消息：你点了一下按钮，鼠标驱动产生消息；程序想改自己的标题，也是给自己发消息；连「请关门」这件事，本质都是有人给窗口发了一条 WM_CLOSE。

类比整个 Windows 就是一栋用微信运转的大厦：每个窗口有个账号（句柄 hwnd），任何人想让它做点什么，都给它发一条消息。窗口收到后由自家的「秘书」（窗口过程函数）拆信处理。你用第 7 章模拟按键敲字，底层也是系统把「按键」翻译成消息，投进当前窗口的信箱——消息才是大厦的通货。

8.2 消息的统一格式：四件套信封

每条消息都是同一个格式：给谁（hwnd）、什么事（msg）、附件一（wParam）、附件二（lParam）。用「请关门」这条最常用的消息练手：

文件：send_close.py
import win32gui               # 模块 win32gui：窗口管理科——发消息的柜台也在它家
import win32con               # 模块 win32con：常量字典（WM_ 家族住这里）

hwnd = win32gui.FindWindow(None, "无标题 - 记事本")   # 收件人：先拿到记事本的门牌号

win32gui.PostMessage(         # 函数 PostMessage（投递消息）：把短信塞进对方信箱，立刻走人
    hwnd,                     # 参数 1（hWnd 收件人）：发给哪个窗口
    win32con.WM_CLOSE,        # 参数 2（Msg 消息编号）：WM_CLOSE = 「请关门」这条台词
    0,                        # 参数 3（wParam 附件一）：WM_CLOSE 用不上附件，给 0
    0                         # 参数 4（lParam 附件二）：同上，给 0
)                             # 跑一下——记事本收到短信，彬彬有礼地关门（若是没保存，会先弹「要不要保存？」）
名字的来历wParam、lParam 这两个怪名字是16 位 Windows 时代的遗产：当时 wParam 是 word（16 位）参数、lParam 是 long（32 位）参数。如今它们都是大整数，但名字留了下来。不同消息对两个附件有不同用法——有的塞键码，有的塞坐标，有的塞文字。

8.3 常用 WM_ 消息速查

消息拆解说什么附件里装什么
WM_CLOSEWindow + Close请关门（走正常关闭流程）都空着
WM_SETTEXTSet + Text把你的标题改成我给的lParam 装新标题文字
WM_KEYDOWN / WM_KEYUPKey Down / Up有键按下 / 松开wParam 装键码
WM_LBUTTONDOWNLeft Button Down左键按下（点了我一下）lParam 装坐标
WM_COMMANDCommand菜单项 / 按钮被点了附件装「是谁被点」的编号
WM_QUITQuit程序该退出了wParam 装退出码

8.4 PostMessage 与 SendMessage：投信 vs 当面递话

同样是发消息，pywin32 提供两个柜台，区别是等不等回执：

PostMessageSendMessage
类比信箱投递：塞进去就走当面递话：等对方处理完才返回
返回值拿不到处理结果能拿到窗口的回复
风险几乎不卡对方要是不回话，你会一直等（卡住）
适合通知类：关窗、按键、点按钮要结果的：改标题、查状态

8.5 实战：广告弹窗清扫机

消息机制 + 第 5 章的枚举回调，合体成一个实用工具：全楼点名，见到标题带「广告」的窗口就投一张「请关门」的条子：

9.1 剪贴板：公共传菜口

剪贴板（Clipboard）是 Windows 划出的一块公共区域：任何程序都能往里放东西、取东西——这就是 Ctrl+C / Ctrl+V 的全部原理。操作它有固定四步：开门 → 清台 → 放菜 → 关门：

类比剪贴板 = 写字楼一层大堂的公共传菜口：全楼共用一个，所以用前要占住台子（OpenClipboard），用完必须立刻让位（CloseClipboard）——你要是占着不走，全楼的 Ctrl+C/V 都得排队报错。
文件：clipboard_write.py
import win32clipboard          # 模块 win32clipboard：剪贴板专用柜台（clipboard = 剪贴板）

只读： False

11.1 程序与进程：菜谱和正在炒的菜

类比程序 = 菜谱（躺在硬盘里的 exe 文件，不动如山）；进程 = 正在灶台上炒的菜（占内存、占 CPU，热气腾腾）；PID（Process ID，进程编号）= 灶台号。同一个菜谱可以同时在好几个灶台开炒——所以「记事本」可以开好几个窗口，各自是独立进程。

本章用到三个模块的分工：win32process（进程科，专职）、win32event（等待科，守进程退场）、win32api（凭条管理，OpenProcess / CloseHandle）。

11.3 进程点名册：谁在场？

文件：ps_list.py
import win32process             # 模块 win32process：进程科
import win32api                 # 模块 win32api：OpenProcess / CloseHandle
import win32con                 # 模块 win32con：权限常量
import pywintypes               # 模块 pywintypes：error 异常（系统进程不让查身份时会抛）

pids = win32process.EnumProcesses()   # 函数 EnumProcesses（枚举进程）：返回在场所有进程的编号（PID）清单

for pid in pids:                      # 循环：逐个编号查身份
    try:                              # try：系统核心进程不让查，会翻车——先圈起来
        hProcess = win32api.OpenProcess(             # 函数 OpenProcess（打开进程）：拿 PID 换进程凭条
            win32con.PROCESS_QUERY_INFORMATION | win32con.PROCESS_VM_READ,   # 参数 1（权限）：查信息 + 读内存（读程序名必须带读内存）
            False,                                   # 参数 2（继承）：False = 不给子进程
            pid                                      # 参数 3（进程编号）：目标灶台号

    except pywintypes.error:                       # 系统进程（权限不够）：跳过
        continue                                   # 下一个

注册表 winreg 档案室

Windows 把全部设置存在一个巨型档案室里——学会查档案、放档案，你的脚本就有了「记性」

为什么有的软件装完能「开机自启」？为什么双击 .txt 总是用记事本打开？答案都在注册表（Registry）——Windows 的总档案室。

12.1 注册表长什么样：大区、柜门、档案

类比注册表 = 大厦的总档案室，三层结构：根键是五个大区（HKEY_ 开头）；每个大区里一层层子键是一排排柜门（用反斜杠串成路径）；柜门里放着一份份值——每份档案有「值名 + 数据 + 类型」三要素。

五大根键

根键拆解管什么
HKEY_CLASSES_ROOTClasses = 种类文件类型与关联（哪个后缀用哪个程序打开）
HKEY_CURRENT_USERCurrent User = 当前用户当前用户的个人设置——桌面、自启动名单（本章主战场）
HKEY_LOCAL_MACHINELocal Machine = 本机整台机器的设置——装了什么软件、驱动（改动要管理员权限）
HKEY_USERSUsers所有用户的总档案
HKEY_CURRENT_CONFIGCurrent Config当前硬件配置（显示器等）
白捡的winreg 是 Python 标准库——不用装 pywin32 也能用！它就是「Windows 注册表接口（registry API）」的官方翻译层，风格和 pywin32 一脉相承，所以放进本教程一起学。

12.2 查档案：开柜 → 逐份报 → 还柜

先看看「开机自启动名单」里都有谁——它就存在 当前用户大区 的 ...\Run 柜子里：

文件：reg_read.py
import winreg                   # 模块 winreg：注册表档案室的管理员（标准库自带）

    r"Software\Microsoft\Windows\CurrentVersion\Run",   # 参数 2（子键路径）：一层层柜门名（r 前缀防反斜杠转义）
    0,                          # 参数 3（保留位）：协议要求必须给 0
    winreg.KEY_READ             # 参数 4（权限）：只读——看，不动手
)

        i += 1                   # 看下一份

        break                    # 跳出循环

12.3 放档案与抽档案：SetValueEx / DeleteValue

文件：reg_delete.py
import winreg                   # 模块 winreg：注册表管理员

key = winreg.OpenKey(                                  # 以写权限开柜（路径同上）
    winreg.HKEY_CURRENT_USER,
    r"Software\Microsoft\Windows\CurrentVersion\Run",
    0,
    winreg.KEY_SET_VALUE
)
winreg.DeleteValue(key, "我的开机小贴士")              # 函数 DeleteValue（删除值）：按值名把这份档案抽走

文件：auto_start_setup.py

COM 自动化：遥控 Office

不隔窗喊话，而是拨打官方客服热线——让 Excel 自己建表、Word 自己写稿

前面我们用 win32gui 「隔窗喊话」：移动 Excel 的窗口、给它发消息。但想往单元格里填数？喊破喉咙也没用——那是 Excel 家的内部业务。本章换一条正路：COM（Component Object Model，组件对象模型）。

13.1 COM：软件圈的官方客服热线

类比Office 这类大牌软件都在大厦前台留了官方客服热线（COM 接口），并且公开了服务菜单：能干什么、每个功能叫什么名字、要什么参数。你的 Python 通过「拨号器」接通热线，之后念菜单点菜即可——属性像旋钮（读状态、调设置），方法像按钮（按下去就干活）。
和 win32gui 分工win32gui 管「外貌与动作」：移窗、最小化、发消息；COM 管「业务功能」：改单元格、跑宏、发邮件。gui 能把 Excel 窗口拖来拖去，COM 能让它算账——层次不同，各司其职，还能组合使用。

13.2 拨号器与常用总机号码

拨号器是 win32com.client 模块的 Dispatch 函数，参数是各软件公布的「总机号码」（专业名叫 ProgID，程序标识符）：

ProgID拨通谁能干什么（举一反三）
"Excel.Application"Excel建表、填数、公式、图表、批量报表
"Word.Application"Word生成文档、套格式、写周报
"PowerPoint.Application"PowerPoint自动做幻灯片
"Outlook.Application"Outlook写信、发邮件、管日程
"WScript.Shell"Windows 脚本外壳SendKeys 敲键、创建快捷方式
装了才有总机号码能不能拨通，取决于这台电脑装没装对应软件：没装 Office 就拨不通 Excel.Application（会抛 pywintypes.com_error，第 27 章急救站见）。

GDI 绘图与截图

Windows 的公共画室——借块画布、拿支画笔，在屏幕上作画；顺便学会「复印整块屏幕」

GDI（Graphics Device Interface，图形设备接口）是 Windows 的公共画室：屏幕上你看到的每个字、每条线、每个按钮，都是某段程序用 GDI 画出来的。本章做两件事：亲手画，以及把屏幕拍下来（截图）。

14.1 画室的规矩：画布凭条 HDC

类比每扇窗口（包括桌面这扇最大的窗）都有一块画布，画布的内容就是它的「脸面」。HDC（Handle to Device Context，设备上下文句柄）= 画布凭条——第 4 章句柄家族表的成员终于登场。画笔（Pen）、刷子（Brush）、位图（Bitmap）是画具；BitBlt（Bit block transfer，位块搬运）是复印机。

本章新登场的模块是 win32ui（画具间）：win32gui 发画布凭条，win32ui 提供好用的画具和 DC 对象。铁律只有一条：画布凭条「取」了必须「还」——GetWindowDC / ReleaseDC 成对出现。

14.2 在屏幕上作画：画一条红线

文件：draw_on_screen.py
import win32gui               # 模块 win32gui：窗口管理科——借桌面画布
import win32ui                # 模块 win32ui：画具间——画笔、DC 对象住这里
import win32con               # 模块 win32con：常量字典（PS_ 家族住这里）

hwnd_desktop = win32gui.GetDesktopWindow()    # 函数 GetDesktopWindow：桌面也是一扇窗！拿它的句柄
hdc = win32gui.GetWindowDC(hwnd_desktop)      # 函数 GetWindowDC：凭窗口句柄「借」画布凭条，存入变量 hdc
dc = win32ui.CreateDCFromHandle(hdc)          # 函数 CreateDCFromHandle：把裸凭条包装成好用的 DC 对象存入变量 dc

pen = win32ui.CreatePen(                      # 函数 CreatePen（造画笔）：
    win32con.PS_SOLID,                        # 参数 1（笔型）：PS_SOLID = 实线（PS = Pen Style；另有 PS_DASH 虚线、PS_DOT 点线）
    5,                                        # 参数 2（粗细）：5 像素
    255                                       # 参数 3（颜色）：255 = 纯红——Windows 颜色按 BGR 排布（见下方提示框）
)
old_pen = dc.SelectObject(pen)                # 方法 SelectObject：换上新笔（旧笔存进变量 old_pen，收工时换回去）

全局热键与按键监听

让脚本长出「反射神经」——你一按键它就行动，不用先切换窗口

第 7 章是「脚本替你按键」；这一章反过来——脚本盯着你的键盘。全局热键是效率工具的灵魂：截图工具按 PrintScreen 启动、录屏软件按 F9 开始，全靠这套机制。

16.1 两兄弟：GetKeyState 与 GetAsyncKeyState

函数名字拆解看的是什么适合
GetKeyStateGet + Key + State「最近一条从消息队列取出的按键状态」（依附于窗口消息）在窗口程序内部判断（第 18 章的 WndProc 里用）
GetAsyncKeyStateGet + Async（异步）+ Key + State「此刻物理键盘的真实状态」——全局的、跟消息队列无关后台脚本轮询监听（本章主角）
类比GetKeyState = 问传达室的登记簿「上次有人送来的包裹单写的是啥」——只有处理过消息的窗口问才有意义；GetAsyncKeyState = 直接冲到键盘本尊面前看哪几个键正被物理压着——谁都能问，随时能问。

16.2 最小监听器：等一个键

文件：wait_key.py
import win32api               # 模块 win32api：按键状态查询在它家
import win32con               # 模块 win32con：常量字典（VK_ 家族）

print("按下 Esc 键退出……")    # 播报
while True:                   # 死循环：监听开始
    state = win32api.GetAsyncKeyState(win32con.VK_ESCAPE)   # 函数 GetAsyncKeyState：查 Esc 键「自上次调用以来按过没」——返回值非 0（最高位/最低位为 1）就是按过，存入变量 state
    if state != 0:            # 非 0：按过！
        print("收到 Esc，再见！")   # 播报
        break                 # 跳出循环，程序结束
返回值的门道GetAsyncKeyState 的返回值是个带两个信号位的整数：最低位=「上次查询以来按过」（轮询模式下可能被清掉，不可靠）；最高位=「此刻正被按着」。轮询间隔很短（几十毫秒）时用 != 0 判断整体即可——教学与实践都够用；要求严格「正按着」就判断 state & 0x8000（位运算：只看最高位，手法同第 10 章拆属性开关）。

16.3 实战：全局热键动作器

监听 + 行动合体：按 F8 执行动作（这里做「报时」），按 Esc 退出——骨架拿来接任何函数就是你的效率工具：

文件：hotkey_f8.py
import win32api               # 模块 win32api：按键监听 + 动作（Beep 报音）
import win32con               # 模块 win32con：常量字典
import time                   # 标准库 time：轮询节奏 + 当前时间

def action_report():          # 函数 action_report：按 F8 后要执行的动作——这里是「报时」
    now = time.strftime("%H:%M:%S")   # 函数 time.strftime：把当前时间按 "%时:%分:%秒" 格式化成字符串，存入变量 now
    print(f"[F8] 现在时刻：{now}")     # 播报
    win32api.Beep(1000, 120)  # 函数 Beep：嘀一声确认收到

print("热键已上岗：F8 = 报时，Esc = 退出（切到别的窗口也照样监听！）")   # 播报
while True:                   # 监听主循环
    if win32api.GetAsyncKeyState(win32con.VK_F8):       # 函数 GetAsyncKeyState：F8 按过没（非 0 = 按过）
        action_report()       # 调用动作函数
        time.sleep(0.3)       # 函数 time.sleep：停 0.3 秒「消抖」——按住不放别连发
    if win32api.GetAsyncKeyState(win32con.VK_ESCAPE):   # Esc 按过没
        print("退出，再见！")   # 播报
        break                 # 结束
    time.sleep(0.05)          # 轮询节奏：50 毫秒一查——够灵敏又几乎不占 CPU
消抖人手按一次键大约持续 80~150 毫秒，而轮询 50 毫秒就查一次——同一次按压会被查到 2~3 次，动作就会连放。解法就是动作后 sleep(0.3) 盖过手速；更精细的做法是「检测从按着到松开的边沿」，留给你的进阶作业。

16.4 进阶：组合键与「按住不放」

文件：combo_listen.py
import win32api               # 模块 win32api：按键监听
import win32con               # 模块 win32con：常量字典
import time                   # 标准库 time：节奏

print("监听 Ctrl+J（同时按）……Esc 退出")   # 播报

    ctrl = win32api.GetAsyncKeyState(win32con.VK_CONTROL)   # 查 Ctrl 的状态，存入变量 ctrl
    j = win32api.GetAsyncKeyState(0x4A)                     # 查字母 J 的状态（0x4A = J 的虚拟键码），存入变量 j
    if ctrl and j:                                          # 两个都非 0：同时按着！
        print("Ctrl+J 触发！")                              # 播报
        time.sleep(0.3)                                     # 消抖
    if win32api.GetAsyncKeyState(win32con.VK_ESCAPE):       # Esc：退出
        break
    time.sleep(0.05)                                        # 轮询节奏
更专业的路线轮询监听简单可靠，但有微小延迟且占一点 CPU。追求「零延迟零占用」的正路是 键盘钩子（hook）：用 SetWindowsHookEx 把自己的函数挂进系统的按键流水线——涉及回调与消息循环，是第 18 章之后的进阶方向；日常效率工具用轮询完全够。

17.5 实战：精准填表器

控件级自动化的招牌菜：绕过键鼠模拟，直接把文字「装」进目标输入框——不抢焦点、不怕输入法、不误伤别的窗口：

import win32gui               # 模块 win32gui：窗口管理科
import win32con               # 模块 win32con：常量字典

hwnd_parent = win32gui.FindWindow(None, "无标题 - 记事本")        # 家长：记事本
if hwnd_parent == 0:                                             # 0 = 没找到
    raise RuntimeError("请先打开一个空白记事本")                    # 抛错提醒

    win32con.WM_SETTEXT,         # 参数 2（消息）：WM_SETTEXT = 把你的文字改成我带的这份

    "这段文字不经过键盘、不经过剪贴板，\n直接由 Python 装进了输入框。"   # 参数 4（lParam 附件二）：要装进去的文字（\n = 换行）

17.6 进阶：给按钮「点」一下

点按钮的本质 = 给家长发一条 WM_COMMAND 消息，报上「哪个孩子被点了」：

文件：click_button.py
import win32gui               # 模块 win32gui：窗口管理科
import win32con               # 模块 win32con：常量字典

# 场景：假设有个标题为「设置面板」的对话框，里面有个「保存」按钮（血统 Button）
hwnd_dlg = win32gui.FindWindow("#32770", "设置面板")          # #32770 = Windows 标准对话框血统（第 5 章讲过）
hwnd_btn = win32gui.FindWindowEx(hwnd_dlg, None, "Button", "保存")   # 在对话框怀里找血统 Button、文字「保存」的孩子

ctrl_id = win32gui.GetWindowLong(hwnd_btn, win32con.GWL_ID)   # 函数 GetWindowLong：读孩子的身份证号（GWL_ID），存入变量 ctrl_id——WM_COMMAND 要报它

win32gui.SendMessage(            # 函数 SendMessage：给家长递话
    hwnd_dlg,                    # 收件人：对话框（家长）——按钮被点的通知由家长处理
    win32con.WM_COMMAND,         # 消息：WM_COMMAND = 「有个菜单项/按钮被点了」
    win32con.BN_CLICKED << 16 | (ctrl_id & 0xFFFF),   # 附件一（wParam）：高 16 位 = 通知码（BN_CLICKED = 被单击，注意 << 要转义写成左右移）；低 16 位 = 控件编号——两段打包
    hwnd_btn                     # 附件二（lParam）：按钮自己的句柄
)
打包公式wParam 的打包公式（高 16 位通知码 | 低 16 位控件号）是 Win32 的经典老配方。实际写时用位移：(win32con.BN_CLICKED << 16) | (ctrl_id & 0xFFFF)。有了 17.4 的位运算底子，这行不再神秘——不过是「两个 16 位小包拼一个 32 位大包」。

18.1 开店的四样手续

类比开一家自己的窗口店要办四件事：① 设计图纸（窗口类 WNDCLASS）：定好店名、风格、接到订单找谁处理；② 工商注册（RegisterClass）：把图纸在系统备案；③ 开门营业（CreateWindow）：按图纸盖出一家真店；④ 雇佣店员跑腿（消息循环 GetMessage → DispatchMessage）：站在门口收订单，分给「窗口过程」处理。

18.2 完整可跑：你的第一个原生窗口

文件：my_window.py
import win32gui               # 模块 win32gui：窗口管理科——建店的全部柜台
import win32con               # 模块 win32con：常量字典（CS_/WS_/WM_ 家族住这里）
import win32api               # 模块 win32api：GetModuleHandle 取「本程序实例」要用

def WndProc(hwnd, msg, wParam, lParam):   # 函数 WndProc（窗口过程）：你店里的「秘书」——系统每投来一条消息就调它一次（hwnd = 收件窗口句柄；msg = 消息编号；wParam / lParam = 两个附件）
    if msg == win32con.WM_PAINT:          # 消息 WM_PAINT（重绘）：系统要求「把你的店堂重新画一遍」
        dc, ps = win32gui.BeginPaint(hwnd)   # 函数 BeginPaint（开始绘制）：领画布——返回 (DC 对象, 绘图结构) 两个值，分别存入变量 dc 和 ps
        win32gui.SetTextColor(dc, 0x00EB5625)   # 函数 SetTextColor：设文字颜色——参数是 BGR 打包的整数（第 14 章讲过排布顺序与网页 RGB 相反）：0xEB5625 = 蓝 EB、绿 56、红 25，正是本教程主题色 #2563EB 蓝
        win32gui.SetBkMode(dc, win32con.TRANSPARENT)   # 函数 SetBkMode：文字背景模式改为「透明」，不然字后面拖着一块色块
        win32gui.TextOut(dc, 40, 50, "你好，这是我自己的第一家店！")   # 函数 TextOut：在客户区 (40, 50) 处写一行字
        win32gui.TextOut(dc, 40, 90, "点击窗口任意处试试；右上角 × 关店")   # 再写一行操作提示
        win32gui.EndPaint(hwnd, ps)       # 函数 EndPaint：还画布——Begin/End 必须成对（第 14 章 DC 铁律同款）
        return 0                          # 返回 0：这条消息我处理完了
    elif msg == win32con.WM_LBUTTONDOWN:  # 消息 WM_LBUTTONDOWN（左键按下）：用户点了我一下
        win32gui.MessageBox(hwnd, "收到一次点击！\n这就是消息驱动的滋味。", "我的窗口", win32con.MB_OK | win32con.MB_ICONINFORMATION)   # 弹窗回应（hwnd 作父窗口）
        return 0                          # 处理完毕
    elif msg == win32con.WM_DESTROY:      # 消息 WM_DESTROY（店要拆了）：用户点了 ×，关店流程启动
        win32gui.PostQuitMessage(0)       # 函数 PostQuitMessage：向自己的消息队列投一条 WM_QUIT（参数 0 = 退出码）——消息循环看到它才会收摊
        return 0                          # 处理完毕
    return win32gui.DefWindowProc(hwnd, msg, wParam, lParam)   # 函数 DefWindowProc（默认窗口过程）：其余消息（移动、最大化、非客户区点击……）交给系统的「默认秘书」——这行绝不能忘，不然窗口连边框都拖不动

hinstance = win32api.GetModuleHandle(None)   # 函数 GetModuleHandle：取「本程序实例」的凭条（None = 当前程序自己），存入变量 hinstance——CreateWindow 要登记在它名下

wc = win32gui.WNDCLASS()              # 类 wc：WNDCLASS 结构（窗口类）——「图纸」对象；win32gui.WNDCLASS() 造一张空白图纸
wc.style = win32con.CS_HREDRAW | win32con.CS_VREDRAW   # 图纸属性 style：横向/纵向尺寸变化时整窗重绘（CS = Class Style 类样式；HREDRAW = Horizontal REDRAW；两开关用 | 同开——第 10 章的位打包）
wc.lpfnWndProc = WndProc              # 图纸属性 lpfnWndProc：订单来了找谁——填我们刚写的秘书函数（lpfn = Long Pointer to FuNction，C 语言时代的命名遗产）
wc.hInstance = hinstance              # 图纸属性 hInstance：图纸属于哪个程序实例
wc.hIcon = win32gui.LoadIcon(0, win32con.IDI_APPLICATION)   # 图纸属性 hIcon：店招牌图标——LoadIcon 从系统预置里取（0 = 系统资源；IDI_APPLICATION = 通用应用图标）
wc.hCursor = win32gui.LoadCursor(0, win32con.IDC_ARROW)     # 图纸属性 hCursor：鼠标移进店里显示什么光标（IDC_ARROW = 普通箭头）
wc.hbrBackground = win32gui.GetStockObject(win32con.WHITE_BRUSH)   # 图纸属性 hbrBackground：店堂背景刷（hbr = Handle to BRush 刷子句柄；GetStockObject 取系统现货，WHITE_BRUSH = 白刷子）
wc.lpszClassName = "MyFirstShop"      # 图纸属性 lpszClassName：图纸编号/店类名（lpsz = Long Pointer to String, Zero-terminated——又一个 C 时代遗产命名）

atom = win32gui.RegisterClass(wc)     # 函数 RegisterClass（注册窗口类）：图纸送系统备案，返回原子编号存入变量 atom（非 0 = 备案成功）

hwnd = win32gui.CreateWindow(         # 函数 CreateWindow（开店）：按备案图纸盖真店，自家句柄存入变量 hwnd
    "MyFirstShop",                    # 参数 1（类名）：用哪张图纸
    "我的第一家店",                    # 参数 2（标题）：招牌文字
    win32con.WS_OVERLAPPEDWINDOW,     # 参数 3（样式）：WS_OVERLAPPEDWINDOW = 「有边框+标题栏+最小化/最大化/关闭按钮」的标准店面打包样式
    100, 60, 640, 400,                # 参数 4~7：位置 (x=100, y=60) 与大小 (宽 640, 高 400)
    0,                                # 参数 8（家长）：0 = 顶层窗口，没有爹
    0,                                # 参数 9（菜单）：0 = 不要菜单
    hinstance,                        # 参数 10（实例）：登记在哪个程序名下
    None                              # 参数 11（附加参数）：None = 没有
)

win32gui.ShowWindow(hwnd, win32con.SW_SHOWNORMAL)   # 函数 ShowWindow：开门营业（SW_SHOWNORMAL = 正常显示，见第 6 章遥控器家族）
win32gui.UpdateWindow(hwnd)           # 函数 UpdateWindow：立刻刷一遍脸（不等消息排队，主动触发一次 WM_PAINT）

while True:                           # ——消息循环（店员跑腿）——
    rc, msg = win32gui.GetMessage(None, 0, 0)   # 函数 GetMessage（取消息）：从队列里取下一条订单（参数 None = 本程序任意窗口的都收）；返回 (取到与否, 消息对象)，拆包给变量 rc 和 msg
    if rc == 0:                       # 返回 0 = 取到了 WM_QUIT（PostQuitMessage 投的那条）——收摊信号
        break                         # 跳出循环，程序结束
    win32gui.TranslateMessage(msg)    # 函数 TranslateMessage：把「按键扫描码」顺手翻译成「字符消息」（不翻译，键盘输入就是乱码——先翻译后分发的固定搭档）
    win32gui.DispatchMessage(msg)     # 函数 DispatchMessage（分发消息）：按订单上的门牌号，投递给对应窗口的 WndProc 秘书——你的代码在这里被「反过来调用」
先跑再说这 50 行是本教程含金量最高的一段：跑起来后你会看到一个真窗口——点它弹窗、拖它移动、点 × 关闭。每一个交互都在走第 8 章讲过的消息流水线，只不过这次收信人是你自己写的 WndProc。跑通之后，回头再读一遍注释，消息机制就彻底通了。

18.3 逐窗口看这段程序的「宿命循环」

  1. 出生：CreateWindow 返回句柄，系统顺手往队列投一条 WM_CREATE（我们没处理，走了 DefWindowProc）；
  2. 亮脸：ShowWindow/UpdateWindow 触发 WM_PAINT → WndProc 里 BeginPaint → TextOut → EndPaint，字上墙；
  3. 营业：你点窗口 → WM_LBUTTONDOWN → 弹窗；你拖动/缩放 → 一串 WM_SIZE/WM_MOVE → DefWindowProc 默认处理（因为我们开了 CS_HREDRAW|CS_VREDRAW，尺寸变了还会再触发 WM_PAINT 重画）；
  4. 打烊：点 × → WM_CLOSE（没处理，默认走「销毁」）→ WM_DESTROY → 我们 PostQuitMessage 投 WM_QUIT → GetMessage 返回 0 → 循环退出 → 进程结束。
WM_CLOSE 和 WM_DESTROY 的分工WM_CLOSE = 「有人请求关店」（还来得及挽留——处理它并直接 return，店就不关了，做「关闭前确认保存」就挂在这）；WM_DESTROY = 「店已在拆」（挽留晚了，只能善后——PostQuitMessage 是标准善后）。想在点 × 时弹「确定退出吗？」？在 WndProc 里加一个 WM_CLOSE 分支，用 MessageBox(..., MB_YESNO) 问一句，答「否」就直接 return 0 吞掉这条消息——试试！

线程与同步：多店员协作不打架

给程序多请几位店员——再配上「单人洗手间」「停车场」「叫号屏」三件防打架神器

第 18 章你开起了自己的店，但店里只有一位店员（主线程）：他去仓库搬货，柜台就没人了。这一章学会请多位店员（多线程）同时营业——下载时不卡界面、监控时不停播报。但店员一多，共用一本账就会打架：两位同时改账本，钱会凭空消失！所以本章后半请出 Windows 的同步三兄弟：Mutex（互斥锁）、Semaphore（信号量）、Event（事件）。

19.1 为什么要多线程：一个店员忙不过来

先看病症。下面的「下载器」用 time.sleep(3) 模拟一次耗时 3 秒的下载：

单线程的世界里，等 IO（网络、磁盘、用户操作）= 全店停摆。多线程就是多请几位店员：一位去搬货，一位守柜台，互不耽误。

19.2 请店员：threading.Thread

类比线程（thread）= 店里的一位店员。造店员（threading.Thread）、安排活（target）、上岗（.start()）、打烊点名（.join()）——四个动作一次学会。
文件：hire_clerk.py
import threading                     # 标准库 threading：线程管理科（Python 自带，开线程不必用 pywin32）
import time                          # 标准库 time：干等计时

def download_task(name, seconds):    # 函数 download_task：店员的活——假装下载，实际干等
    print(f"[{name}] 开始下载……")     # 播报开始
    time.sleep(seconds)              # 干等 N 秒（模拟网络 IO：此时这位店员在「等货」，不占柜台）
    print(f"[{name}] 下载完成！")      # 播报完成

worker = threading.Thread(           # 类 threading.Thread（造一位店员）：对象存入变量 worker
    target=download_task,            # 参数 target：上岗后干什么活——传【函数名本身】，不带括号！带括号就变成「立刻执行」了
    args=("补丁包", 3)                # 参数 args：干活的原料（元组，原样传给函数的两个参数）
)

worker.start()                       # 实例方法 .start()：店员上岗！主线程立刻继续往下跑，不等他
print("主线程没被卡住，柜台照常营业～")  # 这行【立刻】打印——两位店员已在并行干活
worker.join()                        # 实例方法 .join()：打烊点名——等这位店员干完活再往下走
print("全员收工，关店。")               # 最后播报
[补丁包] 开始下载……
主线程没被卡住，柜台照常营业～
（3 秒后）
[补丁包] 下载完成！
全员收工，关店。
诚实的一课：GILPython 有个著名设计叫 GIL（全局解释器锁）：同一时刻只允许一位店员执行 Python 代码。所以多线程在「算数」这类 CPU 密集任务上不会更快；但「等下载、等读盘、等用户」这类 IO 等待时，等的店员会自动让出执行权给别的店员——多线程的主场就是 IO 并发（本章场景全部如此）。真要 CPU 并行，用 multiprocessing（多位店员分身到多栋楼）。

19.3 不加锁的灾难：两位店员共用一本账

店员一多，共享数据就是雷区。两位店员同时往账本存钱，各存 10 万次 1 元——按理余额该是 20 万：

文件：race_demo.py
import threading                     # 标准库 threading：开线程

money = 0                            # 变量 money：共享账本——初始 0 元

def earn(times):                     # 函数 earn：店员的活——往账本存钱，每次 1 元共存 times 次
    global money                     # 声明 global：声明「我要改的是函数外那个全局的 money」
    for _ in range(times):           # 循环 times 次（_ 是惯例：这个计数值用不上，懒得起名）
        money = money + 1            # 「读账 → 加 1 → 写回」三步——【不是】一步到位的原子操作！

a = threading.Thread(target=earn, args=(100000,))   # 店员 A：存 10 万次（单元素元组末尾的逗号别丢！）
b = threading.Thread(target=earn, args=(100000,))   # 店员 B：也存 10 万次
a.start()                            # A 上岗
b.start()                            # B 上岗
a.join()                             # 等 A 干完
b.join()                             # 等 B 干完
print("账本余额：", money)             # 理论上该是 200000——实际呢？
账本余额： 131425        ← 每次跑结果都不同，但几乎不可能正好 200000

钱去哪了？看这个瞬间：账本写着 100 元——A 读到 100，还没来得及写回，B 也读到 100；随后 A 写回 101，B 也写回 101。两次存钱，账上只多了 1 元。「读-改-写」三步之间被人插了队——这就是竞态条件（race condition），多线程世界的头号杀手。解药只有一个：把「读-改-写」圈进一次只能进一个人的围栏——同步三兄弟登场。

19.4 同步三兄弟总览

类比三兄弟都在 win32event 模块里上班，共同点是「一次只放行合适的人数」：
兄弟一次放几人典型用途造出来
Mutex（互斥锁）1 人保护共享账本；跨进程单实例检测win32event.CreateMutex
Semaphore（信号量）N 人（可配）限制并发数：最多 3 路同时下载win32event.CreateSemaphore
Event（事件）0 或所有人广播信号：活干完了、该收摊了win32event.CreateEvent（第 25 章）
什么时候用 Python 自带的锁如果你的多位店员都在同一个 Python 进程里，threading.Lock() 更轻便（纯 Python，一行搞定）。win32event 三兄弟的不可替代之处：① 起名字后跨进程共享（两栋楼用同一间洗手间）；② 能与 Windows 原生事件（第 10 章目录门铃、第 11 章进程退场）混在同一套等待机制里统一调度。本教程两条路都给你看。

19.5 Mutex：单人洗手间，治好丢钱病

给 19.3 的账本装上互斥锁——「读-改-写」圈进洗手间，一次只进一位店员：

文件：safe_account.py
import threading                     # 标准库 threading：开线程
import win32event                    # 模块 win32event：同步三兄弟的宿舍
import win32con                      # 模块 win32con：常量字典（WAIT_ 家族住这里）

money = 0                            # 共享账本，还是初始 0 元

mutex = win32event.CreateMutex(      # 函数 CreateMutex（造一间单人洗手间）：凭条存入变量 mutex
    None,                            # 参数 1（安全属性）：None = 默认
    False,                           # 参数 2（造出来就占着吗）：False = 只造门不进门
    "我的账本锁"                      # 参数 3（名字）：起了名——其他进程也能按名找到【同一间】洗手间！
)

def earn(times):                     # 函数 earn：店员的活——存钱 times 次，每次都「锁门再动账」
    global money                     # 声明改全局账本
    for _ in range(times):
        result = win32event.WaitForSingleObject(mutex, 5000)   # 函数 WaitForSingleObject：进洗手间（最多等 5 秒 = 5000 毫秒）
        if result == win32con.WAIT_OBJECT_0:   # 常量 WAIT_OBJECT_0：门开了，进去了
            try:                     # try：不管里面出不出事……
                money = money + 1    # ……「读-改-写」圈在门里，别人进不来插不了队
            finally:                 # finally：无论如何……
                win32event.ReleaseMutex(mutex)   # 函数 ReleaseMutex：开门出来——忘开门，全店堵死！
        else:                        # 等了 5 秒门还没开（超时 WAIT_TIMEOUT）
            print("锁被占太久，这笔不存了")   # 播报放弃（真实项目里可改成重试）

a = threading.Thread(target=earn, args=(100000,))   # 店员 A
b = threading.Thread(target=earn, args=(100000,))   # 店员 B
a.start()                            # A 上岗
b.start()                            # B 上岗
a.join()                             # 等 A 收工
b.join()                             # 等 B 收工
print("账本余额：", money)             # 这次：一分不少
账本余额： 200000        ← 一分不少（慢了一点点——锁门开门也有成本，这叫「同步开销」）
死锁警告进了洗手间又去等另一间被占的洗手间——两位店员互相等对方开门，全店永久卡死，这叫死锁（deadlock）。两条家规：① 多把锁时，全员按同一个固定顺序拿锁；② 永远给 WaitForSingleObject 配一个超时时间（别用 INFINITE），超时后干脆认输退出。

Mutex 还有一个名气更大的独门用法——程序单实例检测：「同一个程序只许开一个窗口」：

19.6 Semaphore：停车场，限流神器

Mutex 是「1 个车位」的停车场；Semaphore 直接把车位推广到 N 个。9 个任务要下载，但网络只够 3 路同时跑——造个 3 车位的停车场，任务当车：

文件：parking_lot.py
import threading                     # 标准库 threading：开线程
import win32event                    # 模块 win32event：Semaphore 在这里
import time                          # 标准库 time：干等

MAX_PARALLEL = 3                     # 常量 MAX_PARALLEL：车位数——最多 3 路并发
TASKS = 9                            # 常量 TASKS：任务总数

parking = win32event.CreateSemaphore(   # 函数 CreateSemaphore（造停车场）：
    None,                            # 参数 1（安全属性）：None = 默认
    MAX_PARALLEL,                    # 参数 2（当前空位）：初始 3 个空位
    MAX_PARALLEL,                    # 参数 3（总车位数）：最大也是 3（空位只增到此数）
    None                             # 参数 4（名字）：None = 不起名，只有本进程能看见
)

def task(n):                         # 函数 task：第 n 号任务（车）的行程
    win32event.WaitForSingleObject(parking, win32event.INFINITE)   # 常量 INFINITE：无限等——有空位就进，满了死等
    print(f"任务 {n} 进场，开始下载……")  # 播报（同一时刻最多 3 条「进场」）
    time.sleep(1)                    # 假装下载 1 秒
    print(f"任务 {n} 完成，出场～")      # 播报
    win32event.ReleaseSemaphore(     # 函数 ReleaseSemaphore（出场腾车位）：
        parking,                     # 参数 1：哪个停车场
        1,                           # 参数 2：腾出几个位（通常 1）
        None                         # 参数 3：想接收回「腾位前的空位数」就传个容器，None = 不关心
    )

threads = [threading.Thread(target=task, args=(i,)) for i in range(1, TASKS + 1)]   # 列表推导：一口气造 9 辆车（线程）
for t in threads:                    # 逐辆
    t.start()                        # 发车
for t in threads:                    # 逐辆
    t.join()                         # 等全部到站
print("9 个任务全部收工！")             # 收工播报
任务 1 进场，开始下载……
任务 2 进场，开始下载……
任务 3 进场，开始下载……
（第 4~9 号在停车场门口排队）
任务 1 完成，出场～
任务 4 进场，开始下载……
……
9 个任务全部收工！
排队顺序谁先等到车位由系统调度决定，不一定按 4、5、6 的编号顺序——排队的是「车位」，不是「号码牌」。真实下载器里，把 time.sleep(1) 换成 requests.get(url)（需另装 requests 库），就是货真价实的「3 路并发批量下载器」。

19.7 一次守多盏灯：WaitForMultipleObjects

第 10 章守目录门铃、第 11 章守进程退场、本章守锁和车位——全是 WaitForSingleObject 一次守一盏。要同时盯多盏呢？

文件：watch_many.py
import win32event                    # 模块 win32event：造灯 + 守灯
import win32con                      # 模块 win32con：WAIT_ 家族常量
import win32api                      # 模块 win32api：还凭条

lamp_a = win32event.CreateEvent(None, True, False, None)   # 灯 A：手动复位（True），初始不亮
lamp_b = win32event.CreateEvent(None, True, False, None)   # 灯 B：同上

def light_lamp_b():                  # 函数 light_lamp_b：另一个线程稍后点亮灯 B
    import time                      # 局部导入 time：干等
    time.sleep(1)                    # 1 秒后
    win32event.SetEvent(lamp_b)      # 函数 SetEvent：点亮灯 B

import threading                     # 标准库 threading：开线程点亮灯 B
threading.Thread(target=light_lamp_b).start()   # 后台线程上岗

handles = [lamp_a, lamp_b]           # 变量 handles：要同时盯的凭条清单（灯 A、灯 B）

result = win32event.WaitForMultipleObjects(   # 函数 WaitForMultipleObjects（一个人盯多盏灯）：
    handles,                         # 参数 1：凭条清单
    False,                           # 参数 2（全亮才走吗）：False = 任何一盏亮就走；True = 全亮才走
    10000                            # 参数 3：最多守 10 秒（10000 毫秒）
)

if win32con.WAIT_OBJECT_0 <= result < win32con.WAIT_OBJECT_0 + len(handles):   # 返回值落在「灯亮区间」内
    index = result - win32con.WAIT_OBJECT_0   # 变量 index：减去基准值 = 是清单里第几盏亮了（从 0 数）
    print(f"第 {index} 盏灯亮了（{'B' if index == 1 else 'A'}）")   # 播报：1 秒后点亮的是灯 B
elif result == win32con.WAIT_TIMEOUT:   # 常量 WAIT_TIMEOUT：10 秒谁也没亮
    print("等了 10 秒，一盏都没亮")

win32api.CloseHandle(lamp_a)         # 函数 CloseHandle：拆灯 A 还凭条
win32api.CloseHandle(lamp_b)         # 拆灯 B 还凭条
第 1 盏灯亮了（B）
返回值即答案WaitForMultipleObjects 的妙处：返回值直接告诉你是谁触发的——「WAIT_OBJECT_0 + 序号」对应清单里第几盏灯。第 25 章 Windows 服务骨架里「一灯多能」的等待，等你学完事件就能完全看懂。

性能监控 win32pdh：给大厦装仪表盘

任务管理器里那些 CPU、内存读数——自己动手抄，还能设卡顿报警岗

打开任务管理器，CPU 百分比、内存占用实时跳动——这些数字从哪来？来自 Windows 的性能计数器体系，而 win32pdh 就是官方抄表接口（PDH = Performance Data Helper，性能数据小助手）。这一章学会：抄 CPU 使用率、查剩余内存、盯磁盘忙碌度，最后做一个「卡顿侦探」——机器快跑不动时主动弹窗喊你。

20.1 抄表四步舞：开单 → 添项 → 抄表 → 取数

类比PDH 抄表像去医院体检：先开一张体检单（MakeQuery），再勾选检查项（AddEnglishCounter），然后分两次抽血（CollectQueryData，两次之间有时间差才算得出「变化率」），最后取报告（GetFormattedValue）。
文件：cpu_once.py
import win32pdh                      # 模块 win32pdh：性能计数器科（抄表接口全在这）

query = win32pdh.MakeQuery()         # 函数 MakeQuery（开一张体检单）：空查询对象存入变量 query

win32pdh.AddEnglishCounter(          # 函数 AddEnglishCounter（往单上添检查项）：
    query,                           # 参数 1：添到哪张单子
    "\\Processor(_Total)\\% Processor Time",   # 参数 2：计数器路径——「处理器(全部核合计)\占用率」（下面详解）
    0                                # 参数 3（语言索引）：0 = 默认
)

win32pdh.CollectQueryData(query)     # 函数 CollectQueryData（第一次抽血）：只算【基线】，此时取数无意义！
win32pdh.CollectQueryData(query)     # 第二次抽血：两针之间有了时间差，占用率才算得出来

status, value = win32pdh.GetFormattedValue(   # 函数 GetFormattedValue（取报告）：
    query,                           # 参数 1：哪张单子
    win32pdh.PDH_FMT_DOUBLE          # 参数 2：格式常量 PDH_FMT_DOUBLE = 要小数（另有 PDH_FMT_LONG 要整数）
)

print(f"CPU 使用率：{value[0]:.1f}%")  # 返回 (状态码, 数值列表)：第 0 项 = 单子上第 1 个检查项的读数
CPU 使用率：12.4%
为什么用 AddEnglishCounter 而不是 AddCounter计数器路径是英文名时必须用 AddEnglishCounter——中文 Windows 里这些名字被本地化成了中文（「\处理器(_Total)\处理器时间百分比」），写英文名用 AddCounter 会报「找不到计数器」。AddEnglishCounter 自动帮你翻译，代码在任何语言的 Windows 上都能跑——无脑选它。

20.2 计数器路径：楼层(房间)\仪表名

路径语法固定三段：\对象(实例)\计数器——类比「楼层(房间)\哪块仪表」：

计数器路径读的是什么大厦类比
\Processor(_Total)\% Processor TimeCPU 总占用率（0~100）大厦总电表
\Processor(*)\% Processor Time逐核占用率（* = 每层一块表）每层楼电表
\Memory\Available MBytes剩余可用内存（MB）仓库剩余空位
\PhysicalDisk(_Total)\% Disk Time磁盘忙碌率货梯忙碌率
\PhysicalDisk(_Total)\Avg. Disk Queue Length磁盘排队长度（>2 持续 = 硬盘瓶颈）货梯口排队人数
\Process(python)\% Processor Time单个进程的 CPU 占用某家店铺的用电量
\Process(python)\Working Set - Private单个进程的内存占用（字节）某家店铺的占地面积
找路径的官方姿势所有可用计数器在「性能监视器」（perfmon）里：Win+R 输入 perfmon → 左侧「性能监视器」→ 点绿色加号——目录树长什么样，路径就怎么写。实例列里的 _Total 表示合计、* 表示逐个；同名进程多个时系统自动加 #1#2 区分（两个 python.exe 就是 python 和 python#1）。

20.3 连续抄表：CPU 实时监控器

一次抄表没意思，套上循环才是监控。注意「率类」计数器（带 % 的）读的是两个时间点之间的变化率——循环里每轮抄一次即可，首轮那次只算基线：

文件：cpu_watch.py
import win32pdh                      # 模块 win32pdh：抄表
import win32api                      # 模块 win32api：Sleep 干等（顺便再熟悉一遍老朋友）

query = win32pdh.MakeQuery()         # 开体检单
win32pdh.AddEnglishCounter(query, "\\Processor(_Total)\\% Processor Time", 0)   # 添「CPU 占用率」项
win32pdh.CollectQueryData(query)     # 首抄基线（这一轮的数字不用）

for i in range(5):                   # 连抄 5 轮
    win32api.Sleep(1000)             # 函数 win32api.Sleep：本线程干等 1 秒（1000 毫秒）——与 time.sleep 等效
    win32pdh.CollectQueryData(query)                       # 抄表（本轮）
    status, value = win32pdh.GetFormattedValue(            # 取数
        query,                                            # 哪张单
        win32pdh.PDH_FMT_DOUBLE)                          # 要小数
    print(f"第 {i + 1} 秒：CPU {value[0]:.1f}%")            # 播报

win32pdh.CloseQuery(query)           # 函数 CloseQuery：体检单用完销毁（凭条该还就还）
第 1 秒：CPU 8.3%
第 2 秒：CPU 12.7%
第 3 秒：CPU 41.2%
第 4 秒：CPU 35.5%
第 5 秒：CPU 9.8%
一张单添多项AddEnglishCounter 可以对同一张 query 连续调用多次——比如再添一项「剩余内存」：win32pdh.AddEnglishCounter(query, "\\Memory\\Available MBytes", 0)。此后 GetFormattedValue 返回的 value 列表按添项顺序排好：value[0] 是 CPU、value[1] 是内存——一张单，多块表。

20.4 实战：卡顿侦探——CPU 超标自动报警

把监控器升级成「侦探」：CPU 连续 3 轮超过 80% 就弹窗警告。防瞬间抖动误报的诀窍是连续计数：

文件：lag_detective.py（Ctrl+C 停止值班）
import win32pdh                      # 模块 win32pdh：抄表
import win32api                      # 模块 win32api：干等 + 弹窗 + 退场
import win32con                      # 模块 win32con：弹窗样式常量

THRESHOLD = 80.0                     # 常量 THRESHOLD：报警线——CPU 超过 80% 记一次超标
ALERT_TIMES = 3                      # 常量 ALERT_TIMES：连续超标 3 次（约 6 秒）才真正报警

query = win32pdh.MakeQuery()         # 开体检单
win32pdh.AddEnglishCounter(query, "\\Processor(_Total)\\% Processor Time", 0)   # 添 CPU 项
win32pdh.CollectQueryData(query)     # 首抄基线

hot = 0                              # 变量 hot：连续超标计数器（清零用）
try:                                 # try：包裹值班循环——Ctrl+C 能优雅收摊
    while True:                      # 值班死循环
        win32api.Sleep(2000)         # 每 2 秒抄一轮表
        win32pdh.CollectQueryData(query)                    # 抄表
        status, value = win32pdh.GetFormattedValue(         # 取数
            query, win32pdh.PDH_FMT_DOUBLE)
        cpu = value[0]               # 变量 cpu：本轮 CPU 读数
        print(f"CPU：{cpu:.1f}%")     # 播报

        if cpu > THRESHOLD:          # 超过报警线
            hot = hot + 1            # 连续超标 +1
        else:                        # 回落了
            hot = 0                  # 连续被打断，清零重来（防「抖一下也算」）

        if hot >= ALERT_TIMES:       # 连续超标攒够了
            win32api.MessageBox(     # 函数 MessageBox：弹窗警告（第 2 章老朋友）
                0,                   # 参数 1：父窗口句柄，0 = 无父窗口
                f"CPU 已连续 {ALERT_TIMES} 轮超过 {THRESHOLD}%——机器快跑不动了，查查是哪个程序在作妖！",   # 参数 2：正文
                "卡顿侦探",           # 参数 3：窗口标题
                win32con.MB_ICONWARNING)   # 参数 4：样式 = 警告图标（黄色三角）
            hot = 0                  # 报过警，计数清零（下一轮重新观察）
except KeyboardInterrupt:            # 捕获 Ctrl+C
    print("侦探下班。")                # 优雅收摊播报
finally:                             # finally：无论如何
    win32pdh.CloseQuery(query)       # 销毁体检单

事件日志 win32evtlog：大厦的黑匣子

Windows 从出生起就在偷偷记日记——现在把日记本借出来，看看谁在捣乱

Windows 是个尽职的物业：哪个服务没启动、哪个驱动报了错、谁登录过这台机器——统统写进事件日志。你按下 Win+R 输入 eventvwr 打开的「事件查看器」，看的就是这些本子。这一章用 win32evtlog 把本子借出来程序化阅读——最后做一个「系统报错日报」，让机器自己交代最近谁在作妖。

21.1 三本值班日记

类比事件日志 = 物业的值班记录本，主要有三本，各记各的：
本子名记什么类比
Application各软件自己写的记录（Office 报错、程序崩溃）各商户的柜台留言簿
SystemWindows 核心部件（驱动、服务、磁盘）的动静工程部值日记
Security登录、权限审计——默认没权限读（要管理员 + 开审核策略）门禁刷卡记录
还有两小本另有两个不常翻的本子：setup（系统安装记录）和 ForwardedEvents（从别的机器转发来的）。本教程演示用 System——人人可读、条目丰富。

21.2 借书三部曲：Open → Read → Close

老规矩，句柄三部曲（第 4 章的地基第四次踩实）：借本子 → 读条目 → 还本子：

文件：log_peek.py
import win32evtlog               # 模块 win32evtlog：事件日志科（借本读条还本全在这）

handle = win32evtlog.OpenEventLog(   # 函数 OpenEventLog（借出记录本）：凭条存入变量 handle
    None,                          # 参数 1（机器名）：None = 本机（填别的机器名可读局域网电脑的日记）
    "System"                       # 参数 2（本子名）："System" 系统值日本
)

flags = win32evtlog.EVENTLOG_BACKWARDS_READ | win32evtlog.EVENTLOG_SEQUENTIAL_READ   # 变量 flags：读取姿势——从新往旧读（BACKWARDS）+ 连续往下翻（SEQUENTIAL）；位打包老朋友第 5 次登场！

batch = win32evtlog.ReadEventLog(  # 函数 ReadEventLog（翻一页，读一批条目）：
    handle,                        # 参数 1：凭条
    flags,                         # 参数 2：读取姿势
    0                              # 参数 3（记录编号起点）：配合连续读时恒为 0
)

for ev in batch[:5]:               # 变量 ev：一条事件对象；切片 [:5] 只看最新 5 条
    print("时间：", ev.TimeGenerated.strftime("%Y-%m-%d %H:%M:%S"))   # 属性 TimeGenerated：事发时间（时间对象，strftime 格式化）
    print("部门：", ev.SourceName)  # 属性 SourceName：事发部门（哪个部件写的这条）
    print("编号：", ev.EventID & 0xFFFF)   # 属性 EventID：消息编号——低 16 位才是编号本体，高位打包着严重级别，用 & 0xFFFF 剥出来（位运算第 6 次登场！）
    print("---")                   # 分隔线

win32evtlog.CloseEventLog(handle)  # 函数 CloseEventLog：还本子——句柄三部曲收尾

编号： 109

21.3 条目解剖：一条事件的五脏六腑

属性是什么类比
ev.TimeGenerated事发时间（时间对象，可 strftime 格式化）留言的时间戳
ev.SourceName谁写的（部件名，如 DCOM、disk）留言人署名
ev.EventID消息编号（取低 16 位）——同部门同编号 = 同一件事留言类型代号
ev.EventType级别（见下表）红黄蓝三级便签
ev.ComputerName哪台机器哪栋楼
ev.StringInserts消息模板的填空内容（列表）留言的具体细节

级别（EventType）是筛重点的法宝——五档常量：

常量（win32evtlog 家）档位要不要理它
EVENTLOG_ERROR_TYPE错误（红）出事了——日报的主角
EVENTLOG_WARNING_TYPE警告（黄）快出事了——观察名单
EVENTLOG_INFORMATION_TYPE信息（蓝）正常流水账——扫一眼即可
EVENTLOG_AUDIT_SUCCESS审计成功Security 本专属：谁通过了门禁
EVENTLOG_AUDIT_FAILURE审计失败Security 本专属：谁刷卡被拒

21.4 实战：系统报错日报

把整本 System 日志翻完，只挑「错误」级，按事发部门统计——一图看清谁在捣乱：

文件：error_report.py
import win32evtlog               # 模块 win32evtlog：事件日志科
import collections               # 标准库 collections：计数器（自动帮咱数次数）

handle = win32evtlog.OpenEventLog(None, "System")   # 借出系统值日本（None = 本机）

flags = win32evtlog.EVENTLOG_BACKWARDS_READ | win32evtlog.EVENTLOG_SEQUENTIAL_READ   # 从新往旧 + 连续翻

counter = collections.Counter()  # 变量 counter：部门 → 犯错次数 的计数器
total = 0                        # 变量 total：错误总数

while True:                      # 一批一批读，直到读空
    batch = win32evtlog.ReadEventLog(handle, flags, 0)   # 翻一页
    if not batch:                # 空了 = 翻到本子开头
        break                    # 收工
    for ev in batch:             # 逐条检查本批
        if ev.EventType == win32evtlog.EVENTLOG_ERROR_TYPE:   # 只统计「错误」级
            total = total + 1    # 总数 +1
            counter[ev.SourceName] = counter[ev.SourceName] + 1   # 该部门计数 +1（部门名当字典键）

win32evtlog.CloseEventLog(handle)   # 还本子

print(f"【系统日志 · 报错日报】共 {total} 条错误")
print("十大捣乱部门：")
for dept, n in counter.most_common(10):   # 方法 most_common(10)：按次数从多到少取前 10
    print(f"  {dept}：{n} 次")             # 播报

23.2 WScript.Shell 六件套

拨通之后，一个对象身上挂着六套常用本事：

文件：shell_demo.py（可拆开逐段跑）
import win32com.client             # 模块 win32com.client：COM 遥控器科（第 13 章老朋友）

shell = win32com.client.Dispatch("WScript.Shell")   # 函数 Dispatch（拨通总机）："WScript.Shell" = 脚本外壳；遥控器存入变量 shell

# ① Run：跑程序，可选「等它退出」（第 11 章的三种启动方式之外的第四种）
exit_code = shell.Run("notepad.exe", 1, False)   # 方法 Run：参数 1 = 命令；参数 2 = 窗口样式（1 = 正常显示，2 = 最小化）；参数 3 = 等不等它退场（False = 不等；True = 等到底，返回值 = 退出码）

# ② Popup：带【倒计时】的弹窗——超时自动关，返回 -1（比 MessageBox 多一手）
answer = shell.Popup("5 秒后自动消失，点确定提前返回。", 5, "带倒计时的窗", 4 + 32)   # 方法 Popup：参数（正文, 倒计时秒数, 标题, 样式）；样式 4 = 是/否按钮 + 32 = 问号图标（数字加法也是位打包的雏形）

desktop = shell.SpecialFolders("Desktop")       # 属性 SpecialFolders（专属文件夹柜）：按名取「桌面」的真实路径——比手拼 C:\Users\xxx\Desktop 靠谱（用户可能改过位置！）

# ④ Environment：SYSTEM 级环境变量（第 15 章改的只是本进程的公告栏，这里动的是全机器的）
path_value = shell.Environment("SYSTEM")("PATH")   # 属性 Environment（环境变量柜）：("SYSTEM") 选系统级（另有 "USER" 用户级、"PROCESS" 进程级），再 ("PATH") 按键取值

# ⑤⑥ 注册表三连：RegRead / RegWrite / RegDelete——第 12 章 winreg 的 COM 版备胎
value = shell.RegRead(r"HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Shell Folders\Desktop")   # 方法 RegRead：读值（路径可用缩写 HKCU\，比 winreg 的五大战区缩写省事）
# shell.RegWrite(r"HKCU\Software\我的小屋\次数", 1, "REG_DWORD")   # 方法 RegWrite：写值——参数（路径, 值, 类型），类型写 "REG_SZ" 字符串 / "REG_DWORD" 整数
# shell.RegDelete(r"HKCU\Software\我的小屋")     # 方法 RegDelete：删键——只删空键，有孩子的先删孩子
多线程里用 COM：先铺地基COM 有个规矩：每个新开的线程第一次碰 COM 对象前，必须先调 pythoncom.CoInitialize()（模块 pythoncom：COM 地基科——第 13 章 Dispatch 背后的交换机室），否则抛 pywintypes.com_error。第 19 章的 threading 店员若要替主线程遥控 Excel/Outlook，上岗第一件事就是铺地基，收摊时调 pythoncom.CoUninitialize() 拆掉。主线程里 pywin32 已自动铺好——所以第 13 章从头到尾没见过这个错，坑只在新线程。

import win32com.client             # 模块 win32com.client：COM 遥控器科

fso = win32com.client.Dispatch("Scripting.FileSystemObject")   # 拨通文件管家

def folder_report(path):           # 函数 folder_report：给一个文件夹出体检报告（返回：总字节数, 总文件数）
    folder = fso.GetFolder(path)   # 方法 GetFolder：领到文件夹对象
    size = 0                       # 变量 size：本层及下层文件的总字节
    count = 0                      # 变量 count：本层及下层的文件总数
    for f in folder.Files:         # 本层的每个文件
        size = size + f.Size       # 属性 Size：这个文件多少字节——累加
        count = count + 1          # 计数
    for sub in folder.SubFolders:  # 本层的每个子夹
        sub_size, sub_count = folder_report(sub.Path)   # 递归：子夹也出一份报告（属性 Path = 子夹完整路径）
        size = size + sub_size     # 子夹的账并入本层
        count = count + sub_count  # 计数并入
    return size, count             # 返回两数

total_size, total_files = folder_report(r"C:\Users\Public\Documents")   # 跑体检
print(f"共 {total_files} 个文件，合计 {total_size / 1024 / 1024:.1f} MB")   # 换算成 MB 播报

25.1 事件：红灯停，绿灯行

类比事件（Event）= 一盏跨线程/跨进程共享的信号灯：CreateEvent 造灯，SetEvent 点亮，WaitForSingleObject 守着灯等。第 10 章守「目录门铃」、第 11 章守「进程退场」用的都是这套等待机制——现在把灯的主人换成你自己。
文件：event_demo.py
import win32event               # 模块 win32event：等待与事件科
import win32con                 # 模块 win32con：常量字典（WAIT_ 家族住这里）
import win32api                 # 模块 win32api：还凭条的柜台

handle = win32event.CreateEvent(   # 函数 CreateEvent（造一盏信号灯）：凭条存入变量 handle
    None,                          # 参数 1（安全属性）：None = 默认
    False,                         # 参数 2（手动复位吗）：False = 自动复位——被等到后灯自动熄灭，一次放行一个
    False,                         # 参数 3（初始状态）：False = 造出来先不亮（红灯）
    "我的信号灯"                   # 参数 4（名字）：起了名，别的进程也能按名找到这盏灯
)

win32event.SetEvent(handle)        # 函数 SetEvent：点亮信号灯（绿灯！）

result = win32event.WaitForSingleObject(handle, 3000)   # 函数 WaitForSingleObject：守灯等最多 3 秒（3000 毫秒）——灯亮着立即通过，没亮干等到超时
if result == win32con.WAIT_OBJECT_0:      # 常量 WAIT_OBJECT_0：等到了——灯亮（把本行和上一行一起注释，就能看到超时分支）
    print("绿灯，通过！")                  # 播报
elif result == win32con.WAIT_TIMEOUT:     # 常量 WAIT_TIMEOUT：超时——3 秒没亮
    print("红灯超时，撤！")                # 播报

win32api.CloseHandle(handle)       # 函数 CloseHandle：拆灯还凭条
绿灯，通过！
用在哪多线程协作的经典场景：主线程 WaitForSingleObject 守着一盏「活干完了」灯；工作线程干完活 SetEvent 点灯——主线程立即醒。比「每秒问一次干完没」的轮询体面得多。

25.2 Windows 服务：给脚本一间值班室

普通脚本像钟点工：你一跑它才干活，你一关机它就下班。Windows 服务是值班室：开机自动上岗、不用你登录也在后台跑、崩溃还能自动重启。pywin32 提供了把它写出来的完整骨架：

文件：my_service.py
import win32serviceutil         # 模块 win32serviceutil：服务工具箱——把 Python 类安装成 Windows 服务
import win32service              # 模块 win32service：服务的底层柜台
import win32event                # 模块 win32event：造「停机信号灯」
import win32con                 # 模块 win32con：常量字典

class MyService(win32serviceutil.ServiceFramework):   # 类 MyService：自己写的服务类；括号里的 ServiceFramework 是父类（pywin32 提供的服务框架模板）
    _svc_name_ = "MyPythonService"             # 类属性 _svc_name_：服务注册名（英文名，net start 时用它）
    _svc_display_name_ = "我的 Python 服务"     # 类属性 _svc_display_name_：服务管理器里显示的名字
    _svc_description_ = "pywin32 编写的示范服务"  # 类属性 _svc_description_：服务描述

    def __init__(self, args):                  # 方法 __init__（构造方法）：服务启动时最先执行
        win32serviceutil.ServiceFramework.__init__(self, args)   # 调父类构造：先把框架自身收拾好（args 参数原样转交）
        self.hWaitStop = win32event.CreateEvent(None, 0, 0, None)   # 实例属性 self.hWaitStop：停机信号灯——「该收摊了」时它亮
        self.running = True                    # 实例属性 self.running：自己加的运转开关

    def SvcStop(self):                         # 方法 SvcStop（服务停止）：用户点「停止服务」时系统会调它
        self.running = False                   # 拧下运转开关
        win32event.SetEvent(self.hWaitStop)    # 点亮停机灯——让 SvcDoRun 里的等待立即结束

    def SvcDoRun(self):                        # 方法 SvcDoRun（服务主活）：服务的正式工作全写在这里
        while self.running:                    # 循环值班，直到开关被拧下
            # ……每轮要做的事写在这里：巡检文件夹、抄数据、收邮件……
            result = win32event.WaitForSingleObject(self.hWaitStop, 60000)   # 守停机灯最多 60 秒——一举两得：既是轮询节奏，又是停机哨兵
            if result == win32con.WAIT_OBJECT_0:   # 灯亮了 = 有人喊停
                break                              # 跳出循环，服务收摊

if __name__ == "__main__":                     # 脚本被直接运行时（而非被导入时）才执行：
    win32serviceutil.HandleCommandLine(MyService)   # 函数 HandleCommandLine：接管命令行——安装/启动/停止服务全靠它

import win32con                 # 模块 win32con：常量字典
import win32api                 # 模块 win32api：弹窗播报
import time                     # 标准库 time：巡检节奏

def get_removables():           # 函数 get_removables：拍一张「当前 U 盘清单」快照
    snapshot = []               # 变量 snapshot：本张快照
    drives = win32file.GetLogicalDrives()        # 函数 GetLogicalDrives：盘符位图（第 10 章学过）
    for i in range(26):                          # 内置函数 range：0~25 对应 A~Z
        if drives & (1 << i):                    # 位运算：第 i 位是 1 = 这个盘在场
            letter = chr(ord("A") + i) + ":\\"    # 内置函数 chr：编号拼成 "E:\\" 样式的盘符
            if win32file.GetDriveTypeW(letter) == win32con.DRIVE_REMOVABLE:   # 函数 GetDriveTypeW：是可移动盘才收进快照
                snapshot.append(letter)           # 方法 append：入清单
    return snapshot              # 关键字 return：把快照交还调用者

print("U 盘哨兵上岗（Ctrl+C 退休）")   # 播报
before = get_removables()        # 变量 before：上岗时的旧照

    for drive in after:          # 逐个核对最新快照

    ("修复登录超时问题", 3),     # 元组：(事项, 耗时小时)
    ("新报表接口联调", 8),
    ("整理运维文档", 2),
]

excel = win32com.client.Dispatch("Excel.Application")   # 函数 Dispatch：拨通 Excel 总机
excel.Visible = False           # 属性 Visible：False = 隐身办公，后台生成不打扰

try:                            # 军规姿势：正活包 try，Quit 写 finally
    wb = excel.Workbooks.Add()              # 新建工作簿 → 变量 wb
    ws = wb.Worksheets(1)                   # 第 1 张表 → 变量 ws
    ws.Cells(1, 1).Value = f"{week_str} 工作周报"   # A1：标题
    ws.Cells(2, 1).Value = "事项"           # A2：表头
    ws.Cells(2, 2).Value = "耗时(小时)"     # B2：表头
    row = 3                                  # 变量 row：数据从第 3 行开始填
    for task, hours in TASKS:               # 循环：逐条任务填表（元组拆包）
        ws.Cells(row, 1).Value = task       # A 列：事项
        ws.Cells(row, 2).Value = hours      # B 列：耗时
        row += 1                            # 行号下移
    ws.Cells(row, 1).Value = "合计"          # 最后一行：合计
    ws.Cells(row, 2).Value = f"=SUM(B3:B{row - 1})"   # 公式区间随行数自动伸缩（row - 1 = 最后一条数据行）

    path = os.path.join(r"C:\Users\Public", f"周报_{today.strftime('%Y%m%d')}.xlsx")   # 函数 os.path.join：拼完整路径；%Y%m%d = 如 20260913
    wb.SaveAs(path)                         # 方法 SaveAs：保存
    print(f"周报已生成：{path}")             # 播报
finally:                        # 无论成败：
    excel.Quit()                # 军规：Quit 必调，不留后台僵尸

这一章是急诊科：把 pywin32 世界最高频的报错全挂在墙上，照着红字找病因、按药方抓药。建议收藏本章——你以后一定会回来看它。

27.1 破案神器：三件套

第 4 章埋的伏笔现在回收：pywin32 的异常自带病历三件套——错误编号（winerror）、官方说明（strerror）、肇事函数（funcname）。养成肌肉记忆：

文件：diagnose.py
import win32gui               # 模块 win32gui：用一个作废句柄触发真实病例
import pywintypes              # 模块 pywintypes：error 异常的家

fake_hwnd = 99999999           # 变量 fake_hwnd：瞎编的窗口凭条号
try:
    win32gui.GetWindowText(fake_hwnd)   # 函数 GetWindowText：凭条必然无效，这里必翻车
except pywintypes.error as e:   # 关键字 except ... as e：接住异常对象存入变量 e
    print("编号：", e.winerror)   # 属性 winerror：1400——拿这个数字去下表对号入座
    print("说明：", e.strerror)   # 属性 strerror：官方文字说明
    print("肇事：", e.funcname)   # 属性 funcname：哪个函数出的岔子
    if e.winerror == 1400:      # 按编号分诊——这就是「写进代码里的急救站」
        print("诊断：句柄作废（窗口关了或压根没开过）")   # 自动诊断结论
编号： 1400
说明： 无效的窗口句柄。
肇事： GetWindowText
诊断：句柄作废（窗口关了或压根没开过）

27.3 三个病例详解

病例一：装了却找不到模块

明明 pip install pywin32 跑过了，import 还是红。十有八九是装错了地方：机器上有多个 Python（系统版 + 商店版 + venv……），pip 把包装进了 A，脚本却用 B 在跑。药方是「点名安装」：

命令行（任意权限）
python -m pip install pywin32   # -m 的意思：让「即将运行脚本的那个 python」自己经手安装——包必然装到它名下
python -m pip show pywin32     # 验证：能看到 Version 和 Location 就说明装对了地方

病例二：句柄作废（1400）

句柄的寿命和窗口一样长——用户手一抖关了窗，你手里的凭条就成了废纸。重要的操作前验活：

文件：check_alive.py
import win32gui               # 模块 win32gui：窗口管理科

hwnd = win32gui.FindWindow(None, "任务管理器")   # 拿凭条

if win32gui.IsWindow(hwnd):     # 函数 IsWindow：这张凭条还有效吗 → True / False（窗口还在不在）
    print("活得好好的：", win32gui.GetWindowText(hwnd))   # 有效：放心办事
else:
    print("凭条作废——窗口已关或从未开过")   # 失效：别硬闯，重新找或放弃

病例三：com_error（COM 拨号失败）

com_error 出现的两大场景：① Dispatch 当场翻车——这台电脑没装 Excel/Word，总机号码空号；② 干着干着翻车——脚本先前调了 Quit()，之后又摸了摸工作簿对象。药方：拨号前确认软件在装机单上；Quit 之后断念。预防姿势就是第 13 章军规：正活全包 try，finally 里只有一句 excel.Quit()。另外总表新增的那条「新线程里 Dispatch 报错」也是 com_error 的马甲——药方是先 pythoncom.CoInitialize() 铺地基（第 23 章有专案）。

27.4 防御式模板：把急救站写进代码

最高明的急救是让病发不出来。两个可以无限复用的模板：

文件：safe_find.py
import win32gui               # 模块 win32gui：窗口管理科
import time                   # 标准库 time：重试间隔

def find_window(title, retries=3, wait=0.5):   # 函数 find_window：安全版找窗口——带重试与验活（retries 次数、wait 间隔，默认值写在参数里）
    for i in range(retries):                   # 内置函数 range：最多试 retries 轮
        hwnd = win32gui.FindWindow(None, title)   # 函数 FindWindow：找一轮
        if hwnd and win32gui.IsWindow(hwnd):   # 找到了（非 0）且凭条有效（IsWindow 为 True）
            return hwnd                        # 关键字 return：交付凭条，函数结束
        time.sleep(wait)                       # 函数 time.sleep：等半秒——目标程序可能正在启动中
    raise RuntimeError(f"重试 {retries} 轮仍找不到窗口：{title}")   # 实在找不到：明确抛错，而不是返回 0 留隐患

hwnd = find_window("无标题 - 记事本")   # 用法：从此告别「静默失败」
print("凭条：", hwnd)                    # 播报
资源管理总模板凡「取了要还」的资源（剪贴板、DC 画布、注册表柜门、进程凭条），一律套这个骨架：拿凭据 = 取() → try: 干正活 → finally: 还(凭据)。本章没有练习——急救站的作业在报错来的那天。

最佳实践与速查表

十条军规保平安，六张速查表管全年——从入门到熟练的最后一站

最后一章是两样东西：军规（写脚本前扫一眼，少踩九成的坑）和速查表（忘了 API 名字时直奔这里）。

28.1 十条军规

  1. 句柄速用速弃——拿到就用、用完即弃；绝不存盘、绝不过夜。隔夜句柄等于废纸（1400 警告）；
  2. 返回 0 必查——FindWindow 一切「安静却无效」的源头；用 27.4 的 find_window 模板一劳永逸；
  3. 键鼠前必前台——模拟敲键前必 SetForegroundWindow + sleep(0.3~0.5)，否则字敲进别人家；
  4. 通知用 Post，要回执用 Send——关窗、按键给 PostMessage；改标题、查状态给 SendMessage；
  5. 取还配对，铁律成对——OpenClipboard/CloseClipboard、GetWindowDC/ReleaseDC、OpenKey/CloseKey、OpenProcess/CloseHandle，取了必还，还必进 finally；
  6. Quit 军规——COM 应用对象用完必 Quit()，且放在 finally；不 Quit = 后台僵尸 Excel 越攒越多；
  7. 注册表三思后写——只动自家名下的键；动手前 regedit 导出备份；能用 HKCU 就不碰 HKLM；
  8. 用常量别猜数字——永远写 win32con.SW_RESTORE，永远不写 9；位运算（&、|、>>）探测，永远不猜；
  9. 权限最小化——能普通权限就别管理员；能用户级（HKCU）就别机器级（HKLM）；
  10. 小步快跑——每加一段就跑一次；自动化脚本的 bug 是复利的，攒到最后一起炸。
